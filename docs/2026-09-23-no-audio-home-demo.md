# 无音频兜底与官网流程演示

## 验收行为

- 资料库卡片、预览、详情及博主任务中，确认没有音轨或可识别语音的内容显示「无音频」，不展示红色异常或重试按钮。
- 无音频结果按用户和视频保存，不创建空笔记；批量任务计入跳过，进度正常结束，后续提取自动跳过。
- 混合批次保留正常文稿，可继续进入知萃 AI；全部无音频时说明没有可提问的文案，不创建空会话。
- 404 不是无音频证据。生产日志中的媒体 404 来自作品详情读取失败；此类错误显示「资源暂不可用，请稍后重试」，不暴露底层地址。
- 官网四项流程默认自动循环：批量同步、今日/昨日回顾、视频生成计划、博主批量问答。点击标签重播当前流程；人类提问和 AI 回答逐字播放，完整回答后停留再切换。
- 使用现有抖音/B站品牌图标；示例数据与回答有明确标识。网页保留更新检测和资源预加载，移除右下角更新提示，空闲时自动更新。

## 已验证

- 前端类型检查、正式构建、导航/更新/提取队列/无音频卡片渲染/每日回顾测试通过。
- 后端无音频识别、ASR 重试、提取持久化、并发、用户隔离、每日回顾相关测试通过。
- 真实 FFmpeg 生成无声 MP4，经本机 HTTP 流输入提取：返回 `no_audio_stream`，ASR 调用次数为 0。覆盖不同 FFmpeg 版本的无流错误格式。

## 发布与兼容

- 新增 `media_extraction_outcomes` 表，由既有启动 `create_all` 创建；不重建现有表或状态约束。
- 博主任务内部使用既有跳过状态加 `error_code=no_audio`，对外呈现无音频，兼容生产 PostgreSQL CHECK 约束。
- 正式发布由 Gitee/Jenkins 既有流程执行；发布结果、版本与回滚证据写入服务器 `/var/lib/zhicui-deployments`，外部用 `/build-version.json` 和 `/api/health` 核验。
