# 昨日回顾一键进入 AI

## 行为

- 首页「看看昨天干了什么」直接启动昨日回顾，与下方卡片共用同一准备流程，不再使用页内锚点，也无需第二次点击。
- 自动提取缺失文稿、复用已有文稿，生成总结后进入 `/harness?thread=...` 对应的知萃 AI 会话继续追问。
- 顶部入口展示进度，处理中禁用；加载和资料显示偏好就绪后接续点击，重复点击不排队，也不重复发送 AI 请求。
- 初次读取失败时，用户仍可从顶部入口重新读取并启动；账号切换或离开页面时取消本页等待，不把旧结果带给新账号。
- 昨日没有可见资料时明确说明原因，不创建空会话；无音频维持原有跳过规则。
- 之前只完成部分摘要的昨日回顾再次启动时，补提取仍缺失的文稿；来源补齐后生成新回顾，仍未补齐且来源相同则打开原回顾，避免重复 AI 生成。

## 验证与发布

首页同步及回顾相关 108 项检查通过（99 项集成检查及 9 项原有卡片检查，均已纳入 `npm run test:home-sync`），`npm run build`（含 TypeScript 检查）通过。

通过既有 Node 测试执行真实首页与回顾组件，检查入口点击、准备调用、进度和路由跳转；准备流程测试覆盖提取、会话复用与失败恢复。发布沿用 Gitee/Jenkins 的备份、构建、readiness 和生产用户旅程检查，结果记录于 Jenkins 日志和 `/var/lib/zhicui-deployments`；线上版本由 `/build-version.json` 核验。
