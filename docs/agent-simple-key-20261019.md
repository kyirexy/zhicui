# Agent 密钥接入简化验收

## 目标与状态

将常用连接流程收敛为「生成 Agent 密钥 → 复制给 Agent → 后续直接复用」。安装向导、权限选择、固定期限 PAT、设备授权码、MCP 命令和诊断保留在高级设置中。

本次为代码改造与本地验收，尚未发布到生产或替换已安装客户端。基线为已发布的 `1dc8b0fb54b13919b48e1f29aae0fb7dccc6757f`；分支 `codex/agent-simple-key-20261019`；工作目录 `D:/6month-worktrees/agent-simple-key-20261019`。主工作区已有未完成改动保持原样。

## 用户流程

1. 在知萃已登录账号的「Agent 接入」页点击「生成 Agent 密钥」。不再要求先填名称、有效期、权限或设备码。
2. 点击「复制给 Agent」，粘贴到正在使用的 Agent。复制内容包含一次性密钥和官方 CLI 的接入说明；也保留仅复制密钥。
3. Agent 通过 `zhicui connect --pat-stdin --client codex --non-interactive --json` 的标准输入接收密钥（Claude 对应 `--client claude`），验证后保存到系统安全存储，并配置 MCP/Skill。
4. 后续命令、新 CLI 进程和桌面重启继续复用保存的密钥；本机操作仍要求知萃登录同一账号。已有只读 PAT 不会被悄悄提权，也不会因为权限不足自动另开设备授权。

日常密钥使用时自动续期，连续 365 天没有有效使用后失效。可随时停用；账号禁用、密码重置和密钥撤销继续生效。旧 PAT 的权限和最长 90 天有效期保持兼容。

## 实现

- `POST /api/agent-interface/v1/credentials/agent-key`：仅登录会话可创建，输入仅可选 `name`。沿用 `zhc_pat_` 格式，`client_type=agent_key`，无需数据库迁移。
- 服务器为新密钥选择已发布日常权限；暂时没有连接桌面不影响已发布本机能力的授权。签发后不会因未来新增功能而自动扩权。
- `capabilities.daily_agent_scopes` 与签发共用同一权限计算；CLI 优先使用这个精确范围，和 `granted_scopes`（实际已授权）分开。旧服务缺少字段时兼容原目录，显式空值不退回宽范围。
- 完整密钥只返回一次，创建响应禁止缓存；数据库仅保存摘要。界面只在组件内存保留一次性密钥；停用同一密钥立即清空复制入口。
- 连接命令拒绝把完整密钥放在命令参数中，不回显密钥。坏密钥或权限不足时保留原连接，不发设备码。
- 页面主区保留密钥操作和连接管理；没有待确认操作时隐藏空确认卡，存在敏感请求时仍可明确处理。
