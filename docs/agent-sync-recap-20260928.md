# 先同步再回顾（2026-09-28）

用户要求：每次询问今天／昨天点赞、收藏了什么，都先同步；减少授权步骤和等待。

## 已实现的流程

CLI 1.0.11：`zhicui recap yesterday --mode like --connect --json --timeout 5m`。
今天用 `today`，收藏用 `collect`，两类用 `all`；可选 `--platform douyin|bilibili`。
默认每个平台最近 50 条，上限 100 条。每次命令重新启动同步，不复用上次完成作为本次同步。

1. 检查公开能力和当前凭据；已有权限复用，不足时走设备授权，用户在浏览器确认。
2. 同账号桌面桥复用平台登录态，串行采集所选来源；需要登录／验证码时返回平台与本机 Run ID。
3. 只上传公开作品 ID、标题、作者和描述。Cookie、媒体地址、封面签名、本机桥令牌均不上传。
4. `library.activity.record` 复用已有笔记和文稿，仅给新视频补元数据，不下载媒体或执行 ASR。
5. `library.recap.get` 读取首次发现台账，包含未提取文稿的资料；按用户、平台、喜欢／收藏过滤。

每一步重新核验身份；MCP 已缓存的本机动作也不能绕过后来丢失的 scope。
新清单保存需要 `library:write` 与 `local:invoke`，旧只读凭据不会自行扩权。

## 时间与可用性边界

平台不提供真实点赞／收藏日期；回顾是知萃首次同步日期。补同步保留已有日期，今天发现的旧内容不倒填昨天。
这是有条数限制的最近清单，不声称全量；某个平台失败会返回明确 warning，全部失败不会拿旧缓存冒充最新。
本机动作仍只在桌面桥执行，云端不可调用本机桥；Core readiness 仅报告客户端前置条件，不声称用户平台已连接。
云端账号同步、自动定时同步、付费视觉分析等不在此次发布范围。

## 验证与发布

后端 71 项相关测试通过：日期不漂移、未转写清单、用户与来源隔离、隐藏记录保留、平台拒绝即停止、取消、权限和固定清单。
CLI 包含真实子进程 + HTTP 桥替身的完整流程、JSONL 单终态、账号切换、缺少授权、部分失败和本机 Run 轮询测试。
Windows 并发整套测试曾出现既有 Codex 命令探测超时，单独复跑通过；最终完整结果与正式部署证据在发布后补录。
