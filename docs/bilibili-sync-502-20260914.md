# B站同步 502 排查与修复

## 已核实的生产事实

- 用户截图显示本机已读取 20 条 B站收藏，随后显示 20 条待确认和重复的 502。
- 原生 B站采集仅返回规范 BV 链接和来源顺序，不上传登录凭据；每 10 条导入请求约 1 KB。
- 旧前端第一批只发送 10 条，遇到请求级错误后，把尚未发送的其余 10 条也标记为待确认，并丢失平台标签。因此截图不是 20 个独立失败请求的证据。
- 2026-09-14 18:31:34（北京时间），Jenkins 执行旧后端重启。uvicorn 等待现有连接退出。
- 18:33:05，systemd 等待 90 秒超时后发送 SIGKILL。同秒 Nginx 记录 `POST /api/library/imports` 的 upstream prematurely closed connection；部分 GET 请求连接失败。
- 18:31:40 至 18:33:10，多条业务 API 返回 502；18:33:15 后端恢复。18:38 是新 runtime 的正常切换。
- 直接原因是发布过程提前重启旧服务，打断同步长请求；未发现对应时间的 OOM 或 Python traceback。不能把本次 502 归因为 B站封禁、用户未登录或 20 个视频均失效。
- 旧 `/api/library/imports` 在一个 HTTP 请求内串行执行最多 10 条完整字幕、音轨下载或 ASR。服务重启时缺少可恢复的逐项任务状态。

## 本轮实现

- 发布前先验证实际运行的接口关闭状态和健康状态；已满足条件时跳过不必要的旧后端重启。真正切换 runtime、修复运行态漂移和回滚仍保留既有检查。
- B站账号同步通过持久任务接收，处理与 HTTP 请求分离。逐条状态保存，按固定快照和来源排名处理；已保存的完整文稿复用，历史资料不删除。
- 后台限制并发，利用数据库咨询锁防止多进程重复执行；重新启动后继续尚未完成的条目。
- 页面先登记所有批次，再读取任务进度；排队不计为新增，重新打开页面可恢复查询。未提交、处理中和失败分开显示。
- 请求级错误合并提示并保留平台，不再以重复 URL 和技术错误占满用户界面。

## 验证与发布

- 后端 103 项回归通过：持久任务、路由鉴权、用户隔离、增量顺序、文稿复用、B站公共提取和隐私账户操作。
- 前端 59 项回归和类型检查通过：完整 API/面板逻辑、先登记后轮询、断线分类、同快照人工重试、正常 skipped 兼容、取消后停止下一来源。
- 发布相关 50 项回归通过，其中 17 项执行真实 Bash 分支；已关闭且健康时不再提前重启，其他状态仍修复并验证。
- 独立 PostgreSQL 16 临时集群：真进程 kill 后恢复，4 个工作进程的全局提取峰值为 2，4 条分别仅提取一次；已提交文稿但任务尚未标完成的条目复用，最终顺序正确。测试平台提取使用夹具，没有访问生产用户资料或实际平台；临时集群已停止并清理。
- 真实 Chrome 验收 6 项通过：20 条两批登记、等待 30 秒后继续后台观察、完成自动刷新、刷新页面/反复开关弹窗恢复、390 像素窄屏不横向溢出、无页面运行错误。
- 浏览器夹具修正了缺失的必填 `tags` 字段和 `tab` 角色定位；首次编辑期间的开发页脚本错误未在最终冻结代码验收中复现。没有把夹具错误归因为产品故障。
- 本轮网页目标版本为 1.1.13，不修改原生 B站采集或安装包。生产上线结果在发布完成后追加。

## 边界

- 本次恢复机制适用于新接口已经持久接收的任务；不能复活旧接口在本次部署前被中断、尚未登记的条目。用户需重新发起一次该来源同步。
- 正式任务仍依赖视频可访问及字幕/语音服务。测试验证队列、顺序和重启恢复，不等于已替用户完成截图全部视频的实际转写。
- 同一已保存文稿按 BV 和账号复用；若外部 ASR 已完成、但进程尚未保存文稿即崩溃，恢复仍可能需要再次提取。
