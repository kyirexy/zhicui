# B站博主近期目录接口发布记录

## 本次行为

- Web 1.1.22。现有官方 CLI 1.0.21 的通用 Action 命令可直接调用，无需更换已保存密钥。
- core 开放 `creator.resolve`（B站）、`creator.catalog.import`、任务只读查询及平台绑定状态查询。
- 导入动作同时需要 `library:write` 和 `creator:read`，固定读取明确指定主页的前 20 条公开投稿目录，不自动转写或创建订阅。
- 新任务使用 `catalog_recent`，不复用正在运行的全量/自动转写任务；旧只读凭证、日常 7 项权限和有效期均不改变。
- 使用标准公开投稿接口；已有失效平台绑定不降级匿名。登录或风控错误停止并保留原因，不循环请求。普通失败也不自动重试。
- 核对唯一 BVID、投稿时间顺序与首屏完整性。合法少于 20 条时返回真实数量，部分失败不标为完整。
- 客户端资料和博主目录按当前账号保存。Web 的任务进度与通知区分目录、文稿、部分完成与失败。

## 验证与发布要求

- HTTP/MCP 覆盖每日权限、只读拒绝、额外字段拒绝、幂等与凭证/账号隔离。
- 服务测试覆盖只保存目录、20 条上限、保留历史、并发范围冲突、平台验证、短页与失败不重试。
- 数据库 CHECK 约束迁移保留旧任务；生产使用加密备份及隔离 PostgreSQL 双启动演练验证。
- core readiness 检查数据库、模型、B站基础功能开关和任务运行器。平台会话/公开主页可访问性在每次实际请求验证，不宣称已由健康检查验证。
- 生产按同一冻结 SHA 先 dark、恢复演练、再 core 晋级；真实问答 SSE、PAT/MCP、权限拒绝和凭证吊销均为必过项。
- 用户指定 UID `646732586` 的实际导入在发布后复用现有连接执行；发布冒烟不替代真实博主抓取结果。
