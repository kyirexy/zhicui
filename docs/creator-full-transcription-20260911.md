# 博主全部自动转写

用户要求：博主页面不能只刷新目录后留下“未转写”；点击一次就自动转写全部作品。

- 主按钮改为“全部自动转写”，新增博主保存按钮明确为“保存并全部转写”，保存后直接启动同一全量后台任务。没有页面打开、启动或定时触发的自动采集。
- 兼容原有目录 API，新增可选 `auto_transcribe` 参数；`catalog_all + auto_transcribe=true` 在目录发现完成后将全部作品加入持久化转写队列，使用同一个 Run，不受 20/50/100 条近期限制。
- 任务保存发现/转写阶段、逐项状态和整体进度。切换页面不影响后台；取消后停止后续作品，重试保留成功项、只恢复未完成和失败项。
- 仅复用当前用户已有且非空的文稿；空文稿或其他用户文稿不能被标记复用。保留用户移除记录，不恢复已移除资料。
- 风控、需要登录或目录不完整不冒充全量成功；不循环更换账号或连接器。
- SQLite/PostgreSQL 启动迁移为已有 creator_sync_runs 添加 `auto_transcribe BOOLEAN NOT NULL DEFAULT FALSE`；旧任务保持原语义。
- CLI 调用：`zhicui creator sync <source_id> --operation catalog_all --auto-transcribe --wait --json`。

测试覆盖超过 100 条的同 Run 自动转写、失败后不重新抓目录且只重试失败项、取消与续跑、非完整目录停止、非全量参数拒绝，以及非空文稿和账号隔离复用。测试的转写器使用隔离夹具，不代表已执行用户真实博主的批量 ASR。

验证结果：628 项后端回归通过（1 项 Windows 不适用的 POSIX 测试跳过），78 项 CLI 测试通过，Next.js webpack 生产构建通过；Chrome 客户端桥夹具 7 项检查通过，确认主按钮发送 auto_transcribe=true、不提交数量限制，发现阶段后显示 45/121 转写进度。发布后的迁移/备份恢复与线上入口回读另行记录。


## 并行提取修正

用户要求全量作品同时提取文字。全量自动转写改为最多 3 个作品并行，完成一个补入一个，不将全部作品一次投递。协调线程独占任务状态写入，在途提取完成前保留租约；临时失败独立退避，其余作品继续，取消/风控停止新增投递并保留已完成文稿。近期/手选原有操作保持兼容。新增屏障测试证明 3 个提取真实重叠、队列上限、临时失败重试只处理失败项、风控停止新增和在途成功保留；取消测试加强验证已完成结果保留。

并行修正验证：631 项后端回归通过（1 项平台相关跳过），Next.js webpack 生产构建及 Chrome 客户端桥夹具 7 项检查通过。
