# 每日研究：原生产品交付记录

用户要求将“定时同步喜欢/收藏，提取近两日新增视频，分析选题与制作方法并邮件推送”作为知萃核心功能。2026-10-13此前建立的Codex定时任务是过渡方案，不能冒充知萃原生功能。

## 产品约定

- 独立 `/daily-research` 页面、桌面侧栏与首页核心入口；Web也可管理和读报告。
- 默认北京时间15:00、抖音喜欢和收藏、今天及前一天首次发现的视频；可配置来源、时间、收件邮箱和关注方向。首版仅开放抖音。
- 复用已有云端AutomationRunner作为唯一产品调度器；普通用户JWT产品路由独立于Agent协议发布档。保留旧昨日摘要兼容性。
- 客户端主进程领取云端采集任务，复用官方登录平台连接；不依赖首页、不依赖用户安装CLI或Codex。电脑离线时明确等待上线，不承诺唤醒关机电脑，不擅自启用开机启动。
- 两个来源各最多500条；每批最多100条入库；报告展示partial/limited覆盖情况、read/saved/created/reused/skipped/failed。
- 窗口上界取同步完成时间，防止漏掉15:00触发后入库的视频。来源台账按作品去重，保留喜欢和收藏；真实点赞日期未知。首跑可能补发现历史内容。
- 缺文稿/平台验证/下载失败不能伪装为已看原片。报告分别列标题/发布文案、文稿与画面依据，给推荐原因、原视频链接和原创制作建议。
- 站内历史报告与邮件共用持久结果。任意收件地址需要单独验证，不要求更改登录账号邮箱。发送前落库；结果未知不得盲目重发。
- 研究沿用现有额度预留/结算，不绕过免费次数和萃点规则。不自动付费生成视频或发布。

## 验收清单

- [ ] 核心首页/侧栏/移动访问路径可见，设置、报告、历史可用。
- [ ] 每用户隔离、只向验证邮箱投递、验证码限频/过期/错误次数。
- [ ] 固定时区定时幂等，手动运行异步，暂停/修改旧任务不能投递。
- [ ] 桌面多设备抢占、批次幂等、注销/换号取消、离线恢复。
- [ ] 跨日窗口、两来源去重、未解析清单不漏、覆盖不夸大。
- [ ] 模型/邮件失败不会清空已保存报告，未知投递不重复发。
- [ ] 后端既有测试、前端TypeScript/导航、桌面构建/消费者测试通过。
- [ ] 实际浏览器检查，生产后端/Web与Windows版本验证。

## 发布边界

当前工作树存在其他未提交的视频分析和部署改动；本功能只提交自身文件及必要小改动，不夹带那些变更。生产邮件服务仅检查配置存在性，未读取或输出秘密；SMTP host/from/auth已配置，EMAIL_DELIVERY_ENABLED=true。不得因已配置就宣称实际投递通过。

原Codex定时任务 `automation` 暂保留。在原生订阅成功启用并完成验证前，不关闭用户已生效的过渡任务；迁移成功后避免两处重复推送。

## 本地验证

- 目标版本 Web 1.1.18 / Windows beta 1.1.21；CLI不变。
- 后端每日研究、来源登记、Core边界、readiness：76 passed，14 subtests passed；另4项HTTP鉴权、来源白名单、阶段联动及旧库重复迁移通过。
- 桌面build、每日研究消费者mock、平台连接器、会话和同步桥验证通过。涵盖401自动重新确认、账号切换、租约撤销、断网/回包丢失、检查点恢复、批次重复与手动同步隔离。
- 前端生产构建、TypeScript、24项导航及7项研究逻辑测试通过。1440/390/320尺寸的mock浏览器验收通过；截图仅为fixture，不是真实研究结果。
- 独立复核并修复poll状态竞态、迟到批次回执覆写、失败数重复抵扣、跨日计费预留和多session缓存二次结算。
- 报告目前不核验原片画面：完整清单保留，文稿研究最多100条，缺失文稿最多尝试提取3个代表样本；视觉与剪辑建议需要补充原片证据，不能声称自动逐条看过。
- 上述测试没有调用真实平台、ASR、模型或SMTP；生产发布和真实用户验收另行记录。
