# 抖音博主同步健壮性与两端正式部署

本次基于已上线的 `deb4bf721296` 独立检查，不混入主工作区其他修改。

## 修复

- 合作视频按用户、博主、平台和视频保存独立目录；同步另一个博主不会移动现有目录项。文稿继续按用户和视频复用。
- 新博主目录继承该用户对同一作品的永久隐藏或删除墓碑；只有明确恢复才重新显示，不影响其他用户。
- 分页数量上限失败时不修改已确认去重集合；同页并发只请求一次，取消在途请求不推进分页状态，异常风险字段返回受控错误。
- Windows 可变更新清单使用 Nginx 精确匹配，避免落入版本文件的长期缓存规则；版本化安装包与 blockmap 仍长期缓存。

## 数据迁移验收

PostgreSQL 在单事务和表锁内建立新的 source 唯一约束、移除旧约束，不重建表、不修改行或记录 ID。锁内重新读取约束，兼容并发启动、旧约束改名、已有等价新约束，遇到同名异列停止并回滚。部署通过 systemd restart 先退出旧进程，再执行新 startup。

已在实际 PostgreSQL 随机独立 schema 验证 5 场景：并发执行、带引号旧名称、已有新约束、等价新约束、名称冲突回滚；全部通过。每个 schema 仅含验收夹具，结束后全部清理，未访问或修改现有业务表。

生产变更前记录摘要：294 条文稿、361 条本地抖音资料、403 条来源台账、9 条隐藏记录、90 条博主目录。完成部署后核对迁移未改变原记录，并再次同步目录、重复提取现有文稿验收增量复用。

## 两端兼容

现有 Android 1.3.7（29）的前端功能源码与本次一致，调用正式 API；Windows 1.1.4 原生源码未改变，加载正式网站页面。本次无需重复打包即可在两端生效。保留现有 Beta 安装包渠道及签名约束，未将其改称 Stable 包。

两端的编译、更新和发行契约、公开页面窄屏验证及发行文件回读详见 `client-creator-compatibility-20260910.md`。65 项同步/迁移回归中 64 通过、1 项既有 POSIX-only 跳过；另有 18 项发行/下载测试通过，迁移与永久隐藏变更经独立复核。最终流水线与记录复验结果完成后追加。
