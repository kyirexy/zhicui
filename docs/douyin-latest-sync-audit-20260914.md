## 已复现并修复

1. 复用窗口时，新导航失败仍可能接收旧页面首屏并返回成功。采集按本轮主文档提交隔离；使用 Chrome 主框架的新文档 loader 判断提交，不能把 hash/history 同文档跳转当作新加载。刷新清空旧页链，旧文档迟到响应不进入新结果。页面未成功重新加载时保留原资料并明确失败。
2. 普通 `goto` 不保证重新获取网络结果。真实 Chrome 本地 HTTP / Service Worker 夹具复现旧缓存；采集期间禁用 HTTP 缓存并绕过 Service Worker，结束释放调试会话，保留登录资料。收藏通常为 POST，不能仅凭这个缓存风险断言它解释了用户的收藏批次。
3. “准备 29 条文案”原先重读当前列表顶部 29 条；在前 21 条已完成、后 29 条待处理时只覆盖 8 条。现在直接按当前分类待处理 ID 使用已有任务队列，超过 100 条继续分批，复用有效的临时媒体地址。失败如实保留重试入口，不额外改变来源同步状态。
4. 桌面同步未恢复本次确认读到的临时隐藏项。现在只恢复本批有效 ID、采集前的临时隐藏，与目录和排序台账同事务；永久隐藏、其他账号以及采集中新增的隐藏不受影响，异常整批回滚。
5. 原记录缺少可核对的采集信息。新增严格白名单诊断：文档提交、缓存状态、固定接口路径/方法、首屏游标、页数、前三个作品 ID 和采集时间，关联服务端同步批次，存入既有活动日志。没有数据库结构迁移；不记录完整 URL、参数、Cookie、请求头或媒体地址。诊断不作为身份或排序的可信依据。

新旧版本网页可能共存，因此网页和后端共同将可靠顺序写入最低桌面版本提升为 1.1.9。先发布可下载的新安装包，再更新网页/后端；既有历史资料和无需可靠顺序的兼容路径保留。
