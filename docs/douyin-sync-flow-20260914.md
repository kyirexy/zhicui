# 抖音同步窗口、资料目录和文案队列修复

日期：2026-09-14。基于生产提交 `d5b63c4298cd303a90328deaca14aaac88c21dc4` 的独立工作树，保留同期反馈群页面改动；未覆盖主工作目录未提交内容。

## 问题与处理

- 原采集器每个分类结束都关闭浏览器，多来源队列又自动开始下一项，造成点击显示窗口附近关闭、等待重开的体验。现在同一用户、同一同步批次复用浏览器及操作锁；最后一项、取消、失败或空闲超时释放。需要用户操作时停止后续来源，恢复当前窗口；取消整轮同步。显示窗口合并重复请求并限制等待时间。
- 官方分类列表已有可信排序但缺作者或封面的作品被旧质量缓存隐藏。现在这类作品先进入资料目录，继续准备文案；仍拒绝无有效元数据的占位数据。编辑、AI 处理和旧资料恢复不改官方排序。
- 只要有本地资料，旧版目录原先就被整体跳过。现在后台一次性补存当前用户、当前绑定的旧目录，仅归档公开元数据，立即返回已有资料；前端最多静默刷新30秒。恢复失败保留已有资料，稍后重试。详情和封面优先已有目录，避免先等旧连接器。显式刷新仍可更新旧目录。
- 文案任务已有批次时，后续同步结果原先直接跳过；请求还可能被静默截断。现在分块预留所有任务、最多并发提交三批，不等待前一批转写结束；本轮同步范围内未完成任务可以补做，已完成和已运行条目去重。保留后端ASR并发控制，界面显示全部任务的完成数量，不把4个处理槽当作总数。
- 恢复卡改为短状态、必要按钮、折叠帮助；桌面账号区去掉重复技术信息。保留真实失败、未完成数量和下一步操作，不展示内部错误原文。
