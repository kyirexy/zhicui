# 知萃首页与首轮宣发手册

更新日期：2026-09-06。本文是可执行的内容与实验方案；尚未发布的短片、待采集事件和目标值都不代表已有成果。

## 1. 先让哪一类人觉得“这就是我要的”

第一批重点用户：已经在抖音、B 站收藏了教程、公开课和知识视频，需要在学习或工作时找回其中具体方法的人。先围绕软件教程、AI 工具学习、内容创作方法三个相邻场景制作素材，避免一条广告同时讲健身、烹饪、投资和编程。

他们的具体困难是：收藏后找不到那句话；几位博主各讲一部分，难以比较；看懂了，却不知道今天先做什么。

核心定位：**把收藏视频，变成自己的知识。**

可复用的解释文案：

> 把需要的视频整理成完整文案，带着问题核对原文，再把有用结论保存为知识或行动计划。电脑整理，手机继续。

首页和宣发按同一个顺序讲故事：具体问题 → 可看到的产品结果 → 两三步操作 → 一次明确邀请。首页首屏应让访客先看到实际界面或可操作示例；完整下载信息随后展开。

每次只邀请用户完成一步：**“带一条你已经收藏的视频来试试。”** 不要求用户先导入全部收藏，也不把“下载完成”当成获得价值。

## 2. 文案与证据的边界

| 可以讲的内容 | 必须对应的证据或说明 |
| --- | --- |
| 单条视频整理成完整文案 | 录制实际提交、处理状态和最终文案；转写可能有误，需要核对原视频 |
| 选多条视频一起提问 | 实录所选资料、问题、回答和原文依据，主题保持一致 |
| 保存为知识或行动计划 | 展示真实保存结果；如果剪辑跨过等待，明确标出 |
| 手机继续阅读、提问和执行计划 | 使用 Android 实机；平台账号采集仍需 Windows |
| 界面中的示例问答 | 明确标“交互示例”或“示例内容”；未经实际生成核验，不称作真实 AI 回答 |
| 实际应用中的演示数据 | 标“真实界面 · 示例数据”，不能包装成真实用户案例 |

同步由用户手动发起，不写“自动追更”“自动同步全部视频”。不承诺固定处理秒数、准确率、节省百分比或必然学习效果。不使用未取得授权的用户评价、资料截图和私人账号内容，也不编造用户数。

客户端下载状态以网站当前发布信息为准：Android 与 Windows 提供公测安装包；Mac 为测试版，需保留安装与验收状态说明；iPhone / iPad 尚未发布。手机广告中不要使用 iPhone 外框承载 Android 截图。

## 3. 三条 20–40 秒短片脚本

以下均为**待拍摄脚本**。先完成可核验的产品操作，再按实际结果剪辑。没有得到对应结果的镜头不能用动画冒充。建议保留完整原始录屏，剪辑版加中文字幕；等待可压缩，但画面标注“等待过程已剪辑”，不暗示视频时长就是处理耗时。

### 短片 A：收藏的教程，下次还能找到那句话吗？（约 28 秒）

| 时间 | 真实操作画面 | 字幕 / 口播 |
| --- | --- | --- |
| 0–4 秒 | 在知萃已处理文案中展示一个能直接用于工作的步骤 | “上次收藏的教程，这一步到底怎么做？” |
| 4–10 秒 | 粘贴同一条已获展示许可的公开视频链接，发起处理 | “把需要的那条视频，整理成完整文案。” |
| 10–20 秒 | 展示实际处理结果，定位原文并提出一个具体问题 | “带着具体问题看内容，再回到原文核对。” |
| 20–25 秒 | 保存真实生成的有用结论，展示保存后的知识条目 | “用得上的，留下来。” |
| 25–28 秒 | 产品名、网址和简短邀请 | “带一条你收藏的教程来试试。luxai.cn” |

拍摄选题建议：一个实际用过的软件操作问题，如“这个教程里，导出前要检查哪几项设置？”问题和字幕必须根据选定视频改写，不能先写答案再找素材。

### 短片 B：三条视频讲同一件事，怎么一起看？（约 35 秒）

| 时间 | 真实操作画面 | 字幕 / 口播 |
| --- | --- | --- |
| 0–5 秒 | 展示本次真实回答中的一条比较结果，同时露出来源 | “同一个问题，三位作者说法一样吗？” |
| 5–12 秒 | 在视频资料中勾选三条同主题、文案已就绪的视频 | “先选这三条资料。” |
| 12–23 秒 | 输入问题，展示实际回答与来源展开操作 | “有哪些共识？哪里不同？分别依据哪段原文？” |
| 23–30 秒 | 打开其中一条原文核对，保存其中一个结论 | “看结论，也能检查它从哪里来。” |
| 30–35 秒 | 首页演示入口与网址 | “你的收藏，也可以带着问题重新看一遍。” |

拍摄选题建议：同一工具的三条入门教程。只有实际回答提供了可核验的比较结果，才采用片头；若回答未覆盖某个点，保留真实限制，不补写一个更漂亮的结果。

### 短片 C：电脑整理好的内容，手机接着用（约 30 秒）

| 时间 | 真实操作画面 | 字幕 / 口播 |
| --- | --- | --- |
| 0–5 秒 | Android 实机打开一份准备执行的计划或知识条目 | “离开电脑，刚整理的方法也能接着用。” |
| 5–12 秒 | 电脑保存对应知识或计划，露出条目标题 | “在电脑整理需要的内容。” |
| 12–21 秒 | 同一演示账号的 Android 实机打开同一条目 | “在手机继续阅读、提问。” |
| 21–26 秒 | 如果使用计划，勾选一个实际完成的演示任务 | “把下一步放进今天的计划。” |
| 26–30 秒 | Android 下载入口，旁边一行平台说明 | “Android 公测可下载。平台账号采集需 Windows。” |

知识与计划二选一讲完整，不在 30 秒内轮播所有页面。跨端结果必须实际验证；如果内容是手动准备的演示计划，全片标“真实界面 · 示例计划”，不要声称它来自刚才那次 AI 生成。

## 4. 七天小规模内容实验

首轮目的是找出哪个问题最能让目标用户开始使用。先做自然内容分发，不设无依据的投放预算或下载目标。每天记录相同口径；频道的流量机制不同，不直接用播放量排名产品价值。

| 日期 | 执行动作 | 当天要验证的问题 |
| --- | --- | --- |
| 第 1 天 | 用独立演示账号完成短片 A 的真实操作；检查来源许可、文案和保存结果；记录完整录屏 | “找回教程中的具体步骤”能否展示出完整价值？ |
| 第 2 天 | 制作 A 的竖版和字幕，在抖音发布一个版本；评论区只回答真实产品问题 | 访客是否理解自己能拿什么内容来试？ |
| 第 3 天 | 在 B 站发布 A 的完整操作版，并补足处理中等待和来源核对；保留与抖音相同的核心主题 | 更完整的操作证据能否减少疑惑？ |
| 第 4 天 | 在小红书发同一案例的 5–6 张步骤图：问题、输入、文案、提问、结果、平台说明 | 静态步骤是否比抽象功能文案更容易理解？ |
| 第 5 天 | 录制并发布短片 B；优先选择前几天讨论最明确的平台；仅替换“单视频”到“同主题多视频”这个变量 | 用户更关心找原话，还是比较不同内容？ |
| 第 6 天 | 录制并发布短片 C；正文写清 Android 与 Windows 分工，使用同一演示条目 | 手机继续使用是否是实际购买/使用动机？ |
| 第 7 天 | 汇总有效提问、落地页可用数据、下载请求及自愿反馈；选一个表现更清晰的场景继续做第二条案例 | 哪个场景带来了实际使用，而不仅是点赞？ |

素材发布、评论回复和私信发送需由运营人员执行，或另行明确授权。不要把本文当作已经发布的记录。若一周数据量不足，延长观察并保留版本，不强行宣布胜出。

## 5. 衡量有意义的转化

漏斗定义：看到内容 → 打开官网 → 观看演示 / 查看示例 → 发起下载或登录 → 完成第一条资料处理 → 提问或保存一个有用结果 → 后续再次打开使用。

| 指标 | 口径 | 当前如何处理 |
| --- | --- | --- |
| 内容带来的兴趣 | 同一平台内，比较有效提问、主页访问、可获得的外链点击 | 记录平台实际提供的数据，标明日期与内容版本 |
| 演示参与 | 官网演示开始、看至关键步骤或完成一次示例操作的访问数 | 尚需实现事件采集；不能从播放按钮存在推断有人看过 |
| 下载意向 | 有效下载请求；按 Windows / Android 分开 | 可观察已有下载计数，说明它可能包含重复请求 |
| 首次价值 | 新用户成功处理第一条资料，并完成至少一次提问或保存 | 尚需实现匿名或授权的聚合统计，不抓取问答正文 |
| 持续使用 | 获得首次价值后的用户，在约定观察窗口再次阅读、提问或执行计划 | 先确定观察窗口与去重口径，再实施统计 |
| 使用障碍 | 无法安装、平台连接受限、处理失败、看不懂结果等问题 | 使用自愿反馈按问题类型记录，不收集账号凭据 |

真正要优化的是从“来看看”到“处理自己的一条内容并得到可用结果”。下载高但首次价值低，应检查安装、连接和首次操作；演示参与高但下载低，应检查用途、平台信息和下一步是否明确。没有对应事件数据时，这些只是待验证假设。

未来埋点可采用 `landing_view`、`demo_start`、`demo_complete`、`download_intent`、`first_material_ready`、`first_value_action` 等事件名，保存来源标签与匿名访问标识。需落实去重、统计窗口与隐私说明后才能报告转化率；不要上传视频正文、私人标题、问题内容或访问令牌。转化率必须同时报告分子、分母和时间范围。
