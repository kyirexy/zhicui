# 增量同步、来源顺序与同步记录

## 本次规则

- 同步始终增量合并。同一用户按平台作品 ID 去重，完整、部分及空采集都不能自动删除已保存资料或历史来源成员；删除仍由用户明确操作。
- 收藏、喜欢、作品分别保存来源排名和采集快照。最新可信批次按平台原始次序展示，历史未出现资料保留在后面。编辑、AI 整理及视频发布时间不参与来源排序。
- 不可靠采集不能覆盖已有可信排名及其对应快照；首次出现且没有可信排名的资料稳定置后，后续可靠同步可以补齐。
- 已完整保存的 B站视频直接复用文稿，不重复下载、ASR 或生成。抖音自动文稿准备仅针对本次真正新增项；旧资料缺文稿时通过补齐操作重试。
- B站同用户同作品提取使用 PostgreSQL 会话锁，避免多请求并发重复 ASR；SQLite 开发环境使用进程锁。慢请求已完成的文稿保留原快照，后续请求复用并校准自身顺序。
- 每批请求先持久记录，再处理条目；同一批处理中重复提交返回 409，避免重复执行和抢写最终结果。分批上传共享采集时间和连续偏移，旧快照不能覆盖更新来源数据。
- 新增 `library_sync_runs` 表，记录平台、分类、快照、范围、可靠性、条数、新增/复用/失败/跳过及安全错误码。仅保存规范作品 ID 和请求摘要，不存平台凭据、正文或媒体地址。
- `GET /api/library/sync-runs` 鉴权并按当前用户隔离，响应禁止缓存；同步窗口“最近同步记录”展示最近 20 批。记录纳入账号导出与删除范围。
- 首页、资料库和 Agent 共享缓存版本：写入响应立即作废旧版本，迟到读取不能写回缓存；切回前台补读。局部请求失败保留同账号最近成功资料，切换账号不会回填旧数据。

## 边界

- 这是每批 HTTP 同步的持久结果记录，不是后台可恢复任务执行器；进程中断留下的未确认记录显示“结果待确认”，用户可重新同步，已保存资料继续复用。
- 本次起新增同步记录，旧记录不凭空回填。旧版 B站资料缺可靠排名时需再次同步相应分类。
- 网络中断或尚未提交的条目标记“待确认”，不能假报全部成功或全部失败。
- 桌面客户端加载线上页面，更新后重新打开或刷新即可；Android 内置前端未重打包。
