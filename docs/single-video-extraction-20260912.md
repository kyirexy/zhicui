# 单条视频链路与进度简化

用户要求：检查单条视频处理慢的链路，并减少说明，不向普通用户展示底层技术。

## 修正

- 抖音单条入口原先使用外部 DouyinProcessor：完整视频先落盘，再以高质量 MP3 编码，最后使用没有 timeout 的 HTTP 转写调用。现在复用现有流式媒体处理：边接收视频边提取单声道 16kHz / 64kbps 音频，保留受控超时、重试及成功/失败清理。已解析的视频元数据继续复用。
- 流式链路已经在同一份音频上尝试本地兜底。抖音接口失败后不再从路由再次下载整个视频、重复兜底。
- 服务端记录媒体准备耗时、输入/音频字节数、文字提取耗时与字数，不记录媒体签名 URL 或密钥。
- 进度页仅显示读取内容、提取文字、整理内容、保存笔记等步骤和当前等待提示；移除技术日志列表、模型名、重复标题和顶部重复状态。SSE 常规进度文案也统一为简短中文，移除 model/provider 字段，保留完整结果及必要错误提示。
- 并发测试使用独立 SQLite 文件连接，修复原有内存共享连接下轮询回滚干扰写入的偶发测试问题；生产并发仍为用户要求的 50。

## 验证

632 项后端测试完成（1 项平台相关跳过），Next.js webpack 生产构建通过。Chrome 桌面/手机 SSE 夹具 16 项检查通过，确认已进入提取文字阶段、旧技术信息不显示、无横向溢出、取消与重新打开正常。

服务器真实 HTTP + FFmpeg 夹具成功：2 秒样例视频仅生成临时音频，媒体阶段约 77ms、总流程约 79ms，ASR 使用夹具，临时文件清理通过。此结果用于验证链路，不代表真实转写接口或用户视频的耗时。

截图对应视频 7681642132423200019 公开直链复测返回 VideoMetadataUnavailableError，未继续重复请求；已请求用户提供原始分享链接，因此不宣称该视频获得确定的速度提升。之前真实 ASR 测试的响应波动仍然存在，本次不会消除提供商等待。
