# 单条视频信息与重复导入修复

## 现象与原因

用户反馈视频 `7681642132423200019` 导入慢，标题变成“抖音作品 + 编号”、作者为空。只读核实生产记录：同一账号 10:22 的笔记有真实标题和作者“飞天闪客”，10:49 的重复导入保存了默认标题、空作者，分别有 3164 和 3098 字文稿。

- 已绑定账号的恢复入口只读取同步列表；未同步作品虽然可以读取媒体，却没有补取详情。
- 旧公开解析依赖省略作者、封面，并把标题按文件名处理；还有重复且没有超时的页面请求。
- 输入框和首页分流提前丢弃分享文案，服务端失去标题补充来源。
- 单条入口没有复用同用户已有完整结果，重复导入再次下载、转写和生成摘要。

## 修复

- 公开解析统一使用受限页面读取，按目标作品 ID 匹配真实标题、作者和封面。
- 分享文案从输入框、首页到服务端完整保留，只用于补缺，不根据标题猜作者。
- 已绑定账号在读取媒体详情时缓存公开标题、作者和时长，按当前会话隔离，限制 256 条、有效期 1 小时，重新登录或退出时清空。导入前后只读取已有缓存，不再为了信息额外请求平台。旧资料单独补缺时仍可主动查询详情，总等待 8 秒。
- 单条导入复用当前用户同平台、同作品的完整笔记与计划；缺失信息可从同用户旧记录或新详情补齐。空文稿、标题/描述占位、图片兜底、未完成摘要不可复用，B站分 P 不混用。
- 已有资料只补标题作者时不再重做文稿；快速返回也能正常进入资料页。
- 阶段耗时仅记录于服务端，不加入普通用户进度文案。

## 验证与发布要求

后端 666 项测试完成，1 项因 Windows 平台跳过，其余通过。前端 17 项链接测试与 webpack 生产构建通过。Chrome 桌面和手机 10 项夹具验证通过：输入框保留完整分享文案、立即复用自动跳转、标题和作者显示、只发起一次导入、无运行时错误。夹具未对真实账号发起导入。

正式发布继续使用 Jenkins、加密备份及同提交恢复演练。伴随服务需要单独执行该提交中的 `upgrade_creator_api.py`，升级器保留会话、原子切换并在健康检查失败时回退。发布后使用用户已有的这条视频验证元数据修复与重复导入耗时。

本次减少自身重复工作，不把重复导入速度当作首次语音识别速度。外部转写响应仍可能波动，首次完整转写不能承诺秒级完成。

## 正式环境实测与二次修正

Jenkins #231（`78991f38b36d60d0f4ad7fd8dd864c9d79dcb617`）及伴随服务升级通过。用户指出的笔记已从同用户旧记录补回真实标题和作者“飞天闪客”，原文稿和摘要内容未变，没有新增笔记。完整结果复用的服务端核心路径约 3.8ms；此数值不包含浏览器、网络和页面渲染。

同一视频单次真实文稿提取成功：视频读取及音频准备 19.650 秒，文字识别 146.529 秒，共 166.182 秒，得到 3098 字，未创建笔记，也未重复生成摘要。主要等待仍在文字识别。

实测发现独立详情查询 8 秒未返回，而随后正常媒体读取能取得详情。因此进一步将元数据获取接到已经完成身份校验的媒体详情读取处，转写结束后从缓存补到预览和笔记，省去额外详情请求。安装器测试覆盖固定源码位置、重复安装、作品身份不匹配、会话隔离与退出清理。

这次追加修正后，后端全量 672 项测试完成，1 项平台相关跳过，其余通过；前端实现未再修改。

#231 同提交恢复演练通过：两次启动迁移，快照 587 条笔记、17 个计划、14 个用户，未启动任务；临时数据库和文件已清理。证据 `agent-schema-rehearsal-20260912T031345Z-78991f38b36d.json`，SHA-256 `9a4fbf7bdf6c918e87200f435f2ab271980ff0af07bfe2f6a6eab98b0960d83f`。
