# 抖音收藏真实分页与分类恢复修复（Windows 1.1.3）

## 状态

前端回归、真实账号收藏/喜欢各 50 条全序核对、生产收藏台账校准、Windows 1.1.3 发行与本机升级、正式网页 Jenkins #213 部署及部署后复验均已完成。最终结果见下方记录。

## 现场根因

- 收藏官方列表采用 POST 请求，请求游标位于请求体。1.1.2 只检查 URL 查询参数，缺少游标时默认当作 `0`，因此滚动后的后续页可能清空已采集前缀，再被登记为新的首页排名。此前针对 URL 中混合游标的修复没有覆盖这条真实请求链路。
- 原先通过“收藏”可见文本点击标签，没有严格等待官方标签出现和选中状态稳定。官网水合时实际会吞掉最初点击，页面仍停留在“作品”；该轮没有取得收藏接口首屏。本人主页也可能一直保留 `/user/self`，不能要求它必须跳转才能选择分类。
- 喜欢成功、收藏失败时，前端没有将喜欢结果覆盖到收藏。当前收藏页保留旧台账的来源排名；历史采集若曾把后页误登记为可信首页，单纯刷新网页无法校正该台账。
- 卡片日期优先来自视频发布时间，与收藏顺序不是同一个字段。旧年份的视频也可能是当前最近收藏，不能依据发布日期推断未同步或排序错误。

## 实现范围

### Windows 原生采集

- 采集请求 URL、method 和 POST body；解析 JSON 或表单中的来源游标。收藏使用 `cursor`，喜欢和作品使用各自游标规则；请求体与查询参数冲突、游标缺失或非法时，不再默认为首屏。
- 按官方游标连续连接列表，保留首屏到后续页的先后关系，不能用网络完成顺序或视频发布日期替代收藏顺序。
- 官网在滚动过程中可能自行重发首页。最多保留相邻两轮独立页链；新轮首页及所有已返回重叠页的完整身份序列、游标与结束标记相同，且上一轮独立满足所选数量时，可保留那一轮完整结果。新轮缺失/变化、身份缺口或未知游标时不回退，不跨轮拼接后页；新轮自行读满时优先使用新轮。
- 使用官方标签 ID 和 `role=tab` 定位喜欢、收藏和作品，分开计算页面加载与标签选择等待时间，确认 `aria-selected=true` 稳定后继续。仅在仍未选中时最多点击三次，每次完成后至少间隔两秒；已选中的标签不重复点击。
- 真实 DOM 的活动 pane 只有零尺寸动画占位，卡片位于兄弟区域。沿精确已选标签的 aria 关联活动面板寻找实际滚动祖先，不再要求占位面板内部存在视频链接。资料仅来自对应分类的官方列表响应。
- 只在资料数量和实际滚动位置均不再前进时累计停滞。长列表尚未滚到分页触发区时，不因五轮数量相同提前停止；保留 36 轮与挂起请求时限，初始化回到顶部只执行一次。

### 网页入口与展示

- `MIN_LOCAL_DOUYIN_DESKTOP_VERSION` 提升为 `1.1.3`，版本比较使用该常量作为唯一最低版本来源。
- 资料库与 Agent 的抖音本机同步入口均先检查版本。1.1.2 加载新网页后会提示升级，不开始本机采集，也不绕过该检查走旧收藏同步分支。B站、小红书、普通链接导入和既有文稿任务不受此抖音能力门槛影响。
- 切换抖音分类时同步更新 URL 中的 `mode`，保留其余查询参数、锚点与浏览器历史状态。由首页收藏入口切换到喜欢后，刷新不会再被旧 URL 拉回收藏。
- 卡片桌面视图标注“发布于”；缺少发布日期且显示记录日期时使用“记录于”。窄屏两列卡片保留短日期，并通过完整提示及无障碍标签说明日期含义。保持原日期来源与排序规则。
- 右侧资料预览同步补上日期含义：抖音的原发布日期标为“发布于”，记录日期回退标为“记录于”；跨平台原发布日期仍优先，导入日期回退标为“导入于”。只说明现有日期来源，不更改日期映射或来源排序。
- 抖音专用页及首页继续沿用服务端当前分类的可靠快照与排名；缓存仍按账号、分类、排序隔离。同步失败保留既有资料，成功同步不会用小批次替换全部历史。
- 收藏台账校准随网页发布一次性失效旧来源快照：抖音列表缓存从 v4 提升到 v5，包含来源预览的首页会话缓存从 v7 提升到 v8，避免网络响应前闪回旧错误排名。跨平台列表缓存仍为 v2；既有网络刷新及同账号部分失败回退机制保持不变。
