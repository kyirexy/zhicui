# 同步健壮性复查（2026-09-09）

## 范围与发现

在已发布的 1.1.3 与网页提交 dba99096 基础上，复查原生分页、后台增量台账、前端缓存和异常期间的操作。没有按视频发布时间重排数据，也没有重放此前的生产收藏修复。

发现并补强三个可复现边界：

1. 老客户端开着旧网页时，仍可向接口声称其顺序可靠。服务端需要在创建同步记录和推进时间水位之前校验客户端能力；仅网页按钮禁用不足以保护已校准排名。
2. 长采集期间已隐藏的作品，在权威刷新后仍可能被同步前基线的数组合并重新带回界面。资料库现在直接采纳后端完整列表；历史成员的增量保留由后台负责，空列表也不回填旧项。隐藏和恢复结束后统一失效首页与分类缓存，失败或断网也通过只读刷新确认最终可见范围。
3. 本人官方列表采集期间，若用户导航到其他主页，原来的监听可能继续接收另一账号列表。原生采集固定本次本人主页上下文；离开或账号变化则终止并丢弃整轮，避免跨账号导入。

新原生版本为 1.1.4，网页与服务端可靠顺序写入门槛保持一致。未知或过旧客户端只能沿用不可靠元数据导入的兼容路径，不能改写可靠排名。

## 验证原则

- 离线用实际采集控制流注入乱序、缺页、异常响应、取消、账号导航，以及同步期间隐藏操作；不以字符串检查代替行为复现。
- 后端测试使用临时 SQLite，不修改生产资料；生产 PostgreSQL 的锁顺序另作源码审查，不能把 SQLite 验证表述为真实多进程压力测试。
- 原生修复发布前再次验证本人官方页面正常采集，采集证据留在本地受控目录，不上传私人列表、不触发文稿任务。
- 网站发布通过既有 Jenkins 备份、构建、原子切换和线上验收；安装包使用锁定提交构建与哈希验证。
