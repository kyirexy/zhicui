## Context

知萃已经能在“视频资料”页逐条导入 B 站和小红书链接，也已经有一套抖音桌面端本机浏览器登录回传模式。B 站登录态接口可以读取账号收藏夹与点赞视频；小红书没有稳定公开的收藏接口，XHS-Downloader 的收藏/点赞能力也依赖已登录浏览器页面中的可见链接。项目的资料页本身已经限制在 Windows 桌面端或 Android App，因此首版把账号同步定位为 Windows 桌面能力，Android 保留链接导入。

## Goals / Non-Goals

**Goals:**

- 用户可以在知萃中发起 B 站或小红书登录，并在官方页面完成验证。
- 按当前知萃用户和平台隔离本机浏览器资料目录，登录态不上传服务器。
- B 站自动读取最近 10 条喜欢或收藏链接；小红书在用户打开自己的个人主页后读取最近 10 条可见喜欢或收藏链接。
- 将结果交给现有 `/api/library/imports`，沿用用户隔离、幂等、文案提取与逐条反馈。
- 支持取消、重新登录和断开连接，并提供清晰中文状态。

**Non-Goals:**

- 不在服务器或应用数据库保存 B 站、小红书 Cookie。
- 不绕过验证码、访问控制、私密内容或平台风控。
- 不保证同步账号的全部历史内容；首版只处理最近 10 条可见内容。
- 不在 Android 上读取其他 App 或系统浏览器 Cookie。
- 不替换现有单链接导入。

## Decisions

### 1. 登录态只保存在桌面端持久化 Playwright profile

桌面主进程使用 `app.getPath('userData')/platform-sessions/` 下的持久化浏览器目录。目录名由经过严格格式校验的知萃用户标识做 SHA-256 派生，再按平台分区。Chrome/Edge 浏览器直接打开平台官网，用户在官方页面完成登录。

选择本机会话而不是服务端 Cookie 表，是为了避免新增高价值凭据存储、数据库泄漏面和跨设备会话复制。替代方案是在后端 Fernet 加密 Cookie，但即使加密仍会把第三方账号会话上传服务器，因此不采用。

### 2. Electron bridge 使用窄类型请求并发布进度事件

新增 `loginPlatformAccount`、`collectPlatformAccount`、`disconnectPlatformAccount` 和 `cancelPlatformAccountAction`。请求只接受固定平台、固定来源模式、1–10 数量及受限用户标识；返回结果只包含作品 URL、计数和安全错误。状态通过单一 `onPlatformAccountStatus` 事件发送，渲染进程不接触 Cookie。

### 3. B 站使用登录浏览器共享 Cookie 的账号接口

登录成功以 `SESSDATA`/`DedeUserID` 等账号 Cookie 为判断。同步时先调用导航接口得到当前 UID：收藏模式读取收藏夹和资源分页，喜欢模式读取空间点赞视频分页。所有响应在桌面主进程规范化为 `https://www.bilibili.com/video/<bvid>`，去重并限制为最近 10 条。

相较于页面 DOM 抓取，接口响应更稳定且不依赖页面布局；接口异常时返回可操作错误，不降级为其他账号或公共数据。

### 4. 小红书使用用户可见页面的引导式采集

小红书同步打开已登录的官方页面，提示用户进入自己的个人主页。连接器等待 `/user/profile/` 页面，选择“收藏”或“点赞”标签，有限次数滚动并收集带 `xsec_token` 的 `/explore/` 或作品详情链接。只读取页面已呈现内容，不调用未公开的破解接口。

该方案与 XHS-Downloader 用户脚本的“可见即可得”边界一致。自动滚动次数和结果数有硬上限，并在 UI 标记 Beta 与风控提示。

### 5. 复用现有导入 API

桌面连接器返回链接后，前端调用现有 `importPlatformLibraryItems`。首版结果上限与 API 的 10 条限制一致，因此无需新增后端会话、任务表或 Cookie 迁移。重复作品继续由现有 `(user_id, platform, video_id)` 幂等逻辑复用。

### 6. 账号同步界面按连接状态渐进呈现

账号卡在未连接时只呈现“登录并连接”这一项主操作；连接成功后才呈现“同步收藏”和“同步喜欢”，重新登录与断开连接降为文字级管理操作。每个平台的进度、错误和成功反馈固定显示在对应卡片内，避免用户在全局消息中寻找操作结果。

手动链接导入保留为备用能力：支持账号同步的桌面环境默认折叠，在普通网页、Android 或旧客户端默认展开。断开连接使用带标题、后果说明和显式取消按钮的模态确认，而不是浏览器原生确认框。这样可以建立“连接账号 → 选择来源 → 查看结果”的清晰主路径，同时确保键盘焦点、状态播报和窄屏触控可用。

## Risks / Trade-offs

- [小红书页面结构变化导致选择器失效] → 使用多组文本/链接选择器、限定等待时间，并保留单链接导入。
- [自动滚动触发平台风控] → 默认仅同步最近 10 条、限制滚动次数、显示 Beta 风险提示，不绕过验证。
- [平台 Cookie 过期] → 每次同步前验证登录态，失败时要求重新登录。
- [多个知萃用户共用电脑] → 本地 profile 由用户标识哈希后隔离，退出连接只删除当前用户当前平台目录。
- [单批导入包含 ASR 耗时较长] → UI 持续显示逐条导入状态，首版限制为 10 条；后续可改为元数据优先后台准备文案。
- [Chrome/Edge 未安装] → 沿用现有桌面登录的浏览器探测错误，并继续允许链接导入。

## Migration Plan

1. 扩展桌面 contract、preload、main IPC 和安全校验。
2. 加入本机平台会话连接器，不修改数据库。
3. 扩展前端运行时类型与视频资料账号同步 UI。
4. 先以桌面版本发布；旧桌面客户端因 bridge 缺失自动看到“需要更新桌面端”，链接导入不受影响。
5. 回滚时移除新 IPC/UI 即可；本机 profile 可由用户断开连接删除，也不会影响服务端资料。

## Open Questions

- 后续是否把账号同步扩展到 50/100 条并改为元数据优先的后台队列。
- Android 是否采用用户主动导出/分享链接的替代流程，而不是尝试读取系统浏览器会话。
