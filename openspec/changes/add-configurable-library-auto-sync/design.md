## Context

视频库已经有完整的手动流程：启动抖音采集任务、轮询任务状态、刷新资料列表、筛选未提取条目并启动批量文案任务。该编排目前只存在于视频库页面组件中，设置和全局应用壳无法复用。用户设置已由 `SettingsContext` 持久化到当前设备。

## Goals / Non-Goals

**Goals:**

- 用户可在设置中用一个周期选项启用或关闭自动同步。
- 应用运行期间，即使用户不在视频库页面，也可按期完成收藏同步并提前启动文案准备。
- 自动任务与自身、其他标签页和即时执行互斥。
- 设置页展示上次结果与下次运行时间，并可即时执行。

**Non-Goals:**

- 不注册 Windows 计划任务，不承诺应用完全退出后仍能运行。
- 不新增后端定时任务、数据库设置或同步 API。
- 不自动生成知识卡、摘要或计划，只准备可直接提问的完整文案。
- 本次固定同步最近 50 条收藏，不增加来源和数量配置，避免设置复杂化。

## Decisions

1. **调度器放在全局 React Provider 树中。** 它可以直接复用当前 JWT、设置与现有 API，并在任意页面运行。Electron 主进程没有认证上下文，因此不在主进程复制网络逻辑。
2. **周期使用离散枚举。** 提供关闭、30 分钟、1/3/6/24 小时，避免任意小间隔造成接口滥用，也比同时暴露来源、数量和并发更符合 C 端设置。
3. **抽取通用编排模块。** 新模块负责状态检查、采集任务轮询、资料刷新和批量文案任务启动；设置页的“立即同步”和后台调度器调用同一入口。
4. **设备状态按用户持久化。** 保存最后尝试、最后成功、结果、下次计划与运行锁；退出或切换账号不会继承其他用户的计划状态。
5. **使用带过期时间的 `localStorage` 运行锁。** 同一浏览器多个标签页只允许一个任务运行；锁在最长 30 分钟后自动失效，崩溃不会永久卡住。
6. **网络恢复与可见性变化触发到期检查。** 不追求秒级准点；应用从休眠或离线恢复后，若已到期则立即补跑一次。

## Risks / Trade-offs

- **[后台标签页定时器被浏览器节流]** → 在 `visibilitychange`、`online` 和固定一分钟检查时重新判断到期时间。
- **[采集或文案任务耗时超过一个周期]** → 全局运行锁和模块级 Promise 合并并发请求，完成前不启动下一轮。
- **[抖音登录失效]** → 记录“需要重新连接抖音”而不是持续高频重试，下一个周期再检查。
- **[用户误以为关闭应用仍会同步]** → 设置页明确写明“知萃运行期间”。
- **[即时同步和视频库手动同步碰撞]** → 自动调度使用设备锁；后端现有任务接口继续作为最终安全边界，设置页显示忙碌状态。

## Migration Plan

新增设置字段默认值为 `0`（关闭），旧用户不会自动产生后台请求。状态键与锁键均使用独立版本前缀；回滚后无人读取，不影响现有同步。

## Open Questions

无。若未来需要应用退出后仍执行，应新增服务端持久化调度或 Windows 原生后台任务，而不是延长前端定时器。
