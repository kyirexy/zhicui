## Context

知萃已经把视频/文章转录原文与结构化卡片保存在 `notes` 表中，但结果页只支持阅读、切换样式和导出。后端已有统一的运行时 LLM 配置解析与 `_call_llm` 调用入口，前端三个主要结果入口都经过 `CardRenderer`，适合在不改变提取管线和数据模型的前提下增加内容追问。现有样式系统以 `CardStyle` 联合类型和组件映射扩展，六个布局已经共用密度、导出引用和 GSAP 生命周期。

## Goals / Non-Goals

**Goals:**

- 让登录用户可以在卡片生成后围绕当前笔记继续提问，并确保服务端重新校验笔记所有权。
- 让回答优先引用转录和摘要信息，找不到依据时明确说明，而不是补造事实。
- 在首页结果、处理页和笔记详情页复用同一套响应式聊天组件。
- 将风格系统无破坏地扩展到九套布局，并让用户在选择前看见可辨识的视觉预览。
- 用 Phosphor duotone 图标和已有 GSAP/CSS 动效提升质感，同时尊重减少动态效果设置。

**Non-Goals:**

- 不持久化聊天记录，不新增会话表、消息表或数据库迁移。
- 不实现跨笔记知识库、联网搜索或引用视频时间戳。
- 不重写现有六套卡片，也不更换 Tailwind、React 或动画框架。
- 不改变提取、ASR、计划生成和 PNG 导出的既有流程。

## Decisions

1. **采用用户范围的无状态问答端点。** 新增 `POST /api/notes/{note_id}/ask`，请求携带当前问题和最近有限轮次历史；服务端通过 `note_service.get_note(..., user_id=current_user.id)` 获取上下文。相比新增持久化会话模型，这能更快交付且没有隐私与迁移负担。历史仅作为连贯性辅助，笔记内容始终是事实来源。

2. **在 `ai_juicer` 中封装内容问答。** 新函数复用 `_call_llm` 和后台热更新配置，将标题、结构化摘要、截断后的转录原文和最近对话组合为提示。问题限制 600 字，历史限制最近 6 条，转录按字符预算截断，回答温度保持较低；提示要求“没有依据时明确说原内容未提及”。相比在路由里直接拼接 LiteLLM 调用，这保持配置和降级逻辑集中。

3. **聊天首版保持页面会话态。** `ContentChat` 在浏览器内维护消息列表，提供推荐问题、发送/重试/清空、加载骨架和内联错误。组件由 `CardRenderer` 在存在 `noteId` 时挂载，因此三个结果入口自动获得能力。刷新后历史清空，符合本次非持久化范围。

4. **卡片系统按现有联合类型扩展。** 新增 `aurora`、`blueprint`、`paper` 三个独立组件，继续接受 `StyleCardProps` 并把 `cardRef` 放在可导出的根容器上。旧设置值和六套布局保持兼容，不做默认风格迁移。

5. **选择器展示“视觉样本”而不是只有名称。** 新建可复用的 `StylePreview`/`StyleIcon` 表达层，桌面工具栏、移动底部抽屉和独立风格页共用。预览通过 CSS 变量和小型几何结构表达布局，不渲染整张业务卡片，避免列表中同时运行九套 GSAP 动画。

6. **只增加一个图标依赖。** 引入 `@phosphor-icons/react` 的 duotone 图标；图标位移、旋转和呼吸使用 transform/opacity CSS，卡片内部继续复用 GSAP。相比 Lordicon/Lottie，这不需要远程 JSON 资产，也更适合静态导出和 Capacitor。

7. **动效和响应式是组件契约的一部分。** 所有交互保持至少 44px 触摸目标、可见焦点、`aria-pressed`/`aria-live`，动画在 `prefers-reduced-motion: reduce` 下禁用。移动端选择器采用横向可滚动预览或两列网格，避免九项压成难读的小胶囊。

## Risks / Trade-offs

- **[长转录导致请求昂贵或超过模型上下文]** → 设置明确字符预算，优先保留摘要并截取转录，限制历史和回答长度。
- **[LLM 仍可能产生超出原文的结论]** → 系统提示要求基于来源、缺失即说明；界面标注“基于当前内容回答”，不包装为事实搜索。
- **[三个新布局增加前端包与维护面]** → 共用内容格式化、类型配置和 CSS token；不引入新的动画运行时。
- **[问答端点被高频调用产生费用]** → 限制输入和历史，发送期间禁用重复提交；首版不增加全局限流基础设施。
- **[现有工作区有未提交改动]** → 只做增量补丁，保留当前 routes、ai_juicer、notes 与 api 文件中的用户改动，并在最终差异中核对。

## Migration Plan

1. 安装并锁定 `@phosphor-icons/react`。
2. 先部署后端问答端点，再部署兼容旧后端错误处理的前端组件。
3. 构建 Next.js 网页版本并执行后端导入/语法检查；本地启动后验证健康端点和页面。
4. 回滚时移除 `ContentChat` 挂载、问答路由/函数和新增三套映射即可；数据库无需回滚。

## Open Questions

首版无阻塞问题。聊天持久化、跨笔记搜索、精确时间戳引用和用量配额作为后续独立变更评估。
