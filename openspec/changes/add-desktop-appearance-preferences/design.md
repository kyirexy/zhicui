## Context

桌面端由云端或本地 Next.js 页面与 Electron preload bridge 共同组成。当前侧栏颜色、宽度和内容间距全部写死在 `globals.css`，设置页只有版本与连接信息；`SettingsContext` 已使用 localStorage 保存卡片样式和密度，可扩展为桌面外观设置。桌面应用和网页共享静态资源，但 Electron Builder 当前直接复用旧 favicon 作为 Windows 图标。

## Goals / Non-Goals

**Goals:**

- 默认提供更明亮的桌面侧栏，同时保留深色和跟随系统选项。
- 允许用户选择舒展或紧凑布局，并即时看到结果。
- 外观偏好在本机持久化，在本地开发地址和云端地址上使用同一实现。
- 统一桌面品牌入口、浏览器 favicon、窗口图标和安装包图标。
- 保持普通网页与 Android 现有导航和布局不变。

**Non-Goals:**

- 不把外观偏好写入用户数据库或跨设备同步。
- 不新增任意颜色选择器、可拖动侧栏或复杂布局编辑器。
- 不改变知识卡样式选择、业务 API 或抖音连接架构。

## Decisions

1. **扩展现有 `UserSettings`，不创建第二套桌面设置仓库。** 新增 `desktopSidebar` 与 `desktopDensity` 字段，并提供带默认值的兼容合并。这样旧 localStorage 数据会自动补齐新字段，重置设置也只走一个入口。

2. **通过根节点数据属性应用外观。** `SettingsProvider` 将偏好写入 `html[data-desktop-sidebar]` 和 `html[data-desktop-density]`。桌面 CSS 继续要求 `data-desktop-app="true"`，因此普通网页和 Android 即使保存了同样的偏好也不会改变导航结构。

3. **浅色侧栏作为新默认值。** 用户明确反馈固定深色侧栏过暗。浅色模式使用与画布相邻但可区分的冷灰绿色；深色模式保留当前高对比方案；跟随系统根据现有 `data-theme` 解析，而不是新增媒体查询状态源。

4. **设置页使用标准分段选择。** “侧栏外观”和“布局密度”各使用一个可键盘操作的单选组，包含清晰名称和一句结果说明。选择立即生效，不增加保存按钮或模态框。

5. **使用单一品牌母版生成图标。** 左上角品牌标记使用现有叶片播放符号；浏览器与 Windows 图标从同一高分辨率方形资源派生。Electron 窗口显式设置图标，Builder 继续使用多尺寸 ICO。

## Risks / Trade-offs

- **[旧设置对象缺少新字段]** → 读取 localStorage 时与默认设置做浅合并，并对非法枚举值回退。
- **[首帧先显示默认侧栏再切换]** → 在桌面运行时初始化脚本中同步读取轻量偏好，React 挂载后再校准。
- **[浅色侧栏在暗色主题下对比不协调]** → “跟随系统”随主题切换；用户显式选择浅色时保持选择，但文本和边界使用独立可访问令牌。
- **[Windows 图标缓存导致旧图标暂留]** → 新版本安装包提升版本号，验证 `win-unpacked` 和安装器图标；Windows 缓存属于系统行为，不通过运行时绕过。

## Migration Plan

1. 上线兼容旧 localStorage 的前端字段和根属性。
2. 更新图标资源与 Electron 版本，构建新的 Windows 安装包。
3. 本地验证三种侧栏外观、两种密度和应用重启后的持久化。
4. 云端部署只需发布同一前端代码；回滚时旧客户端会忽略新增设置字段。

## Open Questions

无。首版保持设备级偏好，后续若需要跨设备同步再新增用户设置 API。
