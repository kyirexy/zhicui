## Context

知萃 Windows 客户端通过 Electron 加载可信的知萃 Web 页面。视频库返回短时签名的同源媒体和封面代理地址，但桌面首页与视频详情仍有部分位置直接使用原始抖音封面地址；视频失败后也只能跳回抖音。Electron 当前只提供扫码登录和更新能力，没有媒体缓存、目录选择或安全的本地媒体读取协议。

服务器必须继续只保存视频元数据、文稿、知识卡和计划，不能因为桌面端缓存能力而把视频二进制写入数据库或服务器持久目录。

## Goals / Non-Goals

**Goals:**

- 所有桌面视频入口优先使用同源封面代理，并提供一致的加载、失败和重试状态。
- 允许用户在设置中决定是否自动保存播放过的视频，并选择本机保存目录。
- 支持单条视频手动保存、查看进度、播放本地副本、打开文件夹和删除本地副本。
- 让本地视频可由 `<video>` 原生控件稳定播放和拖动进度，同时不向渲染进程暴露任意文件读取能力。
- 保持 Web、Android、服务器和数据库的现有远程媒体策略。

**Non-Goals:**

- 不把桌面端变成通用下载器或文件管理器。
- 不自动下载用户资料库中的全部视频。
- 不在服务器同步桌面缓存状态或备份本地文件。
- 不为本轮增加转码、清晰度选择、云盘同步或跨设备缓存迁移。

## Decisions

### 1. 本地媒体能力只存在于 Electron 主进程

设置、目录选择、下载、索引维护、删除和打开文件夹均通过受限 IPC 完成。Web 渲染层只能提交视频 ID、标题和当前 API 返回的签名媒体地址，不能提交任意目标路径，也不能直接调用 Node 文件系统。

选择这一方案而不是浏览器 File System Access API，是因为 Electron 主进程能提供稳定的 Windows 目录选择、后台写入和原生文件操作，同时 Web 和 Android 不会获得不可用的桌面控件。

### 2. 默认远程按需播放，可选“播放时自动保存”

本地保存默认关闭。用户开启后，第一次播放仍立即使用远程流，同时在后台把视频和封面原子写入所选目录；下载完成后，后续打开优先使用本地副本。视频详情始终提供单条“保存到本地”操作，让用户无需开启自动模式也能主动保存。

不采用“同步后自动下载全部视频”，避免一次同步 50–100 条时占满磁盘、带宽和抖音连接器资源。

### 3. 使用受限自定义协议播放本地文件

Electron 注册 `zhicui-media://` 协议。协议仅接受已存在于桌面媒体索引中的视频 ID和资源类型，并由主进程解析真实路径。视频响应支持 `Range`，从而保留原生播放器的拖动、暂停和继续播放能力。

不直接向页面返回 `file://` 路径，因为 HTTPS 页面访问本地文件会遇到来源隔离问题，并会泄露用户目录结构。

### 4. 设置和索引存储在 Electron 用户数据目录

媒体设置与缓存索引写入 `app.getPath('userData')`，实际媒体默认写入系统“视频/知萃”目录。用户切换目录只影响后续保存，已保存文件继续保留并可通过索引播放或删除。

下载使用同目录 `.part` 临时文件并在成功后重命名，防止中断后留下看似完整的损坏视频。

### 5. 只信任知萃媒体路由

主进程把相对 URL 解析到当前可信知萃来源，并只允许：

- `/api/library/douyin/media/{aweme_id}`
- `/api/library/douyin/cover/{aweme_id}`

URL 中的视频 ID必须与 IPC 请求中的 ID一致。下载不接受用户自定义主机、`file://`、重定向到非可信来源或任意 API 路径。

### 6. 封面统一走代理并具备渐进失败体验

资料库、桌面工作台与视频详情统一使用 `cover_proxy_url || cover_url`。封面组件显示与卡片比例一致的骨架，加载失败后显示简洁占位和“重试”，而不是浏览器损坏图片图标或替代文本。

## Risks / Trade-offs

- **[抖音签名或媒体流在下载中失效]** → 使用当前详情 API新生成的签名地址；失败时删除 `.part` 并允许重新获取页面数据后重试。
- **[大文件占用磁盘]** → 默认关闭自动保存；下载前检查可用空间；界面展示文件大小并提供删除本地副本。
- **[用户切换目录后索引跨目录]** → 索引记录绝对路径，切换只影响新文件；设置页明确说明不会自动移动旧文件。
- **[本地协议被滥用读取任意文件]** → 协议只通过索引和视频 ID查找，不接受文件路径；IPC 校验发送页面和媒体 URL。
- **[远程播放和后台保存重复消耗带宽]** → 自动保存仅在用户主动播放时触发，并对同一视频去重；已在下载或已缓存时不重复请求。

## Migration Plan

1. 发布包含新 IPC 合约和媒体管理器的桌面版本。
2. 前端运行时先检测桥接方法是否存在；旧桌面版本只显示远程播放器，不展示本地媒体设置。
3. 首次启动创建默认设置和空索引，不扫描或移动用户已有文件。
4. 若新能力出现问题，可回滚前端控件和桌面版本；本地视频是普通文件，不影响云端资料和数据库。

## Open Questions

无。默认策略确定为“远程播放 + 用户可选播放时自动保存”，不自动下载整个资料库。
