## Context

视频资料页已有 `Set<aweme_id>` 作为唯一选择状态，AI 来源面板已有 `Set<note_id>`，但两处目前都只能逐项点击。资料库的卡片详情链接覆盖整卡，AI 来源又会把已选项即时移到顶部；直接在 `pointermove` 中逐项触发现有切换函数会造成误跳转、重复反选和来源列表重排。

这项能力只面向桌面鼠标。原有复选框和键盘路径继续承担可访问选择，移动端仍使用原生触屏滚动。

## Goals / Non-Goals

**Goals:**

- 在视频资料网格/列表和 AI 来源列表中提供一致的鼠标框选。
- 普通拖动替换选择，Ctrl/Cmd 拖动追加选择，并遵守各自 50/100 条上限。
- 形成选区后抑制同一次手势的合成点击，保留未形成拖动时的正常点击。
- 让拖动预览与最终选择使用同一组 ID，最终仍写入现有选择 Set。
- 在取消、失焦、滚动、加载或处理锁定时完整清理手势。

**Non-Goals:**

- 不增加触摸或触控笔框选，不改变移动端滚动。
- 不增加边缘自动滚动、Shift 范围选择或套索多边形选择。
- 不为尚未支持统一批量处理的 B站/小红书资料伪造选择能力。
- 不改变批量提取、文案持久化、Note ID 解析或 Agent 提问 API。

## Decisions

### 1. 使用共享 pointer 手势 hook，并只提交现有选择 Set

共享 hook 负责阈值、矩形计算、DOM 命中、上限、取消和清理。调用方只提供容器、当前 ID 集合和最终 `onSelectionChange`，因此框选不会产生第二套业务选择状态。

备选方案是分别在两个页面实现 mouse 事件；这会重复复杂的点击抑制和取消逻辑，也更容易让两处语义漂移。

### 2. 拖动中使用内部候选预览，pointerup 时原子提交

hook 在拖动中维护候选 Set，页面可用它显示选中样式，但业务 Set 只在 pointerup 更新一次。这样 AI 来源的“已选在上”分组不会在拖动过程中不断重排，命中矩形也不会因 DOM 跳动失真。

### 3. 以视口坐标计算并将视觉层 portal 到 body

选区和资料项均使用 `getBoundingClientRect()`。选区被裁切到选择容器的可见边界，来源面板中的滚动外项目不会被误选。视觉层通过 portal 放到 `document.body`，避免响应式面板的 transform 改写 fixed 坐标系。

### 4. 只响应主鼠标按钮并采用 6px 激活阈值

`pointerType === 'mouse' && button === 0` 才建立候选手势；移动未超过阈值时不阻止默认行为。超过阈值后临时关闭文字选择、显示选区，并在结束后吞掉紧随其后的合成 click。按钮、输入框、播放链接等交互控件不能作为框选起点；资料卡的整卡详情链接是特例，允许起拖但仅在未形成拖动时导航。

### 5. 手势开始时快照可见资料矩形

达到阈值时按 DOM 顺序快照 `data-marquee-id` 项及其可见矩形。普通拖动从空 Set 开始，Ctrl/Cmd 拖动从 pointerdown 时的 Set 开始，并在剩余容量内按 DOM 顺序加入命中项。来源列表因此不会受最终分组重排影响。

### 6. 任何滚动或上下文失效都取消本次框选

首版不做边缘自动滚动。手势中发生文档/容器滚动、窗口失焦、pointercancel、Escape、来源加载或批处理锁定时，候选预览被丢弃，业务选择保持 pointerdown 前状态。

## Risks / Trade-offs

- [长列表拖动时读取 DOM 矩形可能有成本] → 只在越过阈值时读取一次，来源列表最多 100 条，后续 move 只做内存矩形相交。
- [框选与整卡链接或 label 合成点击冲突] → 使用阈值和一次性 capture click 抑制，普通点击不调用 `preventDefault`。
- [滚动后快照坐标失效] → 首版在任意滚动发生时取消手势，避免提交错误 ID。
- [用户希望拖动越过边缘继续选择] → 当前明确只选择可见范围；后续可在独立变更中增加边缘自动滚动。
- [AI 来源候选预览与“已选在上”分组暂时不同步] → 拖动中只更新行的选中视觉，释放后一次性重排，保证空间稳定。

## Migration Plan

这是纯前端增量能力，无数据迁移。部署后旧的点击和键盘选择继续可用；回滚只需移除共享 hook、视觉层和两个容器的事件接线。

## Open Questions

无。边缘自动滚动与 Shift 范围选择明确留待后续需求。
