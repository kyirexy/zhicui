## Context

桌面端已有本地媒体索引、目录设置、原子写入和下载进度，但单条保存直接使用设置中的默认目录。下载目前调用 Node 全局 `fetch`，截图中的崩溃来自 Electron 所带 Node/undici 在响应结束阶段触发的内部断言。视频二进制仍必须只写入用户电脑，不能进入知萃服务器或数据库。

## Goals / Non-Goals

**Goals:**

- 每次点击“下载视频”都先让用户选择目标文件夹。
- 用户取消目录选择时保持页面和文件系统不变。
- 下载期间持续展示进度，完成后可打开文件位置。
- 消除 Node/undici 下载流导致 Electron 主进程崩溃的路径。
- 保留现有自动保存、媒体索引和本地优先播放能力。

**Non-Goals:**

- 不增加批量下载、清晰度选择、转码或断点续传。
- 不允许渲染进程提交任意文件路径。
- 不向 Web 或 Android 暴露本地文件系统能力。

## Decisions

### 1. 新增“选择目录并下载”的单次 IPC

Electron 主进程负责打开原生目录选择器，并只把取消状态、下载状态和安全的展示信息返回页面。渲染层不能传入目标路径。选择成功后，该目录用于本次下载，并保存为后续默认目录。

不采用“前端先调用选择目录，再调用保存”的两步流程，因为旧接口无法可靠区分“用户取消”和“用户重新选择了相同目录”，会导致取消后仍开始下载。

### 2. 使用 Electron `net.fetch` 读取媒体

下载请求改用 Electron 的 Chromium 网络栈 `net.fetch`，继续复用现有内容类型校验、可信 URL 校验、磁盘空间检查、进度统计和 `.part` 原子重命名。

不继续使用 Node 全局 `fetch`，因为当前 Electron 运行时的 undici 在视频流尾部可能触发不可捕获的主进程断言。也不引入第三方下载依赖，避免扩大包体和维护面。

### 3. 保持现有媒体索引语义

下载完成后仍写入桌面媒体索引，并通过 `zhicui-media://` 播放本地副本。已缓存的视频显示“打开位置”和删除操作，不重复下载。

### 4. 旧桌面版本降级

前端检测新的 `downloadMedia` 桥接方法。新方法可用时展示“下载视频”并打开目录选择器；旧版本继续保留现有“保存到本地”行为，避免整个播放器失效。

## Risks / Trade-offs

- **[Electron 网络栈返回的流类型与 Node 不同]** → 继续使用标准 Web `ReadableStream` 到 Node 流的适配，并通过桌面 TypeScript 与真实下载验证。
- **[下载中目标磁盘被移除或空间耗尽]** → 删除 `.part` 文件，返回局部错误状态，不退出主进程。
- **[用户选择新目录后已有缓存仍在旧目录]** → 索引继续记录每个文件的绝对路径，只影响本次和后续下载。
- **[旧客户端没有新 IPC]** → 前端特性检测并使用旧保存入口，不调用不存在的方法。

## Migration Plan

1. 发布包含新 IPC 和 Electron 网络栈下载实现的桌面版本。
2. 前端通过方法存在性自动启用目录选择下载。
3. 无需迁移数据库或旧媒体文件；旧索引继续有效。
4. 回滚时可恢复旧前端按钮，新下载文件仍是普通本地视频。
