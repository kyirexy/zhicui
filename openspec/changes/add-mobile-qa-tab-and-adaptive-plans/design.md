## Context

结果工作台已经使用“知识卡片 / 完整内容”页签，`ContentChat` 作为 `CardRenderer` 的右侧兄弟节点常驻；在小于桌面断点时布局变为单列，因此问答被排到卡片和全文之后。计划数据存于 `plans.fields`、`plans.tasks` 和 `plans.days_json` 三个 JSON 字段，现有结构允许附加属性，但 AI prompt、请求校验和前端类型只覆盖连续天数、日期、优先级和少量固定字段类型。

本次改动跨越响应式 React 状态、计划生成 prompt、FastAPI 请求模型、计划 service 规范化、共享类型与计划工作台展示。约束是继续兼容 Next.js 静态导出、SQLite/PostgreSQL、已有计划 JSON 和当前 API envelope，不新增数据库列或第三方依赖。

## Goals / Non-Goals

**Goals:**

- 移动端通过三个明确页签访问知识卡片、完整内容和基于全文的 AI 问答。
- 桌面端继续让 AI 问答常驻右侧，页签切换或断点变化不清空对话。
- AI 根据视频实际内容决定计划字段数量、字段分组、执行阶段、任务数量和排期粒度。
- 任务可以表达具体日期时间、预计时长、频率和 AI 自定义执行细节。
- 用户可在现有任务编辑器中调整日期时间、时长和频率。
- 旧日期字符串与旧计划数据继续正常展示、统计和编辑。

**Non-Goals:**

- 不实现系统通知、定时推送、日历同步或重复任务自动实例化。
- 不把计划任务迁移为独立数据库表。
- 不允许 AI 生成任意 HTML、组件或可执行表达式。
- 不为每一种业务计划建立固定字段模板。

## Decisions

1. **移动端增加第三个页签，但只挂载一份 `ContentChat`。**
   - `WorkspaceTab` 扩展为 `card | source | assistant`，移动端页签包含三项，桌面端隐藏第三项。
   - 使用现有响应式 hook 派生当前可见面板；从移动端 AI 页签切到桌面时，左侧回落为知识卡片，右侧仍展示同一份问答组件。
   - `ContentChat` 始终挂载，只通过响应式可见状态控制布局，避免重复请求、消息清空和两个聊天实例状态分叉。

2. **继续使用 JSON 扩展计划，而不是迁移数据库。**
   - 计划字段增加可选 `group`，任务增加可选 `scheduled_at` 日期时间、`duration_minutes`、`frequency` 和 `details`。
   - `details` 复用动态字段的 `{name,label,type,value}` 结构，使 AI 能表达“3 次”“30 分钟”“在家完成”“完成标准”等未知但安全的元数据。
   - 未识别字段类型由前端降级为文本或键值展示，不执行任何动态代码。

3. **排期字符串兼容日期与本地日期时间。**
   - API 接受 `YYYY-MM-DD` 或 `YYYY-MM-DDTHH:MM`，service 规范化并保留到分钟。
   - 今日/逾期判断继续比较前 10 位日期，排序直接使用 ISO 字符串，因此旧日期和新日期时间可以共存。
   - 前端使用 `datetime-local` 编辑，不引入时区转换；产品本地开发与主要用户语境按北京时间解释。

4. **AI 决定结构，应用只做安全边界和兼容规范化。**
   - prompt 移除“至少 3 个字段”“每天连续编号”“每天固定任务数”等模板限制。
   - AI 可以使用非连续计划日表示关键节点，也可以按视频明确时间生成日期时间；没有依据时保留相对日程，不虚构绝对日期。
   - 对真实计划仍要求至少一个可执行任务，避免产生只有描述没有行动的空计划。
   - 规范化补齐任务 ID、完成状态、所属日和默认优先级，但不裁剪 AI 提供的安全扩展字段。

5. **计划工作台按 AI 分组展示动态字段，并把细节放在任务附近。**
   - `field.group` 相同的字段组成语义区块；无分组字段进入“计划信息”。
   - 日期时间、时长、频率作为任务元信息直接显示，`details` 以紧凑键值形式显示，避免用户在右侧字段与左侧任务之间来回核对。
   - 任务编辑器增加可选时间、时长和频率，未填写即不保存。

## Risks / Trade-offs

- [AI 输出字段过多导致页面变长] → 保留 AI 自主数量，但前端使用分组和紧凑布局；规范化仅接受结构合法的字段。
- [移动端隐藏聊天后请求仍在进行] → 聊天保持挂载让请求可以完成，切回页签可直接看到结果。
- [日期时间没有时区后缀] → 明确按产品北京时间语境解释，并继续使用本地 `datetime-local`，避免客户端重复换算。
- [非连续计划日使“今天第几天”没有任务] → 今日卡片显示明确空状态，执行清单仍展示 AI 选择的关键节点。
- [旧任务没有扩展字段] → 所有新增字段均可选，旧数据渲染路径保持不变。

## Migration Plan

1. 扩展移动端页签状态、响应式可见规则和无障碍关系。
2. 更新计划生成 prompt 与计划规范化，保留 AI 自主字段和任务细节。
3. 扩展请求模型、service、TypeScript 类型和 API payload。
4. 更新计划详情、任务列表、编辑器和动态字段分组。
5. 运行 Python 定向验证、TypeScript、生产构建和严格 OpenSpec 校验后重启开发服务。

回滚时移除新增 UI 和请求字段即可；已写入 JSON 的附加属性会被旧代码忽略，不需要数据库回滚。
