## Context

首页已有两个 `/library?sync=1` 入口，资料库也已有抖音多来源同步弹窗和来源/数量本地存储，但当前查询参数会无条件打开弹窗，另一段依赖未写入的 sessionStorage 标记的直接同步逻辑无法生效。设置页已有“同步与问答”分类，适合承载快捷同步偏好。

## Goals / Non-Goals

**Goals:**

- 用同一个 `sync=1` 意图同时支持首次配置和后续直接执行。
- 将来源与数量封装为可校验、可复用的本地偏好。
- 设置页可修改偏好，并明确控制是否启用“一键直接同步”。
- 保持现有账号登录、弹窗、同步队列和错误反馈不变。

**Non-Goals:**

- 不把本地偏好同步到服务器或跨设备共享。
- 不绕过抖音登录状态，也不自动操作需要官方页面确认的 B站/小红书账号。
- 不修改定时自动同步策略。

## Decisions

1. 新增共享的 `libraryQuickSync` 模块，统一负责偏好校验、读取、保存、重置和变更事件。保留现有 localStorage key，以兼容已经选过来源/数量的用户；另加显式 `configured` 标记，避免仅有旧默认值就被视为用户已确认。
2. 首页继续使用 `/library?sync=1`。资料库消费并立即移除该查询参数，防止刷新或 React 重渲染重复执行。
3. 若未配置，资料库调用现有原生 `<dialog>`；若已配置，则等待资料库账号状态加载完成后调用现有顺序同步函数。账号未连接时回退到弹窗，让用户完成登录，而不是静默失败。
4. 设置页新增“快捷同步”卡片，编辑抖音来源和 1–100 条数量。保存即启用直接同步；“下次先确认”只清除 configured 标记，保留当前选项供下次弹窗预填。
5. B站/小红书仍保留在同一同步弹窗中，但不参与首页无弹窗执行，因为它们依赖桌面桥接与官方页面账号确认，无法提供一致的跨端静默执行语义。

## Risks / Trade-offs

- [本地存储被清理后配置丢失] → 自动回到首次打开弹窗的安全流程。
- [资料库状态请求较慢] → 快捷入口显示“同步中”状态，直到账号状态确定；不使用固定延时猜测。
- [同步失败后用户不知如何恢复] → 停留在资料库并复用现有可见反馈，账号不可用时直接打开同步弹窗。
- [旧页面实例重复消费 URL] → 使用单次 ref 并在执行前移除 `sync` 参数。

## Migration Plan

前端部署即可生效，无数据库迁移。回滚时删除设置卡和查询参数分支即可；现有来源/数量 localStorage 数据仍可被旧版资料库读取。
