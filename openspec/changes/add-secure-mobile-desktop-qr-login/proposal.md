## Why

Windows 客户端当前只能跳到外部浏览器完成账号交接，手机端也没有可直接扫描客户端二维码的入口。用户需要一种安全、清晰的跨端登录方式：在已登录手机上扫描客户端二维码并确认后，客户端自动进入同一账号，同时避免二维码泄露后被他人抢领长期 JWT。

## What Changes

- Windows 客户端登录页直接创建并展示短时有效的登录二维码，实时显示等待、已扫描、已确认、过期和失败状态，并保留账号密码及现有网页登录作为备用。
- Android 登录页增加“扫码登录电脑”入口，使用原生相机扫描知萃登录码；扫码后显示目标设备与校验码，用户明确确认后完成授权。
- 新增服务端 v2 设备登录会话，把二维码中的公开确认凭证与客户端持有的领取凭证完全分离；凭证仅存摘要、短时有效、一次消费，并防止重放和并发重复换票。
- 已登录手机可直接确认；未登录手机保留待确认会话，在完成账号登录后继续确认，不要求重新扫码。
- 增加 Android 相机权限及隐私说明，相机仅在用户主动扫码时启用，二维码在设备本地解析，画面不上传、不保存。
- 增加生命周期、安全失败分支、移动扫码和桌面轮询的自动化验证，并将通过验证的 Web、后端和 Android 版本发布到正式环境。

## Capabilities

### New Capabilities
- `secure-desktop-qr-login`: 规定桌面二维码创建、移动端扫码确认、双凭证隔离、一次性换票、过期/拒绝/取消状态以及相机隐私行为。

### Modified Capabilities
- `client-auth-entry`: Windows 与 Android 统一登录入口新增扫码登录电脑的呈现、回退和登录后继续确认行为。
- `production-deploy-safety`: 正式发布门禁新增扫码登录 API 冒烟、Android 相机能力和跨端登录验收要求。

## Impact

- 后端：新增设备登录会话模型与服务、认证 API、限流/活动记录及启动建表。
- 前端：登录页、认证上下文、API 类型与扫码组件；继续复用 `qrcode.react` 生成桌面二维码。
- Android：新增兼容 Capacitor 8 的原生条码扫描插件、CAMERA 权限与隐私文案，需要重新构建并发布 APK。
- Windows：客户端登录页改为内嵌二维码并接收轮询成功后的会话；无需在二维码中暴露客户端领取密钥。
- 部署：数据库新增表，Web/后端发布后执行正式 API 冒烟；Android 发行需沿用现有签名、版本递增和真机验收门禁。
