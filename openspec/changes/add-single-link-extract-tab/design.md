## Context

单条链接提取目前由首页客户端状态临时展开；桌面首页使用 `WorkspaceActionHome` 时没有该回调，因此“解析链接”退化为指向 `/library` 的链接。提取本身已经由全局 `ExtractionContext` 管理，并已有 `InputBar`、`PipelineProgress`、`CardRenderer` 等稳定组件，因此无需改动后端流水线。

## Goals / Non-Goals

**Goals:**

- 为单条链接建立可直接访问和刷新后重新进入的 `/extract` 工作区。
- 在桌面左侧导航中提供独立、可识别、正确高亮的“单条解析”入口。
- 让所有单条解析快捷入口指向同一路由，同时复用现有提取状态和结果组件。
- 保持移动端底部导航为五项，并保证独立页在窄屏可用。

**Non-Goals:**

- 不改变 `/api/extract`、SSE 事件协议、ASR 或知识卡生成逻辑。
- 不重新设计处理结果详情 `/process?id=...`。
- 不增加新的移动端底部 Tab。

## Decisions

1. 使用 `/extract` 作为独立路由，而不是 `/library/extract`。单条解析是内容进入系统的操作，不是已有资料的子列表；顶级路由也能让导航选中态保持互斥。
2. 在 `ProductDestinationId` 中增加 `extract`，但只插入 `DESKTOP_PRODUCT_DESTINATIONS`。移动端继续通过首页快捷入口进入独立页，从而保持五个底部 Tab。
3. 新页面直接消费全局 `ExtractionContext`。这样切换路由时正在进行的提取不会被局部组件重置，完成后的卡片、错误与进度仍使用唯一状态来源。
4. 新页面复用现有提取组件并提供紧凑的页头、输入主卡、三步说明、进度和结果区域。页面不使用 Portal、手工 DOM 移动或新增动画系统。
5. 首页快捷入口统一使用普通路由链接到 `/extract`，删除桌面端指向 `/library` 的退化路径；移动端首页也不再维护一套内嵌提取工作区。
6. 单条解析首屏使用单一焦点工作台，不再把输入区和流程说明做成两张同权重卡片。链接输入占据视觉中心，流程压缩为输入区下方的横向三步轨道；页面使用已有中性色与品牌蓝，移除双重焦点描边、发光和不必要的玻璃层。

## Risks / Trade-offs

- [Risk] 用户从旧首页开始提取的习惯发生变化 → 首页保留原有“提取单条链接/解析链接”文案，只改变落点并在新页自动聚焦输入框。
- [Risk] 全局提取结果在新页和其他页面之间共享，可能显示上一次结果 → 保持现有 `ExtractionContext` 语义，并在页面上清楚标明当前单条解析结果。
- [Risk] 桌面导航项增加后纵向空间更紧 → 沿用现有紧凑导航尺寸，并仅在桌面导航增加一项。
- [Risk] 页面专用视觉覆盖影响通用 `InputBar` → 所有覆盖都限定在页面 CSS Module 容器内，不修改其他页面的默认输入样式。
