## Why

视频资料库现在更适合批量浏览和集合研究，但用户点击单条视频后，缺少一个能同时观看视频、阅读全文、追问内容并把结论转成行动计划的沉浸式工作区。补齐这个闭环，可以让一条已收藏的视频从“看过”继续走到“理解、提问、执行”，同时保持主数据库只保存文本、链接和结构化知识，不保存视频文件。

## What Changes

- 视频卡片整体可进入大尺寸单视频详情工作区，保留勾选、删除等独立操作。
- 新增单视频详情接口，聚合下载器中的实时媒体信息、当前用户的文案/知识卡以及关联计划。
- 详情页左侧展示大尺寸视频与来源信息，右侧以 Tab 切换 AI 问答、完整文案和行动计划。
- 未提取视频可在详情页启动文案与知识卡提取；提取完成后无需返回列表即可继续问答和创建计划。
- 新增计划 Agent：基于完整视频文案、AI 总结、现有计划和用户自然语言要求，创建或整体调整结构化计划。
- 计划 Agent 应尽量保留已有任务的完成状态，并返回本次调整摘要；用户可继续进入计划工作台执行和精细编辑。
- 明确媒体边界：视频播放地址与封面实时来自本地下载器，主数据库不得持久化视频文件或视频二进制内容。
- 桌面端使用占据主要视口的双栏工作区；移动端使用纵向视频区加内容 Tab，保持相同能力。

## Capabilities

### New Capabilities

- `video-knowledge-workspace`: 单视频大尺寸详情、实时媒体展示、文案阅读、基于来源的问答，以及能创建和调整关联计划的 Agent 工作流。

### Modified Capabilities

无。

## Impact

- 后端：`backend/app/api/routes.py`、`backend/app/services/douyin_library.py`、`backend/app/services/ai_juicer.py`、`backend/app/services/plan_service.py`。
- 前端：视频资料库卡片导航、新增静态兼容的 `/library/detail?id=...` 页面、API 类型与响应封装、详情工作区样式。
- 数据：复用现有 `notes` 与 `plans` 表；不新增媒体表、BLOB/BYTEA/LargeBinary 字段或视频文件写入。
- 外部系统：详情媒体继续依赖本地 `douyin-downloader` 的 manifest 与静态文件服务；无新增前端依赖。
