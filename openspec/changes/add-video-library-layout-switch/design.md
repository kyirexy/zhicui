## Context

视频资料页已经用同一页面编排抖音资料与 B站/小红书资料，但当前展示层强制为单列。抖音已有 `selected: Set<aweme_id>`、全选和底部批量操作；B站/小红书只有预览、详情、摘要和来源动作。此次改动必须复用这些真实能力，不修改同步或持久化 API，也不能把跨平台资料伪装成可执行抖音批量操作。

## Goals / Non-Goals

**Goals:**

- 提供稳定、可记忆的列表/网格切换。
- 两种布局共享同一搜索、筛选、预览和抖音选择状态。
- 在桌面和移动端保持可读、可触控且无横向溢出。
- 移除容易被压缩的单卡管理菜单，同时保留原有管理能力。

**Non-Goals:**

- 不实现鼠标拖拽框选、多账号、分页、标签编辑或新的资料管理 API。
- 不向 B站/小红书增加抖音专属的批量移出、永久隐藏或批量提取能力。
- 不改变视频同步、文案提取、摘要生成和本地媒体链路。

## Decisions

1. **布局是纯前端偏好。** 使用现有 `useLocalStorage` 保存 `list | grid`，并校验存储值。切换布局只改变 `data-layout`，不重建数据键、不清空选择或预览。相比新增用户设置 API，这一方案不引入跨设备同步承诺，也不触碰后端。

2. **统一网格由父容器编排。** 网格模式下让抖音列表包装层使用 `display: contents`，使抖音卡片和跨平台卡片进入同一个响应式 CSS Grid；列表模式继续沿用现有横向资料行。相比复制第二套渲染树，这能保证功能状态和事件处理完全共用。

3. **选择能力按平台保持边界。** 抖音卡片继续显示复选按钮并驱动现有 `selected` 集合；B站/小红书只改变排版，不增加复选控件。布局切换按钮使用 `aria-pressed`，卡片继续使用 `article`，不引入会与内部链接冲突的 `listbox` 或拖拽框选语义。

4. **单卡危险操作收口到底部操作条。** 移出和永久隐藏继续使用已有批量确认流程；仅选择一条且存在 `extracted_note_id` 时显示“删除文案与摘要”。相比修补每张卡片的弹出层，这减少重复入口并避免窄列中的菜单溢出。

5. **明确控制滚动轴。** 平台标签栏保留横向触控滚动，但显式隐藏纵向溢出和可见滚动条；活动下划线放在容器内部，避免 Windows/Electron 出现短竖滚动条。

## Risks / Trade-offs

- [移动端两列网格内容更紧凑] → 390px 维持两列并压缩非关键文案，359px 以下退化为单列，触控目标保持至少 48px。
- [跨平台卡片在网格中没有复选框，视觉能力不完全一致] → 保留真实平台能力边界，并通过抖音批量栏文案明确“已选抖音视频”。
- [旧布局偏好值损坏] → 校验本地值并回退到网格默认值。
- [移除单卡菜单降低单步可发现性] → 复选按钮保持常驻，全选与底部批量菜单提供统一管理入口。
