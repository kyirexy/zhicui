## Context

资料库允许同步 1–100 条视频，但现有批量文案接口一次最多接受 50 条。当前前端初始值为同步 50、处理 20，且改变同步范围只会把过大的处理数向下截断，不会让默认值主动跟随同步范围。

## Goals / Non-Goals

**Goals:**

- 新用户打开资料库时默认同步 50 条并处理 50 条。
- 改变同步范围时自动给出符合批处理上限的默认处理数量。
- 用户仍可手动减少处理数量或关闭自动处理。
- 保持服务端批量任务一次提交、分阶段受控并发。

**Non-Goals:**

- 不把单批提取上限从 50 提高到 100。
- 不修改同步 API、批量任务 API、数据库或运行时并发配置。
- 不强制锁定同步数量与处理数量，使用户失去手动选择能力。

## Decisions

### 以同一个前端常量约束选择和自动处理

复用现有 `MAX_SELECTION = 50` 作为单批处理上限。初始处理数量设为该值；同步范围变化时设为 `min(同步数量, MAX_SELECTION)`。相比增加第二个值为 50 的常量，这能避免选择上限与提交上限漂移。

### 同步范围变化时刷新默认值，之后允许手动覆盖

同步预设按钮和自定义输入都会更新处理数量；自动处理输入仍可被用户调小。相比永久使用派生值，这保留了“只同步较大范围、只处理其中一部分”的灵活性。

### 提交前再次收紧数量

启动同步时再次按 `min(本次同步数量, MAX_SELECTION)` 校验处理数量，避免输入状态或未来 UI 改动向 1–50 条批量接口发送超限目标。

## Risks / Trade-offs

- [同步 100 条时处理数不会同样达到 100] → UI 明确说明单次最多并发处理 50 条；用户可在完成后继续选择其余视频。
- [用户输入同步范围时处理数会随每次输入变化] → 输入仍保留独立编辑能力，完成同步范围输入后可手动调小。
- [默认 50 条增加一次任务的 API 消耗] → 这是用户明确选择的默认行为，服务端 ASR/LLM 阶段仍由独立信号量控制，不会无界同时调用上游。
