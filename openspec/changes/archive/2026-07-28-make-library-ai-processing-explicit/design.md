## Context

当前资料库的同步按钮先从抖音更新元数据，随后在 `autoProcess` 开启时自动选择最近若干视频并创建批量提取任务。每个任务包含一次云端 ASR、一次 DeepSeek 内容分类、一次知识卡生成，计划类再增加一次计划生成。用户仅想查看收藏清单时，这些调用没有必要。

资料库已经具备视频勾选、全选当前、显式“生成文案”按钮、批量任务和逐条进度，因此不需要新增后端 API，只需把同步流程从自动处理流程中解耦。

## Goals / Non-Goals

**Goals:**

- 同步只更新视频清单和必要元数据。
- 只有用户明确勾选视频并点击处理按钮时，才调用 ASR 和 DeepSeek。
- 按钮准确说明会同时生成完整文案与知识卡。
- 保留现有并发、幂等、按用户隔离和视频不落库行为。

**Non-Goals:**

- 本次不拆分“仅 ASR”和“仅生成知识卡”两个后端任务类型。
- 不改变一次显式批量处理最多 50 条的限制。
- 不自动为 AI 问答补提未处理视频；问答仍只读取已有完整文案。

## Decisions

### 同步流程不再引用处理数量

删除 `processCount` 与 `autoProcess` 客户端状态。同步成功后重新加载清单、清空选择并结束，不再调用 `extractItems`。这比默认关闭但保留开关更清晰，因为同步按钮始终只有一个稳定含义。

### 复用勾选后的现有批量任务

用户勾选一个或多个未处理视频后，工具栏显示“生成文案与知识卡 · N”。点击后仍通过一个批量请求创建后台任务，所有目标立即入队，并显示 ASR 与 AI 分阶段进度。

### 继续把文案与知识卡作为一次主动处理

主动处理仍执行 ASR、分类、知识卡和可选计划生成。这保持当前 Note 数据完整性，也避免在本次变更中引入半成品 Note 状态和数据库迁移。后续如需要控制费用，可单独设计“仅转写”模式。

## Risks / Trade-offs

- [新同步的视频不会立即用于问答] → 卡片状态明确显示“待提文案”，工具栏提供醒目的主动处理按钮。
- [用户需要多一次选择操作] → 支持全选当前与多选，批量任务仍保持并发。
- [按钮文案较长] → 使用现有紧凑工具栏样式，并在小屏幕保留数量提示。
- [已经生成的文案与卡片仍保留] → 本次只改变未来同步行为，不删除任何已有用户数据。
