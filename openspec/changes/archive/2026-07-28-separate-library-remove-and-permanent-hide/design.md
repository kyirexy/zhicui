## Context

资料库目前使用 `library_hidden_items` 记录用户移出的抖音作品，记录只有用户与作品 ID，因此所有移出都被视为永久 tombstone。资料库列表会过滤这些记录，后续同步也不会清除；这导致普通整理动作与永久屏蔽没有语义区别，也造成“下载器已同步但资料库显示 0 条”的误导。

本次改动横跨 PostgreSQL/SQLite 兼容迁移、同步任务完成轮询、资料库 API 和桌面/移动端交互。约束是服务器仍不得保存视频文件，已有隐藏记录不得在升级时被静默恢复。

## Goals / Non-Goals

**Goals:**

- 明确区分临时移出与永久隐藏。
- 仅由发生在临时移出之后的下一次成功同步恢复临时记录。
- 让永久隐藏可识别、可管理、可恢复。
- 保持用户隔离以及文案、知识卡和计划的非破坏性语义。
- 让同步结果能解释“已同步但被隐藏”的情况。

**Non-Goals:**

- 不修改或取消用户在抖音中的收藏。
- 不删除下载器侧元数据、视频文件、文案、知识卡或计划。
- 不在知萃数据库保存视频二进制或远程视频内容。

## Decisions

### 1. 在现有记录上增加隐藏模式

`library_hidden_items` 增加 `hide_mode` 字段，允许 `temporary` 与 `permanent`。已有记录迁移默认值为 `permanent`，新安装也使用该默认值，避免部署后历史隐藏内容突然重现。

替代方案是为临时与永久建立两张表，但会增加唯一性冲突、过滤合并和迁移复杂度，且两者共享相同生命周期字段。

### 2. 临时记录在成功同步完成时按时间清除

同步任务成功后，后端根据任务 `finished_at` 清除同一用户中 `created_at <= finished_at` 的临时记录。这样轮询历史成功任务不会误清除用户在该任务完成后新建的临时移出记录；失败或进行中的任务不会恢复任何内容。

### 3. 永久隐藏不能被普通操作降级

重复操作保持幂等。临时记录可升级为永久记录；对已永久隐藏作品再次执行普通移出不会把它降级。恢复接口显式删除永久记录。

### 4. 管理接口返回展示元数据但不持久化视频

永久隐藏列表从用户隐藏记录出发，尽力与下载器当前目录中的标题、封面和作者元数据合并；目录不可用时仍返回作品 ID 与隐藏时间，使用户始终可以恢复。数据库继续只保存作品 ID、模式和时间。

### 5. UI 使用分级操作

卡片主操作维持“移出资料库”，确认文案明确说明“下次同步会重新出现”。“永久隐藏”放入次级菜单或批量上下文，并使用危险样式的确认对话框。页面提供带数量的“已永久隐藏”入口，列表中展示永久标识和恢复操作。

## Risks / Trade-offs

- [历史隐藏记录被视为永久记录，可能包含用户原本只想临时移出的内容] → 提供明显的已永久隐藏入口与批量恢复能力。
- [下载器目录暂时不可用时永久隐藏列表缺少标题和封面] → 使用作品 ID 占位但仍允许恢复，不让恢复依赖外部服务。
- [同步任务完成时间格式或时区不一致导致临时记录未恢复] → 统一解析为 UTC，并在缺少有效完成时间时保守地不清除。
- [一次成功同步会恢复该用户所有早于任务完成的临时移出，而不只当前来源] → 当前隐藏键是全局作品 ID 且同步入口共享同一资料库；该行为与“下次同步重新出现”的用户承诺一致。

## Migration Plan

1. 部署模型与启动期兼容迁移，为既有列缺失的数据库添加 `hide_mode VARCHAR(16) NOT NULL DEFAULT 'permanent'`。
2. 部署兼容读取逻辑，将空值或未知值保守视为永久隐藏。
3. 部署 API 与前端；旧客户端不传模式时后端默认使用临时移出。
4. 回滚时旧版本会继续过滤所有记录；新增字段不会影响旧查询，因此无需删除列。

## Open Questions

无。现有产品语义足以确定默认临时移出、永久操作二次确认和可恢复管理入口。
