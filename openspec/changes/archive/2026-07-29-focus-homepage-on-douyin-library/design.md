## Context

当前首页以单链接输入框和内容品类卡片为主体，并通过多平台文案描述产品能力。产品现阶段最成熟、最具辨识度的路径已经转为抖音批量视频库，因此首页需要把“先看到能力、再进入使用”作为主要叙事，同时不能破坏已有单链接提取流程。

## Goals / Non-Goals

**Goals:**

- 首屏让用户在数秒内理解知萃能批量整理抖音收藏、喜欢和个人作品。
- 用真实产品结构感的预览表现完整文案、批量问答、计划和知识卡之间的关系。
- 让“打开视频库”成为主操作，单条链接提取成为次操作。
- 保持桌面端信息完整，移动端紧凑易读且触控目标清晰。

**Non-Goals:**

- 不移除或禁用后端已有的其他平台解析能力。
- 不修改视频库同步、文案提取、AI 问答或计划生成逻辑。
- 不新增营销统计、轮播、外部素材或第三方动画库。

## Decisions

1. **采用不对称的双栏 Hero。** 左侧提供明确价值、主次操作和可信的流程说明；右侧使用视频库工作台预览。相比居中标题加输入框，这种结构更适合解释批量产品，也能避免通用营销页观感。
2. **首页默认展示批量能力，单链提取使用渐进展开。** 保留现有 `InputBar`、加载进度、样例和卡片结果，但仅在用户主动选择“提取单条链接”或已有提取状态时展示，避免破坏已有功能。
3. **使用现有设计系统与图标依赖。** 复用玻璃表面、前景色、emerald 强调色与已有图标包，不引入新依赖，确保深浅色模式和 Capacitor 构建兼容。
4. **首页内容只宣传抖音路径。** 删除首页可见的公众号、B站、YouTube、小红书字样；其他平台能力仍可保留在代码和后端中，但不参与当前首页定位。
5. **响应式预览按信息优先级收缩。** 桌面展示侧边栏、视频网格和 AI 结果面板；移动端隐藏非关键装饰并保持视频、文案、问答、计划四个结果信号可见。

## Risks / Trade-offs

- [首页弱化单链接提取后，老用户可能找不到原入口] → 保留清晰的“提取单条链接”次级按钮，并在展开后维持原完整流程。
- [产品预览使用静态示例，可能被误解为真实账号数据] → 使用通用内容标题和“示意”语义，不展示夸张数量或虚构效果指标。
- [首屏内容增多导致移动端过长] → 移动端压缩说明文案、减少装饰层和预览列数，确保主按钮在首屏附近。
- [首页定位变化与后端多平台能力不一致] → 仅调整营销呈现，不删除已有解析能力，便于未来重新开放其他平台入口。
