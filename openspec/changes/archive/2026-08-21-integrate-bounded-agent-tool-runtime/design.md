## Context

Agent V2 已把用户问题建模为可恢复 Turn，并把研究进度保存为单调事件；`answer_library_question` 也已具备扫描、分批 map、网页查证、综合、Claim/Evidence 校验和最多两轮修复。当前缺口是这些步骤直接互相调用，`RepeatToolGuard` 没有统一执行入口，因而工具级取消、租约检查和事件只依赖外围进度回调，无法作为独立运行时合同测试。

## Goals / Non-Goals

**Goals:**

- 建立最小、类型清晰、默认拒绝未知工具的领域工具协议与白名单注册表。
- 让工具调用统一经过取消/租约前后检查、重复检测、调用预算、结果大小校验和脱敏事件记录。
- 把现有视频研究的关键步骤接入执行器，而不改变现有 API、Answer Result 或计费语义。
- 让运行时可通过纯单元测试验证，并可在真实 V2 Turn 事件流中观测。

**Non-Goals:**

- 不向模型开放 Shell、文件系统、代码编辑、任意 URL 或第三方插件。
- 不在本次引入自由规划的无限 ReAct 循环；研究编排仍由受测的有界领域流程控制。
- 不保存完整工具参数、文稿、模型密钥或工具结果到事件表。
- 不改变 V1 会话、前端请求合同或现有功能开关策略。

## Decisions

### 1. 使用每个 Turn 独立的注册表与执行器

新增 `AgentToolRegistry` 和 `AgentToolExecutor`。注册表只接收显式 `AgentTool`，重复名称拒绝注册，未知名称拒绝执行。执行器持有 Turn ID、调用预算、`RepeatToolGuard`、边界检查回调和事件回调。

选择 Turn 级实例而非进程全局可变注册表，是为了让闭包只能访问该 Turn 已冻结的来源，并避免跨用户共享参数或状态。替代方案是全局插件表，但会扩大权限面并增加并发隔离风险。

### 2. 事件只记录安全摘要

工具事件记录工具名、调用序号、耗时、结果类型/数量/字符估算和重复计数，不记录原始参数、完整文稿或模型响应。参数规范化只在进程内用于重复检测。

这复用现有 `AgentEvent`，无需数据库迁移；同时保证刷新恢复时能说明 Agent 做过什么，而不把敏感或超大内容落库。

### 3. 每次工具调用的前后都执行同一边界检查

V2 worker 为执行器注入检查回调：通过当前租约续租并验证取消状态。调用前失败则不执行工具；调用后失败则丢弃返回值，失去租约的 worker 无法提交结果。非持久 V1 路径使用无副作用检查，保持兼容。

### 4. 重复熔断与总预算双重有界

同一 Turn 对同一工具、相同规范化参数连续第三次调用产生提醒事件，第五次抛出受控 `AgentToolRepeatBlocked`。此外设置每 Turn 最大调用数，超过后抛出 `AgentToolBudgetExceeded`。

只用重复检测无法阻止不断换参数的循环；只用总预算又无法及时提示明显卡住的路径，因此两者并存。现有 Claim 修复仍保持最多两轮。

### 5. 先接入现有确定性编排，不引入任意模型工具选择

来源扫描、分批文稿映射、外部查证、回答综合、Claim 修复与 Claim 校验通过注册工具执行。编排器仍决定固定的安全顺序和次数，工具执行器负责统一边界与可观测性。

这保留 Codex/DeepSeek Harness 的工具抽象、重复保护和运行边界，但避免在视频资料产品中引入可访问任意能力的通用代理风险。

## Risks / Trade-offs

- [工具事件增多导致写入放大] → 只对阶段级领域工具记录开始/完成，不对每个文稿块单独落事件；保留现有进度计数。
- [结果大小估算增加 CPU 开销] → 使用有界 JSON 序列化，结果上限远低于 Turn 生命周期的模型调用成本。
- [模型调用失败被误认为工具运行时失败] → 保留原异常类型并在事件中只记录稳定错误码；现有 V1 回退仍可接管输出前失败。
- [V1 与 V2 行为分叉] → 两条路径调用同一注册工具流程；只有 V2 注入持久检查和事件回调。

## Migration Plan

1. 在本地功能开关白名单下运行单元/集成测试和真实 37 视频问题。
2. 验证 V2 Turn 中出现工具开始/完成事件，取消和过期租约能在工具边界停止。
3. 保持生产总开关不变；发布时先对管理员白名单灰度。
4. 若异常，关闭 Agent V2 即回退既有 V1，不需要数据回滚。

## Open Questions

无。开放式模型工具选择若未来需要，应作为独立安全评审和 OpenSpec 变更处理。
