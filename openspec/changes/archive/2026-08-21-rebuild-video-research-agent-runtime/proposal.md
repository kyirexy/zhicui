## Why

当前视频 Agent 把路由、检索、综合与证据校验压在一次回答调用中，导致跨几十条视频的问题会被误判为快速问答、只综合部分来源、丢失早期多轮上下文，并允许正文残留未通过验证的引用。知萃需要一个可恢复、可审计、按来源规模自动分层研究的领域 Agent，而不是继续依赖更长的单次 Prompt。

## What Changes

- 在现有 FastAPI 与 Harness 上增量引入持久化 Turn/Event 运行时，支持断线恢复、取消、幂等重试、租约续跑和真实阶段计数。
- 默认由问题意图和来源规模自动选择快速或深度研究；高级设置仍可显式覆盖。
- 对多视频与博主全部作品采用分层研究：全部来源先参加结构化扫描，再深读关键、分歧与高相关来源，明确展示每层覆盖数量。
- 将检索、文稿读取、批量映射、主题聚类与逐字证据校验封装为受限领域工具，执行有界的计划、研究、综合、验证、修复循环。
- 最终正文从已验证 Claim/Evidence 结构渲染；无效引用不得进入正文，反复观点必须由至少两个独立视频支持。
- 增加结构化长期会话记忆与上下文压缩，替代只传最近六条消息的短记忆。
- 视频问答默认仅使用视频资料；用户显式开启后才允许外部网页研究。
- 通过功能开关灰度上线 V2，保留旧链路作为未灰度用户和未开始输出时的故障回退。

## Capabilities

### New Capabilities
- `durable-video-research-agent`: 持久 Turn/Event、自动研究路由、分层多来源研究、Claim 证据修复、长期记忆、恢复与灰度运行契约。

### Modified Capabilities
- `grounded-web-research`: 将默认研究范围从自动联网改为仅视频，外部网页研究必须由用户显式开启，并与 V2 的验证事件和引用结构对齐。

## Impact

- 后端新增 Agent 运行、事件、来源覆盖、Claim/Evidence 与记忆检查点数据，并重构现有 `agent_service`/`ai_juicer` 调用边界。
- 扩展 `/api/agent/threads` 消息、Turn 查询/恢复/取消/重试与 SSE 契约，同时兼容现有 Thread/Message 响应。
- Harness 增加“自动”研究模式、默认仅视频、真实分层进度、恢复与按观点组织的证据展示。
- SQLite 与 PostgreSQL 采用加法迁移；旧线程无需批量回填，新 V2 Turn 首次运行时从旧消息生成初始记忆。
