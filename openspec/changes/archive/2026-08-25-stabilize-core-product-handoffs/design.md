## Context

博主全量规格固定 yutto 2.2.0 作为 B站 metadata-only 连接器，近期作品继续使用 yt-dlp。真实本地部署证明 yutto WebSocket 服务与协议健康，但当前 B站空间接口会让固定版本在部分公开主页上记录抓取失败，同时任务结果错误地表现为 `complete=true, items=[]`。与此同时，前端交接状态把“仍在加载”过早归类为“不可用”，旧 BYOK 单行配置也未被新计费门识别。

该修复必须保持用户隔离、连接器回环与 token、无媒体下载、React DOM ownership、固定版本和许可证边界。

## Goals / Non-Goals

**Goals:**

- 保留 yutto 为 B站全量目录首选连接器，并对当前上游失效提供可验证的 metadata-only 降级。
- 不把异常空目录标记为一次完整成功扫描。
- 让视频和计划的 AI 交接只展示真实加载或真实失败状态。
- 让新旧 BYOK 配置都完全绕过平台计费。
- 提供 Windows 本地一键安装/启动并修正生产 sidecar 启动参数。

**Non-Goals:**

- 不绕过登录、验证码、私密、付费或平台风控。
- 不把 yt-dlp 变成第二套抖音工具，也不下载或归档 B站媒体。
- 不改动 Agent、计划、博主目录或计费数据库结构。
- 不自动启动同步任务。

## Decisions

### 1. yutto-first，yt-dlp 仅做 metadata-only 降级

`catalog_all` 先调用固定 yutto sidecar。只有 yutto 明确返回连接器错误，或已验证为视频空间的主页出现异常空结果时，才调用现有 `_bilibili_playlist` 进行平铺枚举。降级结果仍经过同一安全字段允许列表，并标记连接器来源，便于观察和后续移除。

相较直接升级 yutto，该方案不改变已审核提交、协议和许可证；相较直接切回 yt-dlp，它保留既定主路径与多 P 投影。

### 2. 空目录必须有可证明语义

目录连接器只有在上游明确证明主页确实无投稿时才允许 `complete=true, total_count=0`。固定版 yutto 无法区分空主页和抓取失败，因此其零项结果先触发降级；降级也失败时运行进入部分失败或需用户处理，旧目录保持可用。

### 3. 平台与操作能力分层展示

平台可保存/近期转写取决于近期连接器；“刷新全部清单”单独依赖 `catalog_all` 健康。前端只禁用实际不可用的操作，并在动作附近显示一个短原因与恢复入口。

### 4. 来源交接使用三态模型

请求来源或计划上下文期间保持稳定骨架/“正在读取”状态；成功后显示真实标题和动态问题；只有请求完成且目标仍未解析时才显示不可用错误。重试发生在原位置，不使用全局错误横幅覆盖已经可用的内容。

### 5. BYOK 判断兼容滚动迁移

计费门先检查选中的 `UserCustomChatModel`，不存在时检查旧 `UserAIProviderConfig(mode='custom')` 的完整可用行。有效 BYOK 直接返回 `None`，既不扣点也不创建零点预留。

### 6. 本地 sidecar 与生产保持同一信任边界

Windows 运行文件放在 `%LOCALAPPDATA%/Zhicui/yutto-sidecar`，使用独立 venv、固定提交、审核补丁、随机 token 和隐藏进程；源码、许可证和说明留在运行目录。桌面启动器先准备 sidecar 环境，再启动继承环境变量的后端。生产继续使用 systemd 与 0600 token。

## Risks / Trade-offs

- [yt-dlp 输出与 yutto 字段不同] → 统一投影到现有稳定字段并增加契约测试，禁止媒体 URL、Cookie 和本地路径。
- [真实空主页被额外探测一次] → 只在零项时触发一次平铺枚举，接受少量额外延迟以换取正确语义。
- [B站再次调整接口] → 两条连接器均失败时停止有限重试并给出可操作错误，不伪造成功。
- [首次 Windows 编译耗时] → 只安装一次，后续启动复用；版本与提交必须校验。
- [加载态停留过久] → 保留短状态并允许重试，但不提前展示失败。

## Migration Plan

1. 发布后端兼容计费和 B站降级逻辑及回归测试。
2. 发布前端三态交接和操作级能力提示。
3. 本地运行安装脚本并通过真实 B站主页 metadata-only 冒烟。
4. 生产更新 yutto unit、健康检查和管理员连接器测试后再开放 B站全量。
5. 回滚时可关闭 B站 `catalog_all`；近期 yt-dlp、已有目录、文案、知识和计划不受影响。
