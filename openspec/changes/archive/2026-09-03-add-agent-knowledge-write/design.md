## Context

视频研究 Agent 已具备持久线程、用户隔离资料、结构化消息结果和内部 `plan.create` 工具。项目同时已有成熟的 `knowledge_service.create_entry()` 与知识库详情页，但两者尚未连接。此次改动跨越意图门控、LLM 整理、持久化、运行事件和结果 UI，且必须防止未经用户明确要求的隐式写入。

## Goals / Non-Goals

**Goals:**

- 仅在明确肯定的知识保存意图下执行 `knowledge.create`。
- 可从用户本次要求、最近对话和当前选中视频资料中整理知识。
- 复用现有知识服务，保证用户隔离、字段限制和知识库兼容性。
- 返回结构化 `knowledge_created` 结果并提供“打开知识”入口。
- 任一步失败时不留下知识条目或孤立消息。

**Non-Goals:**

- 不让 Agent 在普通回答后自行判断“值得保存”并静默写入。
- 本次不支持通过自然语言更新或删除既有知识。
- 不新增知识表、权限模型或独立编辑器。

## Decisions

1. 使用确定性意图门控，而不是让 LLM 独立决定是否写入。门控要求保存类动作和知识/记录类目标同时成立，并排除否定、疑问和教程类表达。这样可以在模型调用前阻止误写。
2. 内部工具命名为 `knowledge.create`，与现有产品动作注册表保持一致。工具处理器调用 `knowledge_service.create_entry()`，不绕过既有用户隔离和字段裁剪。
3. 新增专用的 LLM 整理函数，仅负责把有界上下文转成 `{title, summary, content}`。上下文优先包含最近对话，再补充所选视频资料；所有输入和输出都有长度上限。
4. Agent 消息使用 `type: knowledge_created` 和精简的 `created_knowledge` 元数据。前端复用计划创建卡片的视觉层级，链接到 `/notes?id=<entry_id>`。
5. 创建流程沿用计划工具的事务补偿模式：捕获异常后回滚、按当前用户重新查找并删除已创建条目，同时清理本轮孤立消息。

## Risks / Trade-offs

- [口语表达可能漏判] → 覆盖常见“记下来、保存下来、加入知识库”等表达，并以测试持续补充；宁可漏判也不误写。
- [“把上面的保存”缺少正文] → 向整理模型提供最近对话；若仍无法形成有效正文则明确失败，不创建空条目。
- [模型返回非 JSON] → 使用已有宽容 JSON 提取逻辑并对字段做服务端兜底校验。
- [创建后回答持久化失败] → 记录新条目 ID并执行用户隔离的补偿删除。
