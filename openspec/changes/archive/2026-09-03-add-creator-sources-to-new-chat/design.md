## Context

AI 问答的资料面板已经能够列出并勾选 `AgentSource`，博主同步模块也已经维护 `CreatorSource → CreatorSourceItem → Note` 的用户级映射。缺口是两处数据没有在问答选择器中汇合，现有“同步视频”入口偏向采集流程，导致用户需要离开新会话再逐条寻找作品。

## Goals / Non-Goals

**Goals:**

- 在同一个资料面板中展示博主并整组选中其可问答视频。
- 复用既有 Note ID 和 Agent 的 selected source 模式，不引入新的会话上下文类型。
- 保持 100 条单会话上限、用户隔离和移动端触控可用性。

**Non-Goals:**

- 不在选择博主时自动启动同步或转写。
- 不改变 Agent 检索、回答、会话快照或博主采集任务。
- 不允许跨用户或未生成完整文稿的作品进入会话。

## Decisions

### 在博主列表响应中提供已就绪 Note ID

服务端从 `CreatorSourceItem` 查询当前用户、当前来源、未移除且关联 Note 的项目，再与有非空文稿的 Note 联表，返回最多 100 个 `ready_note_ids`。相比前端逐页加载每个博主的作品目录，这避免 N+1 请求，并在服务端完成权限和可用性判断。

### 将“博主”作为资料浏览维度而非页面跳转

资料面板的平台切换增加“博主”。该视图显示头像、平台、名称和可用数量。选择博主会把其 `ready_note_ids` 合并到当前 `selectedSourceIds`；再次选择会移除该组。问答仍提交标准 `source_ids`，后端 Agent 无需识别新的来源类型。

### 选择上限按确定顺序截断并明确反馈

博主资料按作品目录已有顺序返回。若加入整组会超过 100 条，只加入剩余容量并显示实际加入数量，避免无响应或隐藏失败。没有就绪资料的博主保持可见但不可选。

## Risks / Trade-offs

- [同一视频可能属于多个选择路径] → `Set` 去重；取消某博主只移除该博主组内 ID，用户可随后重新手选。
- [博主已就绪数量超过 100] → API 和会话上限一致，只返回前 100 条并标记实际可选数量。
- [同步完成后面板数据变旧] → 打开资料面板时刷新博主列表，保留现有同步完成后的资料刷新逻辑。
- [博主接口暂不可用] → 只在博主视图内显示重试状态，不影响逐条视频选择和现有会话。

## Migration Plan

响应只增加可选字段，旧客户端可忽略；无需数据库迁移。回滚前端后，新增响应字段不会影响现有调用方。
