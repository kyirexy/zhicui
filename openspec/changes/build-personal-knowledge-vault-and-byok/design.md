## Context

现有 `notes` 表只保存视频/文章抽取得到的 AI 摘要，`/notes` 页面再按 `card_type` 显示为卡片库。Agent 的 LLM 配置来自全局 `system_settings`，无法按用户切换；`_call_llm` 遇到只有 reasoning、没有正文的响应会抛错，而 Agent 路由只保留包装后的 502。

## Goals / Non-Goals

**Goals:**

- 在不迁移或删除已有视频笔记的前提下，建立统一、可搜索的个人知识流。
- 让用户能够独立创建和维护自己的理解与想法。
- 让每个用户选择平台默认模型或 OpenAI 兼容供应商，并安全保存密钥。
- 让 Agent 在空正文响应时自动恢复，并留下足够的诊断信息。

**Non-Goals:**

- 本次不接入支付网关、订单或自动续费。
- 本次不删除 `notes.card_type`，也不重写历史 AI 摘要生成流程。
- 本次不实现向量数据库；搜索继续使用现有关系数据库的可移植查询。

## Decisions

1. **原创知识使用独立 `knowledge_entries` 表。** 该表保存 `user_id/title/content/source_label/timestamps`，避免把没有视频元数据的内容强塞进 `notes`。知识库 API 在服务层合并两类结果并按更新时间排序。备选方案是扩展 `notes` 大量 nullable 字段，但会模糊视频笔记的不变量。
2. **知识库 UI 采用内容列表和文档详情，不再提供卡片类型导航。** 列表以来源（视频知识/我的理解）作为非排他的元数据；搜索覆盖两类内容。卡片样式组件继续留给旧详情和导出链路，本次不删除代码以降低回归风险。
3. **每用户供应商配置使用独立表和 Fernet 加密。** API Key 使用现有 `ENCRYPTION_KEY` 机制；GET 永不返回明文。用户未启用自定义配置时解析到平台默认配置。
4. **通过显式 `user_id` 传入 LLM 调用解析配置。** Agent 调用传递当前线程所属用户；抽取等后台链路继续使用平台默认配置，避免隐式全局变量和跨用户泄露。
5. **空正文只重试一次。** 首次响应无可见正文时，第二次加入“关闭深度推理并直接输出最终 JSON”的指令；仍为空则抛出带错误分类的异常并记录原始类型、供应商、模型、操作名，不记录提示词或回答。
6. **基础额度先以产品策略字段呈现。** API 返回 `mode/default allowance/custom unlocks` 的明确说明，不在客户端伪造余额；后续计费系统可替换该策略响应。

## Risks / Trade-offs

- [合并两张表分页不精确] → 服务层先分别查询受限候选集，再统一排序分页；当前数据规模足够，未来可升级为数据库 UNION。
- [用户提供不兼容端点] → 保存前校验 URL，提供显式连接测试，失败不影响平台默认服务。
- [空正文重试增加成本] → 只在明确空正文时重试一次，并在日志中标记恢复调用。
- [没有支付系统就无法真正售卖高级功能] → 本次只建立能力边界和 BYOK 解锁，不声称已购买或已扣费。

## Migration Plan

1. 启动时创建 `knowledge_entries` 与 `user_ai_provider_configs` 表，不改动现有数据。
2. 发布兼容 API 和 Agent 恢复逻辑，再发布前端知识库与设置页面。
3. 回滚时旧 `notes` 和全局配置仍可工作；新表可保留，不影响旧版本。
