## Context

`CardRenderer` 是首页结果、知识库详情和处理过程页的统一卡片编排层。宽屏时它把卡片与 `ContentChat` 并排，但卡片列没有高度约束；任一主题的章节、结论或高密度转录都可能把右侧问答留在一条很长页面的顶部。各主题的 PNG 导出引用位于主题组件内部，因此可以在编排层限制可见视窗而不裁剪导出内容。

问答服务已把短文稿全文发送给模型；文稿超过 14,000 字时，会在本地扫描全部分块，选择最多四段问题相关或均匀覆盖的片段，并始终加入 AI 摘要。但摘要目前只是截断后的 JSON 字符串，API 也不返回“全文直读/全文扫描”和 AI 摘要使用状态。

## Goals / Non-Goals

**Goals:**

- 在宽屏中让卡片默认保持在一个可扫描的阅读高度，并允许用户随时查看完整内容。
- 只在确实溢出的电脑端卡片上显示展开动作，移动端保持自然文档阅读。
- 保持九种主题、密度切换和完整 PNG 导出兼容。
- 让问答显式扫描完整文稿，并把问题相关片段与结构化 AI 理解一起提供给回答模型。
- 向用户透明展示文稿长度、全文直读或分段扫描、扫描/选中片段数及 AI 理解使用状态。
- 继续逐字验证原文依据，不信任模型自行声明的 grounded 状态。

**Non-Goals:**

- 不把超长文稿无上限地塞进单次模型请求，不引入向量数据库或额外检索模型。
- 不持久化卡片展开状态或服务端聊天记录。
- 不改变卡片内容生成、九种主题内部布局或数据库模型。
- 不把文稿位置百分比描述为视频时间戳。

## Decisions

### 1. 在统一编排层实现渐进式阅读

`CardRenderer` 在主题组件外增加阅读视窗。宽屏且内容高度超过视窗上限时，视窗使用 `overflow: hidden` 和底部淡出提示，并在外部显示“展开完整卡片”；展开后解除高度限制并保留“收起卡片”。`ResizeObserver` 在主题动态加载、密度切换和窗口变化后重新判断溢出。

不逐一修改九个主题，是因为长度问题属于工作区编排，而不是主题数据表达。视窗位于 `cardRef` 外，导出按钮仍直接截取完整主题节点。

### 2. 桌面限高不应用于移动端

1080px 及以上启用限高阅读，与现有卡片/问答双栏断点一致；更窄视口保持单列完整内容。首页结果容器从窄卡片宽度扩为工作区宽度，避免在宽屏中把双栏挤进过窄父容器。

### 3. 将 AI 摘要转换为面向问答的语义文本

新增摘要整理函数，优先解析保存的 JSON，并按标题、核心洞察、金句、章节、结论、数据和风险判断组成有限长度的纯文本上下文。解析失败时才使用原始摘要字符串。这比直接截断 JSON 更稳定，也明确体现“AI 理解后的信息”。

### 4. 区分完整文稿扫描与模型上下文

短文稿使用 `full` 模式，完整文稿直接进入模型。长文稿使用 `retrieved` 模式：本地检索仍遍历全部分块，再把有问题相关性的有限片段按原顺序发送给模型。API 返回 `source_context`，包含文稿字符数、模式、扫描分块数、选中分块数和 `ai_summary_used`。

这种设计能诚实承诺“完整文稿已扫描”，又不虚假宣称超长全文全部进入同一次模型上下文。

### 5. 来源状态跟随每条回答

`ContentChat` 把 `source_context` 保存到 assistant 消息和当前标签页的 sessionStorage。回答状态、等待文案和依据标签显示“完整文稿/相关原文片段”和“AI 卡片理解”，旧会话没有该字段时按兼容状态渲染。

## Risks / Trade-offs

- [限高视窗可能在主题异步加载后闪现按钮] → 初始不裁剪短内容，`ResizeObserver` 完成测量后只更新必要状态，并使用短透明度过渡。
- [长文稿词法检索仍可能错过同义表达] → AI 卡片理解始终作为语义补充；无明显命中时均匀覆盖全文位置。
- [用户误解“完整文稿覆盖”为全文全部发送给模型] → UI 明确区分“全文直读”和“扫描全文后选取相关片段”。
- [返回字段增加客户端兼容成本] → `source_context` 为新增可选字段，旧客户端和旧 sessionStorage 消息继续可用。
- [首页变宽影响无问答卡片] → 只扩展结果工作区最大宽度，卡片内部仍由 `CardRenderer` 响应式布局控制。

## Migration Plan

1. 先部署向后兼容的问答响应字段与摘要整理逻辑。
2. 部署前端阅读视窗、来源状态和宽屏布局。
3. 无数据迁移；回滚前端后新增字段会被忽略，回滚后端时前端按缺失字段显示兼容文案。

## Open Questions

- 后续若长视频规模与问答量显著增加，再根据真实命中率评估向量检索；本轮继续使用无依赖的本地确定性检索。
