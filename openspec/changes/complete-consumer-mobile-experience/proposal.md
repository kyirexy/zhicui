## Why

当前 Android 与移动网页虽然具备核心业务能力，但仍像桌面页面的窄屏版本：普通用户会看到模型、AI 服务等技术概念，反馈按钮长期遮挡内容，设置入口不明确，计划默认页与既有“今日 / 目标 / 复盘”契约不一致。现在需要把移动端收束为可直接交付给普通用户的完整产品，而不是继续追加局部样式补丁。

## What Changes

- 建立统一的移动端白色实色外壳，规范顶部品牌区、底部导航、安全区、触控尺寸、页面尾部和无横向溢出要求。
- 移动端所有一级入口使用普通用户语言；隐藏 AI 服务、Provider、API Key 和 AI 路由等技术设置，保留桌面端的高级配置能力。
- 在移动首页提供绿色品牌 Logo、账号/设置入口、问视频主行动、资料状态和最近会话，减少解释性文案。
- 将反馈能力移入设置页，移除会遮挡内容与输入框的移动端悬浮按钮。
- 将回答模型在移动端呈现为简洁的“回答选择”，加载和切换状态不暴露内部模型术语；模型目录仍保留已发布选项和图标。
- 修正计划首页默认打开“今日”，一级视图统一为“今日 / 目标 / 复盘”，确保四象限、快速创建、删除确认和任务操作在手机上完整可见。
- 统一视频资料、研伴、知识、计划、设置、登录和原生弹层的白/灰视觉语言，主要触控目标不小于 44px，并覆盖 360px、390px、430px 常见视口。

## Capabilities

### New Capabilities

- `consumer-mobile-experience`: 定义普通用户移动端的信息架构、白色实色视觉语言、导航、设置、反馈、用户化文案、安全区和跨页面响应式要求。

### Modified Capabilities

- `clear-action-plan-workspace`: 明确移动端默认今日视图、目标命名、完整四象限和居中创建/确认交互。

## Impact

- 影响前端根布局、移动底部导航、Android 首页、设置页、反馈弹窗、研伴模型选择、计划工作区及相关 CSS Modules。
- 不改变后端 API、用户数据、视频同步、知识条目或计划数据结构。
- 不引入新的 UI 组件库；继续使用 React 19、Next.js 16、Phosphor/Lucide 和原生 `dialog`。
- 需要执行 TypeScript、Next.js 生产构建、Capacitor production export/sync，并进行 360/390/430 视口回归。
