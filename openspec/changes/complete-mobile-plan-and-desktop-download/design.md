## Context

计划中心已是独立主导航目的地，但当前移动样式仍以压缩桌面布局为主：页面顶部预留 4rem、目标卡片有多层信息列、悬浮按钮靠近底栏中部，删除确认使用自制弹层且缺少稳定的焦点闭环。桌面侧栏的底部区域只有设置、反馈和账号信息，没有跨设备下载入口。

## Goals / Non-Goals

**Goals:**

- 移动端首屏直接出现计划标题、状态和视图切换。
- 浏览计划、创建计划、添加任务、进入详情、打卡、编辑和删除都不被底栏、软键盘或安全区遮挡。
- 桌面侧栏左下方提供一键下载 Android APK 的固定入口。
- APK 使用生产 API，且版本、文件大小和发布时间与清单一致。

**Non-Goals:**

- 不新增计划字段、日历拖拽、系统通知或后台提醒。
- 不改变首页、视频、研伴和知识的业务结构。
- 不自动发布 APK 到线上或推送远程仓库。

## Decisions

1. **移动端使用紧凑工作台而非桌面缩放。** 移除无来源的顶部留白，摘要保持单行滚动，内部 Tab 作为轻量粘性分段控件。
2. **目标行改为纵向信息节奏。** 标题和状态优先，进度与下一步随后呈现；删除操作保留独立 44px 触控区。
3. **新增按钮固定在右下角。** 它位于底部导航上方并计入安全区，不与五项 Tab 或角标重叠。
4. **删除确认继续使用产品样式，但补齐对话框行为。** 打开时锁定滚动、限制焦点、支持 Escape、关闭后恢复触发元素焦点。
5. **桌面下载入口使用普通可信链接。** 固定指向 `/download/zhicui.apk`，保留浏览器/桌面壳的原生下载处理，避免引入额外下载状态。
6. **本地构建与发布分离。** 手动执行静态导出、Capacitor 同步和 Gradle 构建，更新产物与清单，但不调用会自动提交和推送的发布脚本。

## Risks / Trade-offs

- [五项底栏上方悬浮按钮占空间] → 固定于右侧 1rem 并预留底部内容空间。
- [移动端摘要过长] → 保持单行可滚动且隐藏滚动条，不挤压标题。
- [APK 构建环境缺少 Android SDK] → 先完成并验证 Web/Capacitor 静态导出；若 Gradle 环境不可用则保留旧 APK 并明确报告阻塞。
