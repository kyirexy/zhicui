## Context

知萃当前以 FastAPI、PostgreSQL、Next.js、Electron、Capacitor Android 和多个隔离采集 sidecar 组成。核心业务已在 `luxai.cn` 运行，但生产健康仍主要依赖进程存活和人工管理标志，客户端正式/内测渠道没有强制隔离，用户也缺少完整的数据权利入口。此变更跨越 Web、API、数据库、客户端发行与服务器运维，必须保持现有 JWT 用户隔离、手动同步和 React DOM ownership 约束。

## Goals / Non-Goals

**Goals:**

- 为用户提供可审计的协议同意、数据导出和账号删除闭环。
- 让备份、恢复、深度健康、告警、限流和安全头成为生产默认能力。
- 让连接器健康反映真实进程与协议探测，安全回填历史坏数据。
- 让官网在 320px 以上不横向溢出，并清楚区分 Web、Windows、Android 能力。
- 让正式发行 feed 只接受符合签名身份与完整性要求的包。
- 让部署只有在关键旅程和发行物验证通过后才成功。

**Non-Goals:**

- 不绕过抖音/B站验证码、私密、付费或平台风控。
- 不把 Android 更新做成静默安装；仍由系统浏览器和系统安装器确认。
- 不在仓库提交证书、keystore、密码、Cookie 或备份密钥。
- 不承诺本次完成 iOS 客户端或应用商店上架。
- 法律页面提供产品级数据事实与权利入口，但不替代执业律师最终审阅。

## Decisions

1. **账号删除采用重新验证、短确认令牌和服务端事务清理。** 用户先输入当前密码取得短时一次性确认，再执行删除；服务端以用户 ID 清理所有业务表和加密绑定，最后删除用户。相比仅前端二次确认，这能避免被劫持会话直接删除。

2. **导出采用即时 JSON 压缩包的流式下载。** 首版数据规模较小，可在受限查询中生成版本化 JSON；响应不包含密码哈希、加密密钥、平台 Cookie、临时媒体 URL 和服务器路径。大规模异步导出留待后续。

3. **深度健康与存活检查分离。** `/api/health` 保持轻量存活；新增受保护的 readiness 检查验证数据库、关键设置、任务租约与 sidecar。公开响应只给安全摘要，管理员响应给脱敏原因。

4. **告警使用数据库事件加可选 Webhook。** 复用现有错误日志和管理端，以冷却窗口聚合 critical、同步失败和 readiness 失败；配置了 HTTPS Webhook 才外发，不配置时仍在管理端形成未确认事件。避免强绑定第三方监控供应商。

5. **限流使用数据库/进程双层轻量策略。** 登录、注册、密码验证和 AI 高成本入口使用按 IP 与账号的滑动窗口；单机生产先以内存快速路径实现并记录审计，Nginx 再提供粗粒度保护。未来多实例时可换 Redis 而不改变 API。

6. **连接器健康以真实探测为准，管理员开关只决定是否允许。** 状态由 `enabled AND probe.ready` 得出；yutto 服务不存在、token 无效或协议握手失败时不得显示健康。yt-dlp 降级必须标明字段质量，不能冒充完整目录。

7. **历史回填是幂等、可预览、分批执行的管理任务。** 先统计缺失字段和可恢复来源，再小批刷新；无法确认唯一身份的占位项隔离为 `needs_action`，不复制、不误删用户资料。

8. **发行渠道使用显式 `beta`/`stable`。** 未签名 Windows 包和 Android Debug 包只能进入 beta 清单；stable 构建必须验证 Authenticode 或允许的 Android release 证书指纹。签名私钥只从本机/CI secret 注入。

9. **生产部署先备份、再切换、再做旅程闸门。** 在数据库结构或后端发布前创建加密备份并验证归档；部署后验证 readiness、登录边界、法律页面、关键路由、版本清单和下载哈希，失败则回滚应用并保留备份。

10. **官网响应式修复采用内容约束而不是隐藏。** 根布局禁止横向溢出，标题使用流体字号和可换行按钮，320/390/768/1440 四档做真实浏览器快照；不缩放整页、不裁切主要内容。

## Risks / Trade-offs

- [可信 Windows 证书和 Android 长期 keystore 属于外部凭据] → 构建/发布契约全部落地；没有凭据时稳定通道明确拒绝，继续保留可识别的内测通道。
- [账号全量删除不可恢复] → 强制密码重验、明确列出影响并记录不含内容的审计事件；备份按既定保留期自然淘汰且不用于普通恢复单个已删除账号。
- [备份包含敏感数据] → 0600 权限、独立目录、可选公钥/对称加密、校验和、保留策略与恢复隔离库。
- [平台实时探测可能短暂失败] → 区分 disabled、degraded、needs_action、unhealthy，使用短缓存和最后成功时间，不自动高频重试。
- [历史回填触发平台风控] → 只处理用户明确授权的来源，低并发分批、可取消、遵守冷却和墓碑。
- [单机限流不适合未来多实例] → 将键和策略封装，保留 Redis 替换点；当前部署是一台应用服务器。

## Migration Plan

1. 先发布兼容数据库新增字段、法律静态页面、导出与删除 API、readiness 和连接器探测；保持现有客户端可用。
2. 安装并验证备份 timer、告警配置、Nginx 安全头和真实 yutto sidecar；修正错误健康标志。
3. 以只读预览运行历史资料审计，再分批回填宣传账号和真实用户资料。
4. 构建 beta 客户端验证流程；注入正式凭据后生成 stable Windows/Android 产物并原子切换清单。
5. 执行浏览器、API、连接器、恢复和小并发冒烟；所有闸门通过后开放正式宣传口径。
6. 回滚时恢复上一版应用产物；数据库采用向后兼容字段，不回滚用户创建的数据，必要时从隔离恢复库人工核验。

## Open Questions

- Windows 可信代码签名选择 EV/OV 证书还是云端 Trusted Signing，由账号与预算决定。
- Android 正式包采用官网长期分发还是后续 Play/国内商店渠道；两者可以复用同一稳定签名身份。
- 隐私政策与用户协议上线后仍应由熟悉中国大陆互联网产品的律师复核主体名称、地址和投诉联系方式。
