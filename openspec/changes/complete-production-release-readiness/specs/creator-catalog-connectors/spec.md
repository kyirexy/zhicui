## ADDED Requirements

### Requirement: 目录健康必须来自真实运行探测
系统 SHALL 将管理员启用标志与真实连接器 readiness 分开保存，最终可用状态 MUST 同时满足已启用和协议探测成功；最后成功时间、降级来源和脱敏失败原因 SHALL 可见。

#### Scenario: 健康标志过期
- **WHEN** 数据库仍标记 B站全量已启用但 yutto 服务、端口或握手不可用
- **THEN** API 和界面显示连接器不可用或降级，不得显示完整健康

### Requirement: 降级目录不得冒充完整元数据
系统 SHALL 对 yt-dlp 等降级目录逐项标记字段质量；缺少标题、封面、作者、发布时间或简介时 MUST 显示待补全并禁止把占位内容标成准备转写。

#### Scenario: 降级只返回 BVID
- **WHEN** 降级连接器只能确认 BVID 而无法取得完整安全元数据
- **THEN** 项目保存稳定身份和待补全状态，不生成“B站作品 BV...”伪完整卡片

### Requirement: 历史目录质量可审计和幂等回填
系统 SHALL 提供只读预览及分批回填缺封面、缺作者、占位标题和过短文稿的管理任务，并 MUST 尊重用户隔离、墓碑、冷却与取消。

#### Scenario: 预览历史坏数据
- **WHEN** 管理员启动质量审计预览
- **THEN** 系统按平台和缺失类型返回聚合计数且不修改数据

#### Scenario: 分批回填
- **WHEN** 管理员确认一批可安全恢复的项目
- **THEN** 系统幂等更新字段、记录逐项结果且不复制资料或恢复已永久移除项目
