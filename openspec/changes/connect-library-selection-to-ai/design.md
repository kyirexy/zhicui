## Context

资料库用抖音 `aweme_id` 保存最多 50 条当前选择，Agent 线程则使用已持久化 Note ID。当前跳转链接只从已有文稿的选择项派生 Note ID，因此选择中只要存在尚未转写的视频，跳转就会静默缩小集合。Agent 能从 `source_ids` 恢复选择，但普通来源接口只返回当前范围前 100 条，较旧的入口来源可能没有可展示元数据；来源列表也没有按选择状态分组。

后端已经支持 `transcript`、`ai`、`full` 三种幂等批量操作。`full` 会按需完成 ASR 后生成结构化卡片；`transcript` 只补齐 Agent 所需文稿。两种路径都会逐条持久化 Note，并在任务结果中返回 Note ID。

## Goals / Non-Goals

**Goals:**

- 一个显式动作完成所选视频的结构化文案整理。
- “去问 AI”携带全部且仅携带动作开始时的选中资料，不允许成功子集静默跳转。
- Agent 面板完整展示入口带入的已选资料，并把已选组稳定放在未选结果之前。
- 处理期间保持选择和目标快照稳定，错误就近可恢复。

**Non-Goals:**

- 不增加鼠标拖拽框选、跨平台统一批量处理或新的持久化队列。
- 不改变 Agent 线程来源快照、100 条上限、提取并发上限或 Note 数据模型。
- 不实现来源列表的完整分页；只定向补齐本次已选来源。

## Decisions

### 1. 结构化整理复用 `full` 批量操作

“提取结构化文案”对动作开始时的选择快照调用一次 `full` 任务。这样后端负责按需复用已有文稿、补齐 ASR、生成结构化结果并保持 Note 幂等；前端不再串联两个容易产生中间状态的按钮。

备选方案是前端先发 `transcript` 再发 `ai`，但会增加一次任务交接、更多竞态和重复状态文案，且没有用户价值。

### 2. AI 交接只按需补文稿，并验证一一对应后跳转

“去问 AI”先快照全部选中项。已有可用文稿的项目直接使用其 Note ID；缺文稿项目提交 `transcript` 任务，并直接从最终任务快照读取新 Note ID。前端按原快照顺序合并 ID，只有每一项都有唯一 Note ID 时才跳转 `/agent?source_ids=...`。任何不可提取、失败、中断或缺失都会留在资料页并保留原选择。

不为“去问 AI”自动执行 `full`，因为 Agent 只要求可用文稿；额外生成知识卡会产生不必要的 LLM 工作。

### 3. 批量动作使用不可变选择快照

动作开始后禁用卡片复选、全选、清空和其他批量动作，同时业务函数仍只读取开始时复制的数组。UI 锁定减少误操作，快照从数据层消除事件边界竞态。

### 4. 来源接口定向返回入口已选元数据

`GET /api/agent/sources` 接受最多 100 个重复的 `include_id` 参数，并在现有响应中增加独立 `included_items`。服务只从当前用户拥有且文稿可用的 Note 中解析这些 ID，按请求顺序返回，不改变当前范围、搜索排序、`items`、`total` 或截断语义。

把定向结果独立返回而不是混入 `items`，可以避免“收藏/喜欢/搜索结果”数量与顺序被入口资料污染。前端把 `included_items` 写入来源 registry，供已选组稳定展示。

### 5. Agent 来源列表使用两个语义分区

来源面板先渲染按选择 Set 顺序派生的“已选”组，再渲染当前 `sources` 中排除已选项后的“未选/当前结果”组。已选组跨范围和搜索保持；未选组继续保持后端的来源顺序或搜索相关度。复选框仍是唯一选择语义，不新增拖拽或虚假操作。

## Risks / Trade-offs

- [批量任务部分成功] → 不用成功子集跳转；保留全部选择并显示成功/失败数量，用户可重试失败项。
- [入口 ID 已删除或不再有文稿] → `included_items` 不返回无权或不可用项；资料库交接完整性校验会阻止本地生成的缺项，Agent 后端继续做最终归属校验。
- [服务重启导致内存任务状态丢失] → 已完成 Note 仍逐条持久化，但前端将本次交接视为中断并停留，不猜测成功集合。
- [来源选择达到 100 条] → 定向补齐沿用 Agent 上限并去重，资料库自身仍限制 50 条。

## Migration Plan

1. 先部署向后兼容的来源 API 字段与参数；旧前端会忽略 `included_items`。
2. 部署资料库双动作和 Agent 分组前端。
3. 回滚时可仅回滚前端；新增查询参数和响应字段不会影响旧调用。
