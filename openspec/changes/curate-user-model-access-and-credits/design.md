## Context

知萃当前同时存在平台默认 LLM、OmniRoute 实时模型目录和用户 OpenAI Compatible 配置。桌面 Agent 会把大量实时模型与 `auto/*` 路由暴露给普通用户；视频分析已经实现统一萃点账户、只追加账本、免费额度和管理员调账，但普通聊天尚未接入。管理端已有 LLM 配置和 Provider 管理模式，可继续作为模型发布入口。

## Goals / Non-Goals

**Goals:**

- 管理员通过知萃 Web 管理端维护普通用户可见的聊天模型目录。
- 普通用户只选择管理员发布的具体模型，不存在“智能选择”或 `auto/*`。
- 至少支持一个免费模型，并让管理员配置免费次数和收费萃点。
- 保留用户自己的 OpenAI Compatible 模型，密钥只在后端解密使用。
- 复用现有萃点账户和账本，保证聊天扣费可审计、幂等且失败可退。

**Non-Goals:**

- 不把 OmniRoute 完整管理控制台复制到知萃前端。
- 不向普通用户暴露 Provider API Key、内部成本、API Base 或未发布模型。
- 首版不实现充值支付、订阅等级和复杂折扣。
- 首版不对 BYOK 收取平台模型萃点。

## Decisions

1. **用“管理员发布目录”替代实时全目录。** 新增 `ChatModelOffering`，保存用户展示名、真实模型、Provider 模式、启停/默认/免费状态、免费日额度、每次萃点、能力和排序。普通 API 只序列化安全字段。相比继续过滤 OmniRoute 实时目录，这能稳定产品名称、价格和权限。
2. **只允许明确模型，不保留智能路由。** 管理 API 拒绝 `auto` 与 `auto/*`；用户保存选择时必须引用一个启用的 Offering。已有 `omniroute + auto/*` 用户配置在读取时回退到管理员默认发布模型。
3. **复用 `UserAIProviderConfig` 保存用户选择。** `mode` 收敛为 `platform/custom`；平台模式的 `model` 字段保存 Offering ID，避免新增第二张用户偏好表。运行时由 Offering 解析真实模型与服务器端密钥。
4. **Provider 凭据仍由服务器配置持有。** Offering 首版支持 `platform`（现有 LLM 配置）与 `omniroute`（服务器环境）两种运行来源；管理端填写模型 ID，但不读取或回传密钥。
5. **复用统一萃点账户。** 聊天账本仍写入 `AnalysisCreditLedger`，通过 metadata 标记 `scope=chat`、Offering 和请求 ID。免费额度新增独立 `ChatModelFreeUsage`，不与视频分析次数混用。
6. **聊天采用固定每次价格。** 首版管理员配置 `points_per_request`，请求前预留，成功后全额结算，完全失败时释放。相比 Token 实时计价，这更易解释，也不依赖所有 Provider 正确返回 usage；后续可增加 Token 计价版本。
7. **免费额度优先。** 免费 Offering 在额度内不产生萃点预留；额度耗尽时返回明确错误，不偷偷切换到收费模型。
8. **桌面端保持一个紧凑选择器。** Agent 只展示发布模型的名称、免费/萃点标签和当前余额；自定义模型入口指向设置页，不与平台目录混成大量 Provider 分组。

## Risks / Trade-offs

- [固定每次价格无法精确反映长上下文成本] → 管理员可按模型设置保守价格；高成本视频分析继续走独立报价。
- [已有 OmniRoute 模型选择失效] → 读取时自动选择管理员默认模型，不执行自动路由。
- [SQLite 并发扣费能力有限] → 沿用现有事务和幂等键；生产 PostgreSQL 使用行锁。
- [管理端误发布无效模型] → 提供连接测试，并允许立即停用；普通用户只看到启用项。
- [免费模型被滥用] → 免费额度按用户与自然日记录，并继续沿用 Agent 请求频率限制。

## Migration Plan

1. 启动迁移创建 Offering 和免费用量表。
2. 若目录为空，从当前平台 LLM 配置创建一个“免费模型”种子 Offering。
3. 部署管理员目录 API，再部署用户目录与选择 API。
4. 更新管理端和桌面端选择器，移除 `/ai-routing` 的普通用户实时目录入口。
5. 若需回滚，保留表数据，恢复平台默认解析；账本为只追加记录，无需删除。

## Open Questions

- 首版免费额度默认值采用每日 30 次；管理员可以改为 0（不限额）或其他数值。
- 充值和套餐将在独立变更中实现，本变更只提供管理员发放萃点与消费基础。
