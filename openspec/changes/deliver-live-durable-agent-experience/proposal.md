## Why

深度研究 Turn 虽然能够持久执行，但当前会把多批文稿映射串行塞进一个长工具调用，最终回答也只在结束时一次性出现；用户在数分钟内只能看到空白的“正在生成”，与 Codex 和 DeepSeek Harness 的持续动作反馈存在明显差距。现在需要把已经持久化的真实事件变成可见、可恢复的执行体验，并压缩多视频研究的墙钟时间。

## What Changes

- 将深度研究的 transcript map 改为有界并发批处理，并为每个批次记录开始、完成、失败、覆盖数和耗时。
- 为规划、映射、综合建立阶段预算和受控降级，避免单个供应商请求让整个 Turn 长时间无反馈。
- 在 V2 Turn 中持久追加安全的答案增量事件，使首次文字尽早出现，并在刷新或重连后可按序重放。
- 在空白助手消息位置展示 Codex 式单行当前动作、已处理来源数、阶段耗时和取消入口；首段答案到达后平滑转为正文流式展示。
- 执行轨迹在整个 Turn 中默认保持单行，置于当前助手回答之前；只有用户主动操作才展开最近动作，不再让固定任务卡与正文争夺空间。
- 将首段和后续持久答案块统一限制为小块，配合流式光标形成连续书写感，而不是突然出现整段文字。
- 将持久答案块进一步收紧到 16–24 字，并让客户端以稳定阅读速度持续排空，避免每个 32 字事件在百毫秒内吐完后长时间停顿。
- 对最终综合上下文做分层 Reduce，避免再次提交大量原始文稿，同时保持 Claim/Evidence 校验边界。
- 单视频“核心观点”保持可验证的分点展开；明确索要“完整文案/全文”时直接返回已保存原文，不再让模型把全文概括成摘要。
- 仅在存在已核验依据时展示引用覆盖率，并把运行中的终止入口统一写成“停止生成”。
- 增加并发上限、事件顺序、断线重放、取消和无重复答案的回归覆盖。

## Capabilities

### New Capabilities
- `live-agent-execution-feedback`: 定义动作立即可见、答案增量展示、重连重放和空白态替换的客户端体验。

### Modified Capabilities
- `durable-video-research-agent`: 增加有界并发映射、阶段预算、批次事件和可恢复答案增量要求。

## Impact

- 后端：`agent_runtime_worker.py`、`agent_runtime_service.py`、`agent_tool_runtime.py`、`ai_juicer.py` 与 Agent SSE 路由。
- 前端：Agent SSE 类型/解析、`VideoAgentWorkspace`、消息视图和动作时间线样式。
- 数据：复用现有 `agent_events` 单调序号，不新增原始文稿、密钥或未校验模型结构落库。
- 运行：继续使用当前模型供应商与聊天计费；并发数和阶段预算保持服务端有界。
- 归属：借鉴 OpenAI Codex（Apache-2.0）和 DeepSeek Harness（MIT）的事件化执行与流式反馈模式，保留现有许可证及说明文件。
