## ADDED Requirements

### Requirement: 深度文稿映射采用有界并发
系统 SHALL 将独立 transcript map 批次以服务端限制的并发数执行，SHALL 在协调线程确定性归并结果，并 MUST 保持用户模型路由、用量归属、租约和取消边界。

#### Scenario: 三十七条来源形成八个 Map 批次
- **WHEN** deep Turn 开始跨来源映射
- **THEN** 系统同时执行不超过配置上限的独立批次
- **AND** 每个批次开始、完成或失败时追加包含批次序号、覆盖数和耗时的脱敏事件

#### Scenario: 并发批次乱序完成
- **WHEN** 后创建的批次先于早期批次返回
- **THEN** UI 可以按实际完成顺序显示事件
- **AND** 综合输入按原批次序号稳定归并

#### Scenario: 阶段预算在全部批次启动前到期
- **WHEN** Map 阶段达到配置预算
- **THEN** 系统停止启动新的批次并等待或终止有界的在途调用
- **AND** 最终覆盖统计明确记录未映射或失败来源，不宣称已分析全部来源

#### Scenario: 精确枚举问题使用聚焦深读
- **WHEN** 用户要求完整列出一个具体知识点但没有要求跨视频共识
- **THEN** 系统扫描冻结的全部来源并只映射相关性最高的有界来源集
- **AND** 不触发仅用于共同观点的跨来源整稿修复

### Requirement: V2 Turn 持久输出合并后的答案增量
系统 SHALL 将可见答案以有界字符块追加为单调 Turn 事件，SHALL 支持 SSE 重放，并 MUST 在完成、错误、取消或租约丢失边界 flush 或丢弃未提交缓冲。

#### Scenario: 供应商连续返回多个小 Token
- **WHEN** 综合模型产生连续可见字符
- **THEN** 首个非空增量立即提交
- **AND** 后续字符按有界块合并后提交而不是每 Token 写数据库

#### Scenario: 供应商首个回调包含整段正文
- **WHEN** 首次可见回调超过客户端平滑展示的字符预算
- **THEN** Writer 将首段和剩余内容统一切成小型有界块
- **AND** 任一持久 delta 通常保持在 16–24 个可见字符，不得包含整篇或数百字正文

#### Scenario: 结构化综合在 overview 后继续生成 claims
- **WHEN** 模型已关闭 `answer` 字段并继续流式生成 claim 的 `text` 与 `explanation`
- **THEN** 服务端将这些安全叙述字段投影为连续 Markdown 增量
- **AND** evidence、内部 JSON 与未公开结构字段不得进入临时正文

#### Scenario: 页面在生成中重新连接
- **WHEN** SSE 订阅从零或已确认序号恢复
- **THEN** 服务端按事件序号重放已提交答案增量
- **AND** 最终 `done` 仍只包含一个 canonical 助手消息

#### Scenario: Worker 在提交增量后失去租约
- **WHEN** 原 Worker 不再拥有 Turn 租约
- **THEN** 它不能继续追加增量或提交最终消息
- **AND** 新 Worker 可以依据已提交事件恢复或安全重试

#### Scenario: 取消与 Worker 同时追加事件
- **WHEN** 不支持行锁的开发数据库让两个写入者观察到同一事件序号
- **THEN** 系统依据唯一约束修复计数并有界重试
- **AND** 客户端不得收到数据库约束或事务栈信息

### Requirement: 深度综合使用有界分层上下文
系统 SHALL 优先使用 Map 阶段的结构化发现进行综合，只补充有界的高排名原文块，并 SHALL 使用完整冻结来源执行最终逐字引用校验。

#### Scenario: Map 已覆盖三十七条来源
- **WHEN** 系统进入最终综合
- **THEN** Prompt 不再无界重复包含全部原始文稿
- **AND** quote 校验仍能访问冻结的全部来源文本

#### Scenario: 部分 Map 批次失败
- **WHEN** 至少一个批次因超时或供应商错误失败
- **THEN** 综合使用成功批次和有界原文继续生成可证据支持的回答
- **AND** 回答元数据显示实际 mapped、failed 和 deep-read 数量

### Requirement: 单视频问答保留展开深度和原文语义
系统 SHALL 区分对单条视频的研究型概括与原文读取请求，SHALL 对研究型概括保留可验证的分点结构，并 MUST NOT 使用生成模型改写明确请求的完整原文。

#### Scenario: 用户询问单条视频的核心观点
- **WHEN** 当前范围只有一条视频且问题要求核心观点、主题或总结
- **THEN** 系统在证据允许时输出 3–5 个 fact/action 观点及逐字依据
- **AND** 不得把单一来源伪装成 recurring/common/trend，也不得在全部观点校验失败后只留下短 overview

#### Scenario: 用户索要单条视频的完整文案
- **WHEN** 问题明确要求完整文案、完整文稿、全文、全部字幕或完整转录
- **THEN** 系统逐字返回该视频已保存的完整原始文稿
- **AND** 不调用生成模型做摘要、扩写或改写
