## Context

笔记问答目前由 `POST /api/notes/{note_id}/ask` 接收问题和最近 6 条对话，`ai_juicer.answer_note_question()` 把标题、结构化摘要和有长度上限的转录交给 LLM。接口仅返回纯文本 `answer`，前端对话仅存在组件内存中。卡片详情由 `CardRenderer` 先渲染卡片、再在下方渲染 `ContentChat`；笔记详情页限制为 `max-w-2xl`，并关闭了已有的样式工具栏。

本变更跨越 FastAPI 服务、前端 API 类型、React 交互组件和响应式样式，但不需要新依赖或数据库迁移。所有问答仍必须经过用户所有权校验。

## Goals / Non-Goals

**Goals:**

- 让每次回答同时提供最多 3 条可由服务端在当前摘要或转录中核验的原文证据。
- 保留最近对话并支持模型生成的相关追问，让“这段内容里……”一类指代能够连续工作。
- 在桌面端把卡片与问答组织为主次明确的双栏工作区，在移动端保持自然的单栏阅读顺序。
- 降低 9 套主题的选择成本，按用途分组并按卡片内容类型标出推荐主题。
- 保持旧客户端对 `answer` 和 `grounded` 的兼容。

**Non-Goals:**

- 不生成或伪造视频时间戳；现有转录没有稳定的逐句时间信息。
- 不把聊天记录写入数据库，也不跨设备同步。
- 不引入全文向量检索、外部搜索或新的模型服务。
- 不重写 9 套卡片主题内部的动画系统。

## Decisions

### 1. LLM 返回结构化 JSON，服务端再次校验证据

问答模型被要求返回 `answer`、`evidence`、`grounded` 和 `follow_up_questions`。服务端只保留能在本次提供给模型的转录或摘要中找到的证据原文，并根据校验结果计算最终 `grounded`，不直接信任模型布尔值。

选择这一方案而不是让前端从答案中解析引用，是因为服务端掌握真实来源且能阻止伪造证据。若模型没有输出合法 JSON，服务端退化为兼容的纯文本答案、空证据和 `grounded=false`，不会使整个问答失败。

### 2. 证据使用原文摘录，不使用时间戳

每条证据包含 `quote` 和 `source`（`transcript` 或 `summary`）。当前数据模型只有整段转录，没有稳定时间码，因此界面明确标注“转录原文”或“卡片摘要”，不显示虚假时间定位。

### 3. 会话使用 sessionStorage 按 note_id 隔离

前端只保存有限数量的消息和结构化元数据到 `sessionStorage`，键名包含 `note_id`。刷新同一标签页可恢复追问，关闭标签页后自然清理；清空按钮同步删除存储。相比数据库持久化，这个方案不增加隐私和迁移成本，并符合本轮轻量连续问答范围。

### 4. CardRenderer 成为统一展示编排层

卡片主题组件继续只负责可导出的卡片本体。`CardRenderer` 在 `cardRef` 外增加工作区标题、操作区、主题工具栏和问答侧栏：桌面宽屏为双栏，窄屏及移动端为单栏。这样 PNG 导出仍只包含卡片，不会包含控制按钮或聊天内容。

### 5. 主题按用途筛选并基于内容类型推荐

9 套主题元数据保持不变，`StylePicker` 新增“全部、清晰阅读、视觉表达、专业呈现”筛选。推荐关系由前端静态映射完成，不调用模型；当前卡片上下文可标出推荐主题，独立样式页使用通用推荐。

## Risks / Trade-offs

- [模型偶尔返回无效 JSON] → 解析器支持代码围栏与纯文本回退，接口始终保留 `answer`。
- [模型轻微改写证据导致校验失败] → 优先严格子串校验；未通过时宁可不展示证据，避免把改写内容伪装成原文。
- [长转录中间部分未进入上下文] → 沿用现有首尾截断策略，并在 `grounded`/依据说明中反映可用来源；本轮不引入检索基础设施。
- [双栏压缩复杂卡片] → 只在足够宽的视口启用双栏，卡片列设置更高最小宽度，其他尺寸回退单栏。
- [sessionStorage 包含用户问答] → 数据仅在当前浏览器标签会话内，并限制消息数量；用户可一键清空。

## Migration Plan

1. 先部署兼容扩展后的后端响应，旧前端仍可读取 `answer` 和 `grounded`。
2. 再部署前端结构化问答和工作区布局。
3. 不需要数据库迁移或数据回填。
4. 回滚时可单独回退前端；后端新增字段不会影响旧客户端。
