## Context

`CardRenderer` 已经负责卡片样式切换、桌面高度控制、PNG 导出和右侧 `ContentChat`。完整文稿存在于同一个 `CardData` 中，但主要通过处理过程页或卡片“详细”密度访问，造成原始内容、AI 提炼和问答三个上下文彼此割裂。现有 `TranscriptViewer` 已提供搜索、复制和长文滚动能力，可以直接复用。

## Goals / Non-Goals

**Goals:**

- 在同一个结果工作台中通过页签切换 AI 知识卡片和原始内容，并默认展示知识卡片。
- 桌面端让右侧问答始终与左侧阅读上下文并列。
- 完整文稿可直接阅读、搜索和复制，同时保持页面总体高度可控。
- 首页新结果和知识库详情共享同一套结果结构。
- 保留卡片导出边界，原始文稿和问答不进入 PNG。

**Non-Goals:**

- 不复制或替换现有 AI 问答实现。
- 不新增媒体下载、ASR、文稿编辑或重新转写能力。
- 不依赖易过期的视频 CDN 地址实现强制内嵌播放。
- 不新增数据库字段或后端 API。

## Decisions

1. **扩展 `CardRenderer` 而不是另建结果页。** 首页、知识库详情和处理过程页已复用该组件；在组件内组合内容层、卡片层和问答层能避免三套布局漂移。
2. **新增独立 `ContentSourcePanel`。** 该组件只负责标题、来源、摘要、统计和全文，复用 `TranscriptViewer` 的交互；卡片渲染器继续负责布局与卡片状态。
3. **桌面采用“左侧页签阅读区 + 右侧问答”。** 左侧使用“知识卡片 / 完整内容”页签，每次只展示一个主阅读面板，默认选中知识卡片；右侧问答保持 sticky，不随页签切换卸载或重置。
4. **移动端沿用同一页签关系。** 知识卡片与完整内容不再上下重复堆叠，AI 问答自然排在当前页签面板之后；页签本身不使用横向滚动。
5. **页签遵循可访问交互。** 使用 `tablist`、`tab`、`tabpanel` 语义，维护 `aria-selected`、`aria-controls` 和键盘焦点，支持左右方向键以及 Home/End。
6. **全文与卡片导出隔离。** 新面板置于 `cardRef` 外，导出仍只捕获卡片。为避免“详细”卡片再次嵌入全文，传给卡片主题的展示数据移除 `transcript_raw`，全文统一由内容层承载。
7. **处理过程页显式关闭内容全览。** 该页已有独立视频信息和原始转录段落，使用新 prop 避免重复。
8. **不强制内嵌视频。** 来源地址可能是 B 站页面、公众号文章或短期 CDN；内容全览提供来源链接并显示平台推断，保证各平台行为稳定。

## Risks / Trade-offs

- [完整文稿抢占首屏、降低卡片可见性] → 默认选中知识卡片；完整文稿仅在用户切换页签后展示，并使用约 60dvh 的内部滚动区。
- [部分旧笔记没有全文] → 展示明确的“暂无可用全文”状态，并保留 AI 摘要与卡片。
- [来源平台无法可靠识别] → 仅基于 URL 做展示性推断，无法确认时使用“网络内容”，不影响功能。
- [知识卡片详细密度不再重复全文] → 更新密度说明为卡片细节，完整全文固定由内容全览承载。

## Migration Plan

无需数据迁移。上线后现有 `CardData` 自动进入新布局；处理过程页通过 prop 保持原有结构。回滚时移除内容面板和 prop，并恢复原来的卡片布局即可。
