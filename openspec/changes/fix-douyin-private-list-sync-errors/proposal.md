## Why

同一抖音登录态的对照实测证明账号确有喜欢作品，但知萃当前连接器会把上游 HTTP 403、风控或缺少收藏会话字段压缩成“检查 0 条、同步成功”，使用户误以为列表为空且可能反复重试加重风控。现在需要让喜欢列表走已验证可用的读取路径，并让收藏受限状态成为可恢复、可理解的用户操作状态。

## What Changes

- 为抖音喜欢列表增加经真实账号验证的私有列表读取适配与安全回退，不再把 403 当作空列表。
- 在同步前验证收藏所需的浏览器会话字段（包括 `UIFID`）；缺失时直接返回需要重新捕获登录态的用户操作提示。
- 统一分类 401/403、验证码、登录失效、缺少签名上下文与真实空列表，并把分类结果传递到同步任务和前端。
- 修正同步汇总：受限或异常来源计入失败/需处理，不得显示为成功检查 0 条。
- 对连接器日志和诊断字段做脱敏，禁止记录 Cookie、令牌、签名查询参数或完整私有请求 URL。
- 保持手动同步、每次最多 100 条及已有资料不丢失的现有产品约束。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `douyin-library-sync-control`: 增加私有列表读取的错误分类、登录态前置校验、准确同步汇总和安全诊断要求。

## Impact

- 后端抖音账号连接、私有列表提取、同步任务状态与 API 响应。
- 桌面/Web/移动共用的视频同步弹窗及用户提示。
- 连接器契约测试和同步回归测试。
- 不改变数据库中的媒体保存策略，不新增自动同步，也不自动触发 AI 生成。
