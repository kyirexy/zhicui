## Context

知萃由同一套 Next.js 客户端同时服务普通浏览器、Capacitor Android 与 Electron Windows。普通浏览器根路由是公开官网，而两种安装客户端的根路由是个人工作台。当前 `AuthGuard` 将 `/` 无条件视为公开路由，`DesktopAppFrame` 又只依据路由而非账号状态渲染桌面导航，因此客户端未登录时会先出现工作台外壳。Electron 安装版直接加载 `https://luxai.cn`，远端网页更新不要求重装，但已打开窗口没有构建版本检测；原生更新器配置指向尚未提供 Release 产物的 GitHub feed。

## Goals / Non-Goals

**Goals:**

- 在 Android 与 Windows 客户端中，以认证恢复结果作为工作台壳层的唯一放行条件。
- 未登录客户端直接显示现有的统一登录/注册页，保持原目标页回跳。
- 普通浏览器官网继续公开。
- 对远端网页部署提供低干扰、可回退的构建版本检测和刷新机制。
- 让 Windows 原生更新检查可持续运行，并明确可部署的更新 feed 契约。

**Non-Goals:**

- 不做 JavaScript 绕过应用商店或操作系统安装器的原生代码热替换。
- 不把管理后台或用户数据接口改为公开。
- 不在用户编辑、流式生成或下载期间无条件强制刷新。
- 本轮不代替发布者生成代码签名证书或向外部渠道发布安装包。

## Decisions

1. **根路由的公开性由运行环境决定。** 普通 Web 的 `/` 仍公开；当 Electron runtime 已确认或 Capacitor Android 已确认时，`/` 与其他工作台路由同样需要账号。这样不复制第二套首页，也不破坏官网获客路径。

2. **壳层在认证结果之前保持中性。** `DesktopAppFrame` 仅在 runtime 已确认、认证恢复完成且存在用户时渲染侧栏；Android 的头部、底部导航和后台调度器同样在登录后出现。认证页保持稳定挂载，不使用临时 Portal 或手工移动 React DOM。

3. **开发免登录改为显式开关。** 自动 `/api/auth/dev-session` 只在明确启用的环境变量下运行；默认本地启动也展示真实登录/注册，以便开发行为与安装版一致。

4. **网页更新使用版本探测而非任意脚本热替换。** 构建时生成公开、无敏感信息的版本标识。安装客户端在可见、聚焦时及低频间隔请求该标识；发现变化时，若页面没有声明忙碌状态则刷新，否则显示用户可控的刷新提示。哈希静态资源继续长期缓存，版本标识与 HTML 禁止陈旧缓存。

5. **原生更新继续使用操作系统安装流程。** Electron 启动后检查、窗口重新聚焦时检查并按小时低频检查；更新自动下载，下载完成后提示用户重启安装。发布 feed 采用可控的 `luxai.cn` generic 目录，必须原子上传 `latest.yml`、版本化 EXE 与 blockmap，最后切换清单。

6. **发布能力与本地实现分阶段验收。** 本轮可完成客户端检测、门禁、调度和发布脚本/配置；只有真实上传新版本产物后，线上 Windows 自动更新端到端才算发布完成，不能用网页 JSON 清单冒充 electron-updater feed。

## Risks / Trade-offs

- [客户端环境识别需要一次异步解析，可能短暂空白] → 使用品牌化、无工作台信息的认证恢复画面，并避免渲染业务 Provider 的请求型组件。
- [自动刷新可能丢失未提交内容] → 默认发现新版后提示刷新；仅在明确安全状态才自动刷新，并在 focus 事件中去抖。
- [旧桌面版本仍指向 GitHub feed] → 新 feed 配置只能随下一次手工安装的新版本生效；首次迁移需提供一个新的完整安装包。
- [未签名 Windows 安装包触发 SmartScreen] → 下载页保留安全提示；正式发布前应采用稳定代码签名证书。
- [开发免登录习惯被改变] → 保留显式环境变量开关，自动化或个人开发需要时可开启。

## Migration Plan

1. 部署前端认证门禁、版本标识与缓存规则，验证普通官网仍公开。
2. 构建 Android 客户端，验证首次启动、失效 token、登录、注册和退出。
3. 将 Electron 更新 provider 切换到受控 generic feed，bump 版本并生成三件套产物。
4. 原子发布 EXE/blockmap/latest.yml，先用测试客户端验证，再更新公开下载清单。
5. 如网页版本检测异常，可停止发布版本标识或关闭客户端检测；如原生 feed 异常，回滚 `latest.yml` 到上一稳定版本。
