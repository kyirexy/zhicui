## Context

知萃通过固定版本的 `jiji262/douyin-downloader` sidecar 读取当前用户的抖音收藏、喜欢和本人作品。连接器健康与 Cookie 有效只证明进程和登录会话可用；收藏端点仍可能返回 HTTP 200、正文 `blocked`。现有同步把该结果直接判为失败，缺少通道回退、冷却窗口和可观察的来源级状态。

实现必须继续保持用户作用域隔离、metadata-only、回环访问和敏感字段不落库。浏览器仅可复用当前用户自己建立的会话，不得共享 Cookie、绕过验证码或持续对平台重试。

## Goals / Non-Goals

**Goals:**

- 让收藏读取在轻量 API 被明确阻断时自动尝试一次后台真实页面通道。
- 用按用户、按来源的熔断状态阻止连续无效请求，并给出准确的下次可重试时间。
- 将连接器健康、账号登录和收藏可读性拆成可诊断状态。
- 让收藏失败不影响喜欢和本人作品，并保持已有资料不变。
- 对所有新增响应和日志执行字段允许列表及错误脱敏。

**Non-Goals:**

- 不保证抖音收藏在所有账号、地区或时段均可读取。
- 不绕过验证码、私密、付费或平台访问控制。
- 不引入第二套抖音采集核心，不持久化视频媒体。
- 不通过高频轮换指纹、代理或账号规避平台限制。

## Decisions

### 1. 在 sidecar 内实现双通道编排

收藏任务先调用已有 `get_user_collection`。只有检测到 `blocked`、Argus 拒绝、护航域空响应或同类结构化风险错误时，才进入浏览器回退。普通网络错误仍走现有有限重试，认证错误直接标记需要用户处理。

选择 sidecar 而不是 FastAPI 控制浏览器，是因为 Cookie 和浏览器上下文必须留在隔离边界内。FastAPI 只消费脱敏后的任务状态。

### 2. 回退复用持久登录上下文，但按任务新建页面

浏览器回退使用当前作用域 Cookie 创建无界面 Chromium context，打开官方收藏页并监听页面自身产生的 `listcollection` XHR。每个任务使用独立 page，任务结束关闭 page/context；Cookie 仍由现有作用域存储管理。若页面出现登录、验证码或安全验证，立即停止并返回 `needs_action`。

不注入自制签名请求作为首选，因为当前 Argus/UIFID 校验已证明静态签名不稳定；也不把浏览器设为每次同步的默认路径，以控制资源和平台访问频率。

### 3. 采用内存熔断并返回确定的冷却时间

sidecar 以作用域摘要和 `collection` 来源作为键保存熔断状态。一次 API 阻断且浏览器回退失败后进入冷却；默认首次 15 分钟，连续失败指数增加，上限 6 小时。成功读取后清除失败计数。熔断状态不包含 Cookie 或用户标识原文，进程重启后允许重新探测一次。

熔断期间收藏请求立即返回结构化 `source_blocked`，不访问抖音；喜欢和本人作品使用不同键，不受影响。

### 4. 统一结构化诊断契约

任务和即时错误返回 `error_code`、`source_mode`、`channel`、`fallback_attempted`、`retry_after_seconds`、`needs_action` 和安全的 `message`。允许的 `error_code` 包括 `source_blocked`、`verification_required`、`session_expired`、`network_error` 和 `connector_error`。原始 HTML、Cookie、请求头、签名参数和媒体 URL不得进入响应或日志。

### 5. 前端按来源展示状态

“已连接”继续描述账号会话。收藏受限时在收藏选项旁显示“暂不可读取”和预计可重试时间，同时保持喜欢、本人作品及其同步按钮可用。同步组合含收藏时，后端返回收藏失败与其他来源结果，前端不把整个账号显示为断开。

## Risks / Trade-offs

- [页面结构或 XHR 形态变化导致浏览器回退失效] → 将响应识别和字段清洗集中在适配器，并通过契约测试固定成功、空结果和验证页三种情况。
- [Chromium 增加内存和启动延迟] → 只在明确 API 阻断时回退，限制同一作用域单飞并设置总超时。
- [后台浏览器仍触发平台验证] → 立即停止、进入冷却并提示用户稍后再试，不自动循环。
- [sidecar 重启丢失熔断状态] → 接受重启后单次探测；不为短期风控状态新增含用户关联的持久数据。
- [组合同步产生部分成功] → 以来源级结果呈现，已成功项目照常入库，失败来源不回滚。

## Migration Plan

1. 扩展 sidecar 契约和测试，默认关闭浏览器收藏回退。
2. 更新 FastAPI 适配器和前端，使其兼容新旧 sidecar 响应。
3. 部署新 sidecar，健康检查确认新 capability 后开启回退。
4. 用小账号分别验证收藏成功、`blocked`、验证码和熔断路径。
5. 如需回滚，只关闭回退开关；旧 API 路径和现有 Cookie/资料均保持可用。
