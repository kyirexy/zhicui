## Why

当前视频问答把“有依据”错误地等同于“只能复述原文”：即使用户明确要求随便生成一个示例，Agent 仍反复回答“原内容没有给出”，导致连续追问无法完成正常的创作任务。右侧问答面板的输入框还会随消息区滚动，长对话时需要回到底部才能继续输入。

## What Changes

- 为单视频问答增加意图自适应行为：事实问题继续严格核对原文；示例、改写、扩写、头脑风暴等创作请求可以基于原文和用户要求生成新内容。
- 创作型回答必须明确区分“原文事实”和“AI 生成示例”，不得把生成内容伪装成原文证据。
- 连续追问必须结合最近对话理解指代与用户纠正；当用户明确要求“随便给一个”时直接执行，而不是重复来源缺失提示。
- 保留服务端逐字证据校验，生成内容本身不进入原文证据列表，也不错误标记为完全有原文依据。
- 将右侧问答面板改为固定头部、独立滚动消息区和常驻底部输入区；桌面与移动端均保持输入框可见并考虑安全区。

## Capabilities

### New Capabilities

- `adaptive-grounded-chat`: 覆盖事实核对与创作辅助双模式、连续追问服从、证据标注边界，以及右侧问答输入区的常驻布局。

### Modified Capabilities

无。

## Impact

- 后端：`backend/app/services/ai_juicer.py` 的单视频问答提示词、结构化响应和降级行为。
- 前端：`ContentChat` 及其全局样式，可能补充回答状态文案但保持既有 API 字段兼容。
- API：`POST /api/notes/{note_id}/ask` 保留现有请求与响应结构，不涉及数据库迁移。
- 测试：增加“事实缺失应拒绝”和“明确要求示例应生成”的定向回归，并验证桌面/移动端输入框常驻。
