## Context

公开官网既承接营销流量，也承担首次体验和客户端下载入口。现有应用已经支持多平台内容整理、知识卡片和行动计划，但访客需要看到具体结果才能判断价值。当前项目使用 Next.js 16 与 React 19，公开浏览器首页和安装客户端认证入口具有独立边界，且既有下载状态必须保持真实。

## Goals / Non-Goals

**Goals:**

- 用具体的输入片段、整理步骤和输出结构解释产品，降低首次理解成本。
- 让访客无需登录即可操作示例，并清楚区分展示内容和实时处理。
- 提供舒服、易读、适应手机的视觉层次与完整行动路径。
- 通过构建和真实浏览器核验后按现有安全流程部署。

**Non-Goals:**

- 不新增提取算法、业务 API、用户数据收集或付费投放系统。
- 不伪造用户评价、节省时间统计、用户量、提取速度或平台支持。
- 不构建或宣称本次发布新的原生客户端能力。

## Decisions

1. **优先使用可操作的网页示例。** 用 React 状态控制固定演示内容、来源与结果视图，支持重复操作，避免展示实时请求的假象。相较只有静态装饰图，访客能主动查看结果；相较首屏大型自动播放 GIF/MP4，文本仍可读、可复制、可访问，初次加载成本更低。后续真实录屏可作为补充资产。
2. **来源与示例身份随内容展示。** 可核验的公共来源显示作者、标题或来源链接；自编内容显示“演示示例”等明确标签，不把编造的文字归给真实作者，也不把手工编排的结果标成实际提取记录。演示不访问私有用户笔记。
3. **采用一个主要行动和一个次要行动。** 首屏主要行动进入客户端下载区，次要行动定位到示例；下载信息放在独立的跨设备介绍区域，避免多个同等强调的按钮竞争。
4. **移动端介绍保持可兑现。** 以手机内可使用的知识卡片、阅读与行动场景说明价值，同时提供真实下载状态。沿用现有 Android/Windows 内测入口、iOS 未开放说明和 Mac 测试状态。
5. **交互遵守 React DOM 所有权与动态偏好。** 使用稳定挂载的组件和状态驱动视图，避免临时 body Portal 或手工操作 React 元素。按钮具有明确名称、焦点反馈与足够点击面积；减少动态偏好下直接呈现可读状态。

## Risks / Trade-offs

- [示例被误认为实时 AI 或客户案例] → 在输入和结果附近保留示例标签、来源说明，不使用虚构性能或社会证明数据。
- [视觉调整破坏手机浏览和下载入口] → 在桌面与手机窄屏验证首屏、示例切换、内容完整性和现有下载状态。
- [过重动态内容影响体验] → 优先使用文本和 CSS 展示，动态效果保持轻量，并支持减少动态偏好。
- [线上切换失败或包含不相关变更] → 检查本次提交范围，使用既有隔离构建和回滚部署流程，部署后核验实际页面与服务健康。

## Migration Plan

1. 完成首页组件、文案、样式与本地演示内容，保持路由和认证行为兼容。
2. 执行生产构建，使用真实浏览器核验桌面、手机、示例交互、主要入口和减少动态效果。
3. 通过现有生产发布流程部署；确认新版首页内容、设置页和后端健康接口可用。
4. 若新版本无法正常提供服务，使用现有发布回滚机制恢复上一版产物。
