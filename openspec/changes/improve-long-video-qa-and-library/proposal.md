## Why

当前长视频问答只保留转录开头和结尾，用户询问视频中段细节时可能得到“没有提到”的错误判断。知识库列表也缺少搜索、类型筛选和视觉层级，笔记数量增加后很难快速找到或辨认内容。

## What Changes

- 将长转录从固定首尾截断升级为问题相关的分段检索，在有限上下文中优先提供与当前问题及最近追问最相关的文稿片段。
- 为转录证据增加原文大致位置百分比，让用户知道依据来自视频文稿的前段、中段还是后段，不伪造时间戳。
- 扩展用户笔记列表 API，支持按标题关键词和卡片类型进行用户范围内的服务端筛选与分页。
- 重设计知识库列表，增加搜索框、类型筛选、结果统计、主题缩略预览和更清晰的空状态。
- 保持现有问答和笔记列表调用兼容；未传筛选参数时行为不变。

## Capabilities

### New Capabilities

- `question-aware-transcript-retrieval`: 对超长转录进行问题相关的分段选择，并返回可核验的证据位置。
- `searchable-visual-library`: 在用户自有知识库中进行服务端搜索、类型筛选和带主题预览的响应式浏览。

## Impact

- 后端：`ai_juicer.py` 的转录上下文构建与证据定位，`note_service.py` 和 `/api/notes` 的筛选查询。
- 前端：笔记 API 类型、`notes/page.tsx`、新增知识库卡片组件以及相关全局样式。
- API：`GET /api/notes` 新增可选 `q` 与 `card_type` 参数；问答 evidence 项新增可选 `position_percent`。
- 数据与依赖：不修改数据库结构，不新增第三方运行时依赖。
