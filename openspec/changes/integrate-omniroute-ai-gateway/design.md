## Context

知萃的 LLM 调用统一经过 LiteLLM，并已经有每用户 `platform/custom` 配置、Fernet 加密密钥和连接测试。OmniRoute 是一个独立的 Next.js/Node 网关，提供 OpenAI 兼容 `/v1` 接口、`auto` 模型、多供应商回退和自己的管理面板。将其代码直接合并进 FastAPI 或知萃前端会破坏升级边界，也会让 OmniRoute 的管理权限暴露给普通用户。

## Goals / Non-Goals

**Goals:**

- 保留 OmniRoute 上游源码、MIT 许可证和固定提交，能够独立升级。
- 允许服务器管理员配置一个只在后端可见的 OmniRoute 地址、访问密钥和默认模型。
- 用户可以选择平台基础 AI、平台托管 OmniRoute 或自己的 OpenAI 兼容供应商。
- 左下角入口打开独立 AI 路由工作台，移动端保持完整可用。
- 用户可以搜索网关实时返回的可用模型，并通过一次点击把具体模型保存为自己的有效 AI 配置。
- 管理员仍能进入 OmniRoute 完整高级控制台，普通用户只使用知萃提供的安全功能面。
- 不配置 OmniRoute 时，现有基础 AI 和自带供应商路径完全不受影响。

**Non-Goals:**

- 不在知萃前端复制 OmniRoute 的系统级密钥、供应商账号、代理、审计等管理实现。
- 不把 OmniRoute 管理密码、供应商凭据或内部 API Key 下发到浏览器。
- 不承诺第三方免费额度、模型在线率或供应商服务条款。
- 不在本次变更中自动部署、开放公网端口或修改生产 Nginx。

## Decisions

1. **OmniRoute 保持独立 Git 工作树。** 使用 `integrations/OmniRoute` 和 `.gitmodules` 记录上游 URL，知萃不修改其源码。相比复制少量路由代码，这能保留许可证、审计历史和独立升级能力。
2. **采用服务器侧托管模式。** `OMNIROUTE_API_BASE`、`OMNIROUTE_API_KEY` 和 `OMNIROUTE_MODEL` 由知萃后端环境提供。普通用户只看到“可用/未启用”，不会获得共享网关密钥。
3. **复用现有用户配置表。** `mode` 扩展为 `platform/omniroute/custom`；OmniRoute 模式不新增用户密钥字段，运行时从服务器环境解析。自带供应商仍使用原有加密列。
4. **通过 LiteLLM OpenAI 兼容适配调用。** OmniRoute 运行时模型使用 `openai/<model>`，API Base 指向 `/v1`。这样摘要、知识问答和视频 Agent 继续复用现有调用链。
5. **网关未配置时禁用选项而非伪装可用。** API 返回 `omniroute.available`；前端显示部署状态和明确说明。已选择 OmniRoute 后若管理员撤销配置，运行时安全回退到知萃基础 AI。
6. **管理面板不对普通用户开放。** Compose 默认只绑定 `127.0.0.1:20128`；管理员高级控制台地址由独立环境变量提供，并继续使用 OmniRoute 自身认证。普通用户 API 不返回该地址。
7. **新增独立工作台并保持单一主流程。** “AI 路由”链接到 `/ai-routing`。工作台默认只展示“当前模型、搜索、可用模型列表”，整行点击即保存；供应商、自有 API Key 和高级控制台只保留页面底部次级入口，避免用户先理解路由策略和目录分区。
8. **后端提供只读安全适配层。** 浏览器不直接访问 OmniRoute，也不携带共享密钥。FastAPI 仅代理健康、模型目录、免费层、免费供应商排行和自动路由等允许字段，并对短时结果缓存；异常统一转成知萃错误文案。
9. **每用户保存实际模型选择。** OmniRoute 模式使用现有 `model` 列保存实时目录中的模型 ID；后端继续兼容已有 `auto`、`auto/*` 记录，但普通工作台不把自动路由作为并列选择项。运行时优先使用用户值，空值才回退服务器默认模型。

## Risks / Trade-offs

- [OmniRoute 上游体积较大] → 保持独立子模块边界，不把依赖安装到知萃前端。
- [管理员误把管理面板暴露公网] → Compose 默认只监听 loopback，文档明确使用 SSH 隧道。
- [共享 OmniRoute 密钥被前端泄露] → API 只返回可用性、模型和能力描述，密钥只存在后端环境。
- [OmniRoute 被撤下时用户配置失效] → `effective_config` 检测可用性并回退平台配置。
- [模型目录很大或网关响应慢] → 后端限制返回条数、去重并短时缓存；前端仅展示可用真实模型，使用搜索和渐进展示，不增加多层筛选。
- [共享用量被误认为个人用量] → 普通用户只展示免费池目录总量与网关状态，不展示全站请求或费用明细；个人计量留待 scoped key 方案。
- [第三方免费额度变化] → UI 使用网关实时数据并显示目录更新时间，不将额度写死为产品承诺。

## Migration Plan

1. 拉取并固定 OmniRoute 上游源码。
2. 部署 OmniRoute 到仅本机监听的容器，创建独立访问密钥。
3. 在知萃后端配置三个 `OMNIROUTE_*` 变量并重启后端。
4. 使用用户设置页连接测试验证，再允许用户选择 OmniRoute。
5. 回滚时清空 `OMNIROUTE_API_BASE`/`OMNIROUTE_API_KEY`；已选择用户自动回退基础 AI，数据库无需迁移。
