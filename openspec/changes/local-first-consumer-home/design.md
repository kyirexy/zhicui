## Context

桌面首页目前并发读取视频、知识、计划和统计接口，等全部请求结束后才展示内容；页面上方又把这些结果重复成四个指标。项目已经具备 Electron 视频文件本地保存和 `localStorage` 设备偏好，但没有用于首页近期内容的按用户快照。

## Goals / Non-Goals

**Goals:**

- 首页先服务“继续使用”，而不是展示管理统计。
- 用户开启本地数据后，首页可立即恢复最近一次成功内容，再在后台更新。
- 本地快照与设置均按设备持久化，快照按用户隔离且可清除。
- 明确区分轻量结构化快照、本地视频文件和账号云端数据。

**Non-Goals:**

- 不把浏览器缓存升级为离线数据库或数据唯一来源。
- 不缓存完整文案正文、AI 密钥、认证凭据或视频二进制。
- 不修改现有后端数据模型、鉴权和同步 API。
- 不承诺完全离线编辑计划或知识。

## Decisions

1. **首页直接移除统计条。** 不用另一组卡片替代，而是让“继续整理”和“今天要做”紧接欢迎区。统计仍保留在计划中心等需要数据判断的专业页面。
2. **使用版本化、按用户命名的 `localStorage` 快照。** 快照规模小、结构简单，复用现有设备存储能力即可；相比 IndexedDB 更易迁移和清除，也无需新增依赖。
3. **本地优先但不阻塞网络刷新。** 页面挂载时先恢复快照并结束首屏骨架，随后并发读取 API；成功数据覆盖快照，部分失败继续保留可用内容。
4. **只缓存首页所需最小字段集合。** 每类最多保存首页正在展示的条目，避免完整文案、长摘要和大量列表占满浏览器配额。
5. **设置提供一个默认开启的“在当前设备保留最近内容”开关和清除动作。** 关闭时立即删除全部首页快照并停止后续写入；视频文件继续由现有“本地视频”设置单独管理。

## Risks / Trade-offs

- **[本地内容可能短暂过期]** → 页面恢复后立即后台刷新，并在缓存中保存更新时间，不把快照描述为实时云端数据。
- **[共享电脑上的隐私风险]** → 快照按用户 ID 隔离，用户可随时清除；只保存首页最小字段，不保存完整文案正文。
- **[浏览器存储不可用或已满]** → 所有读写失败静默回退到当前网络加载，不影响主要功能。
- **[“本地优先”被误解为完全离线]** → 设置文案明确说明账号内容仍同步到服务端，本机仅保留近期副本；视频文件由另一项设置控制。

## Migration Plan

新增设置字段由 `DEFAULT_USER_SETTINGS` 自动补齐为开启状态，旧用户无需迁移操作。新快照采用独立版本前缀；回滚代码不会读取该键，用户可通过设置清除或由后续版本清理。

## Open Questions

无。本次只实现首页近期副本；完整离线知识库如需支持，应作为单独的数据架构变更。
