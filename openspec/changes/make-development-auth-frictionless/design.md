## Context

本地后端已有受 `DEV_AUTH_BYPASS` 和回环地址双重保护的开发会话接口，前端也会在首次挂载时调用一次。但一次性调用无法覆盖后端启动稍慢、JWT 失效或开发者主动退出等情况，登录页又没有直接重试入口。生产环境仍必须维持邮箱/用户名加密码的标准认证。

## Goals / Non-Goals

**Goals:**

- 本地开发页面启动后无需输入即可获得标准 JWT 会话。
- 自动申请暂时失败时可恢复，最终仍失败时提供一键重试。
- 开发者可以主动切换到普通登录/注册流程做认证测试。
- 所有开发捷径同时受后端开关、回环地址和前端构建模式约束。

**Non-Goals:**

- 不删除生产登录、注册或 JWT 校验。
- 不在前端打包长期有效的 JWT。
- 不引入新的用户表、会话表或第三方认证依赖。
- 不让任意账号绕过密码校验。

## Decisions

1. **复用标准 JWT，不写死令牌。** 开发会话端点创建或复用保留账号后调用现有 `create_token`。相比写死 JWT，这能继续经过 `/auth/me` 和所有用户隔离逻辑，也不会受签名密钥变化影响。
2. **固定开发账号身份，但以一键端点为主要入口。** 保留账号使用稳定邮箱和用户名；每次开发会话请求都会恢复 `is_active` 和管理员状态。前端不要求开发者知道密码，避免将“免输入”退化为预填表单。
3. **共享开发会话动作。** `AuthContext` 暴露一个显式的 `enterDevelopmentSession`，启动恢复和登录页按钮使用同一请求、持久化及错误处理逻辑，避免两套状态漂移。
4. **自动流程只做有限重试。** 开发构建在首次恢复失败时短间隔重试，覆盖后端刚启动的常见竞态；达到上限后停止，登录页保留手动一键入口，避免无限网络循环。
5. **生产采用多层拒绝。** 后端必须同时满足开发开关和回环来源；前端仅在 `NODE_ENV=development` 展示或触发开发入口。任意一层不满足都回到现有普通认证。
6. **跳转只接受站内路径。** `redirect` 参数必须以单斜杠开头，其他值统一回退到首页。

## Risks / Trade-offs

- [开发账号拥有管理员权限，可能误操作本地数据] → 仅在本机开发开关下创建，并使用醒目的开发模式提示。
- [后端未启动时自动重试会让进入页面稍慢] → 使用少量短间隔重试，失败后立即显示可操作的一键入口。
- [开发者退出后刷新又自动登录] → 这是当前“开发阶段一直不用登录”的预期；不刷新时仍可在登录页测试普通认证。
- [错误配置把开发开关带到公网] → 后端额外强制回环来源，生产启动方式不设置该开关。

## Migration Plan

无需数据库迁移。部署代码后重新启动本地前后端即可；生产部署保持 `DEV_AUTH_BYPASS=false`。回滚时删除新增的前端入口和重试逻辑，原有普通认证不受数据影响。
