## Context

知萃 Windows 客户端已经使用 Electron、`playwright-core` 和系统 Chrome/Edge 为 B站、小红书保存按知萃用户隔离的本机 profile，并通过窄 IPC bridge 返回作品链接。抖音仍使用另一条链路：桌面端只完成临时扫码并把 Cookie 交接到生产 sidecar，喜欢和收藏最终从腾讯云 IP 读取。生产审计已确认有效登录下仍会在约 13 秒后返回 `risk_controlled`，因此继续加固云端签名无法提供稳定承诺。

现有抖音资料页依赖 sidecar manifest 展示元数据，来源台账只保存作品标识、来源模式和顺序；本地连接器返回的作品需要一个用户隔离、metadata-only 的服务端快照，才能在不上传 Cookie 的前提下继续复用资料列表、文稿提取和跨端使用。

## Goals / Non-Goals

**Goals:**

- 在 Windows 本机使用持久化官方 Chrome/Edge 会话读取抖音喜欢、收藏和自己的作品。
- 已登录时手动同步不主动弹出页面；只有登录、验证码、页面结构变化或平台验证需要用户处理时才显示官方页面。
- Electron 渲染进程和服务器永远不接触抖音 Cookie、LocalStorage、签名参数或 profile 路径。
- 用新的用户级 metadata snapshot 接收最多 100 条本地发现结果，并与现有抖音资料列表、来源台账、隐藏机制和批量文稿任务合并。
- 保留旧客户端和公开博主能力，允许安全渐进发布与回滚。

**Non-Goals:**

- 不保证绕过抖音验证码、私密访问控制或任何平台风控。
- 不在 Web 或 Android 中读取其他应用、系统浏览器或抖音 App 会话。
- 不自动定时同步、不自动重试风控、不在登录后后台持续监视平台。
- 不把 Python 下载器或完整 Chromium 打入 Electron 安装包。
- 不上传或永久保存视频二进制、签名播放地址和 Cookie。

## Decisions

### 1. 扩展现有通用本地账号连接器，而不是打包第二个 sidecar

`PlatformAccountConnector` 增加 `douyin` provider，继续使用 `app.getPath('userData')/platform-sessions/<user-hash>/douyin` 和系统 Chrome/Edge。首次连接打开官方登录页并保存持久 profile；同步时先以最小化后台窗口读取，只有无法定位自己的主页、需要验证或会话失效才把页面带到前台。

替代方案是把 `jiji262/douyin-downloader`、Python 和浏览器运行时完整打包到桌面端，但这会显著增加安装包体积、升级面和许可证义务，并重复 Electron 已有的浏览器能力，因此不采用。

### 2. 从官方页面已呈现的数据采集，不直接复刻云端裸 API 请求

连接器进入当前账号主页并选择“作品”“喜欢”或“收藏”标签，有限滚动页面，同时读取作品卡链接与官方页面自身返回的作品 JSON。网络响应只在主进程内短暂解析，递归提取 `aweme_id`、标题、作者、封面、发布时间和时长；不得记录响应正文或签名字段。页面响应不可用时使用可见 DOM 链接降级，仍受 100 条和有限滚动上限约束。

该方式让请求的 IP、Cookie、浏览器指纹和页面会话保持一致。直接在本机重新调用未公开 API 仍需要持续维护签名算法，且容易再次形成“凭据有效但接口受限”，因此只作为官方页面自身加载行为的一部分观察，不主动构造无限分页请求。

### 3. 新增用户隔离的抖音本地来源快照

新增 `douyin_local_library_items` 表，以 `(user_id, video_id)` 唯一，保存规范化公开元数据、最近来源模式、来源顺序、首次/最近发现时间和可用状态。同步 API 每次最多接收 100 条，校验抖音 canonical URL、字段长度和安全 URL，不接受 Cookie、请求头、媒体路径或任意扩展对象。

服务端同时幂等更新现有 `video_source_ledgers`，保持喜欢、收藏和作品的来源顺序语义。资料列表把本地快照与旧 sidecar manifest 合并并按作品 ID 去重；新版客户端立即可用，旧客户端和服务器公开目录仍可工作。

### 4. 文稿提取复用现有任务，只改变 metadata 来源和媒体解析入口

本地同步只登记元数据，不自动生成 AI 卡片。用户选择或近期同步要求准备文稿时，现有批量提取任务从合并后的 item snapshot 取得作品；对 `desktop-local` item，后端按 canonical 单视频链接即时解析临时播放地址并执行现有 ASR，任务结束清理媒体。私人列表不再由云端读取，但公开单作品解析仍由云端完成。

### 5. 桌面与非桌面使用明确能力分支

前端只在可信 preload bridge 支持 `douyin` provider 时显示“本机连接”流程。普通 Web、Android 和旧客户端继续显示分享链接与受限兼容说明，不尝试 localhost 或伪造本机能力。连接状态保存在按知萃用户分区的本机 profile，并通过 bridge 实时验证；localStorage 只可作为 UI 缓存，不能作为登录有效性的事实来源。

### 6. 手动同步、精确状态和受控发布

同步只能由用户点击触发，提供 20/50/100 和 1–100 自定义数量。状态文案使用“本机登录有效”“正在本机读取”“已发现 N 条”“需要在抖音官方页面验证”，不使用“可以同步”作为成功保证。遇到风控或验证码后停止任务并提供冷却/重新验证动作，不自动循环。

Electron main/preload 改动通过新 Windows 版本发布，远程页面先保持旧 bridge 兼容。自动更新源必须包含新版 EXE、blockmap 和 `latest.yml`；没有真实上传原生产物时不得宣称本机能力已发布。

## Risks / Trade-offs

- [抖音页面结构或标签文案变化] → 同时使用网络响应与多选择器 DOM 降级，错误明确要求打开官方页面，保留分享链接导入。
- [最小化 Chrome 在部分系统仍短暂闪现] → 复用持久 profile、启动参数使用最小化窗口；只有用户动作触发，不在后台定时启动。
- [本地只取得链接而云端单视频解析仍受限] → 每条失败独立可重试，已发现目录保留；不得把一次媒体失败变成整个来源同步失败。
- [恶意客户端提交伪造元数据] → 服务端只接受当前用户数据，重新规范化视频 ID/URL并限制字段，不信任客户端媒体地址或凭据。
- [新增快照与旧 sidecar manifest 重复] → 以当前用户和作品 ID 去重，来源台账保存多来源模式，优先采用更新的本地快照。
- [未签名 Windows 包影响信任] → 内部验证可显式允许未签名；公开推广仍以代码签名为发布前置项。

## Migration Plan

1. 新增快照模型、启动迁移、metadata ingest API 和合并读取，不改变旧 sidecar API。
2. 扩展 Electron contract/security/preload/main 与本地连接器，加入抖音持久登录和有限采集。
3. 前端按 bridge capability 切到本地流程；旧客户端继续使用云端兼容路径并显示准确限制。
4. 运行桌面 contract、连接器、后端隔离/幂等和 Next production build 验证。
5. 先部署兼容后端和 Web，再发布新版 Windows 安装包与更新清单，使用小账号和多作品账号各做一次手动冒烟。
6. 回滚时关闭前端本地能力入口并回退安装包；服务端快照只含公开元数据，可以保留且不影响旧资料。

## Open Questions

- macOS 客户端发布后是否复用同一 Playwright 连接器；本轮只验证 Windows。
- 后续是否把本地发现的封面下载为用户侧缓存；本轮只保存经校验的远程封面 URL。
