## Context

现有计划工作台已经支持三项焦点、计划列表、周复盘、快速新增和任务排序，但“今天”仍以单个大卡片和折叠区纵向堆叠。桌面端没有利用宽屏建立执行主栏与管理侧栏，移动端也缺少成熟计划产品常见的日期节奏和任务视角切换。

实现继续使用 Next.js 16 客户端组件、现有计划 API、Phosphor 图标和局部 CSS Module。不得引入新的计划字段、伪造紧急程度或破坏 Electron、Capacitor 静态导出及查询参数详情页。

## Goals / Non-Goals

**Goals:**

- 让桌面端首屏同时回答“今天是哪天、最重要的是什么、还有多少任务、从哪里快速记录”。
- 提供清单与四象限两种互补视角，并让同一任务在一个视图中只出现一次。
- 保持任务完成、焦点安排、计划跳转和快速新增使用现有可靠流程。
- 在窄屏把双栏和四象限自然降级为单列，保持 44px 触控目标与安全区。

**Non-Goals:**

- 不增加完整月历、提醒、重复任务、番茄钟、标签、子任务或协作。
- 不复制参考产品的卡通皮肤、会员运营、装扮、广告或额外底部导航。
- 不修改后端接口、任务优先级枚举或数据库结构。

## Decisions

### 1. 今日工作台使用主执行区与管理侧栏

桌面端将日期条和视图控制放在统一顶部，下面使用约 2:1 的两栏布局。主栏展示焦点及当前视图，侧栏展示今日进度、快速收集和逾期摘要。相比继续堆叠全宽卡片，这能让用户在不滚动的情况下完成安排和执行；移动端在 900px 以下回到单列。

### 2. 四象限是现有数据的派生视图

不新增“紧急”字段。高优先级且今天到期/逾期归入“重要且紧急”；高优先级的其他任务归入“重要不紧急”；非高优先级但今天到期/逾期归入“紧急不重要”；其余归入“不重要不紧急”。界面明确这是整理视角，任务仍保留原始计划与排期信息。

### 3. 日期切换只刷新执行概览

周日期条调用现有 `getPlanOverview(date)`，不重新读取完整计划列表，也不触发整页骨架。这样保留快速切换的即时感，并继续由后端按北京时间分类任务。

### 4. 快速收集复用现有安全表单

桌面侧栏提供始终可见的“记录任务”和“创建计划”入口，继续打开现有 `PlanQuickCapture`，避免出现两套表单校验。移动端保留浮动新增和 BottomSheet，不复制桌面侧栏。

### 5. 视觉保持知萃而非模仿参考产品

沿用暖白、深墨和薄荷绿单一强调色，使用紧凑任务行、细分隔和低层级表面，不加入插画背景、渐变、装饰字体或多色象限。象限通过编号、标题和轻微边框差异表达，而不是四种高饱和颜色。

## Risks / Trade-offs

- [派生象限不能表达用户主观紧急度] → 文案说明它基于优先级与排期整理，并保留清单视图作为默认。
- [同一任务来自多个概览桶] → 在前端按 `plan_id:task_id` 去重后再分组。
- [频繁切换日期产生竞态] → 日期请求只接受最后一次选择对应的响应并显示局部读取状态。
- [移动端信息过密] → 隐藏桌面侧栏，将象限改为单列分组，次要元数据允许换行或截断。

## Migration Plan

1. 先增加日期切换与视图状态，再替换“今天”布局。
2. 在现有 CSS Module 中新增工作台样式，不改动全局计划规则。
3. 验证桌面 Electron、390px 移动端、深色模式和现有详情查询参数。
4. 回滚仅需恢复计划页面与局部组件，后端和用户数据不受影响。

## Open Questions

无。完整日历、主观紧急度编辑和番茄钟留给独立变更。
