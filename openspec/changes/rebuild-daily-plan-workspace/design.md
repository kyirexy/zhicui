## Context

现有计划以 `plans` 表保存元数据，同时用 flat `tasks` 与 `days_json` 两份 JSON 保存任务。页面已经有“今日 / 目标 / 复盘”，但今日行动由后端自动截取前三项，用户不能确认自己的三项焦点；计划只能从视频生成；任务没有完成时间和稳定排序；复盘只能展示当前快照。前端还存在早期 `.plan-*` 与后期 `.plan-workspace-*` 两套全局样式覆盖。

实现必须兼容 SQLite、PostgreSQL、JWT 用户隔离、Next.js 16 客户端页面、Capacitor 静态导出和 Electron 壳层。现有用户任务、视频关联、完成状态和 AI 动态字段不得丢失。

## Goals / Non-Goals

**Goals:**

- 建立用户确认的每日三项焦点、其他今日任务与逾期分层。
- 支持手动计划、快速任务、稳定排序、真实完成时间和周复盘。
- 让 AI 调整先预览后应用，并保护既有完成记录。
- 用一个局部视觉系统提供移动优先、浅深色一致的高质量体验。
- 保持旧 API 调用与旧 JSON 可读，所有新读取和写入按用户隔离。

**Non-Goals:**

- 不实现系统通知、重复任务语义、完整日历、第三方日历同步、标签、子任务或协作。
- 不迁移任务到独立数据库表，不重写视频详情已有的直接生成计划流程。
- 不为旧任务补造完成时间，也不根据缺失历史生成效率趋势。

## Decisions

### 1. 计划列使用加法迁移，任务行为继续存放在 JSON

`plans` 增加可空 `start_date` 与 `completed_at`。新计划写入北京时间日期；旧计划读取时以 `created_at` 的北京时间日期作为回退。任务 schema 升为 v3，增加 `position`、`focus_date`、`focus_order`、`completed_at`，在读取时惰性规范化、在任何写入时同步回 flat/day 两份结构。相比立即拆分任务表，这一方案改动小且兼容现有 AI 输出；代价是跨计划聚合仍需遍历当前用户计划。

### 2. 三项焦点通过一个跨计划原子端点保存

`PUT /api/plans/focus` 接收日期和有序的 `{plan_id, task_id}`，最多三项。service 在同一事务中校验所有计划属于当前用户、任务未完成，并清除该日期旧焦点后设置新顺序。概览继续返回 today/overdue/upcoming 以兼容旧客户端，同时增加 focus、suggestions 与 unscheduled。

### 3. 排序保存全量任务 ID 顺序

`PUT /api/plans/{id}/tasks/order` 接收该计划完整且不重复的任务 ID 数组。service 拒绝缺失、额外或重复 ID，再写入连续 position 并重建 days。前端使用 dnd-kit 的 Pointer/Touch/Keyboard sensors，并提供上移/下移按钮作为非拖拽路径。

### 4. 周复盘只使用可重建的事实

任务完成时记录 UTC `completed_at`，重开时清除；计划自动或手动完成时同步 `plans.completed_at`。周复盘按 Asia/Shanghai 的周一到周日计算完成、计划内排期、顺延与当前逾期，并按计划聚合。存在已完成但无完成时间的旧任务时返回 `partial_history: true` 与 `history_started_at`，这些任务保留在总进度但不进入历史周计数。

### 5. AI 调整采用无状态预览与乐观并发应用

preview 使用当前计划、未完成任务、动态字段以及可选的关联视频文案生成受限 operations，并返回 `base_updated_at`、摘要、差异和预览计划，不提交数据库。apply 接收同一基线和 operations；若计划已更新则返回 409。服务端只允许计划元数据与未完成任务的新增、修改、删除、排序操作，始终保留已完成任务的 ID、内容、done 与 completed_at。

### 6. 页面状态局部化，样式从全局级联中退出

`/plans` 保持查询参数详情形式以兼容静态导出。页面拆为工作台数据 hook、今日/计划/复盘视图、快速新增、焦点安排与 AI 预览面板；自定义视觉集中到一个 CSS Module，旧 plan 样式仅在确认无调用后删除。主色为低饱和薄荷，玫红只表示错误/逾期，不使用紫蓝 AI 渐变和统计卡片矩阵。

## Risks / Trade-offs

- [JSON 聚合随计划数量增长] → 所有查询先按用户过滤，概览限制候选数，周复盘限制最多 31 天；未来数据规模增长再拆 task 表。
- [旧任务没有完成时间] → 不回填猜测时间，明确 partial history，并从升级后的第一次打卡开始形成完整历史。
- [跨计划焦点写入部分失败] → 先完成全部所有权与任务校验，再统一写入并只提交一次事务。
- [AI 预览与用户编辑冲突] → 使用 `updated_at` 基线检测并返回 409，要求重新生成预览。
- [触控拖拽误操作] → 仅拖动把手启动、设置激活距离，并保留上移/下移按钮和键盘 sensor。
- [现有脏工作区与全局样式冲突] → 不覆盖无关 diff，新样式使用 CSS Module；删除旧规则前用搜索确认调用。

## Migration Plan

1. 归档已完成的旧计划变更并同步主规格，创建本变更。
2. 为 Plan 增加可空列和跨方言启动迁移；部署时不批量重写任务 JSON。
3. 上线 service/API 与兼容类型，再切换前端工作台。
4. 验证旧视频计划、手动计划、静态导出和双用户隔离后归档本变更。
5. 回滚前端不会损坏新增字段；旧代码会忽略 v3 可选任务字段。若回滚后端，新增可空列可以保留。

## Open Questions

无。提醒、重复任务和完整日历留给后续独立变更。
