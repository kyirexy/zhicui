## Context

设置页当前把所有卡片顺序堆叠在一个窄列中；桌面主侧栏同时固定展示设置、AI 路由和管理端，账户区域只提供直接退出。项目已有桌面运行时标记、认证上下文、设置组件和主题变量，可在不改业务组件的情况下重组导航。

## Goals / Non-Goals

**Goals:**

- 为桌面端提供类似原生应用的独立设置工作区。
- 通过分类导航与搜索降低定位设置项的成本。
- 让左下角账户区域成为明确、可访问的账户菜单入口。
- 保留所有现有设置组件和即时生效行为。
- 为窄屏提供不遮挡内容的响应式分类导航。

**Non-Goals:**

- 不新增个人资料编辑、计费或邀请好友等尚不存在的功能。
- 不改变设置数据的存储位置或后端 API。
- 不复制或重写现有设置卡片内部逻辑。

## Decisions

1. 使用 `?section=` 保存当前设置分类。这样可刷新、前进后退和直接链接，同时不需要新的全局状态。
2. 桌面运行时为 `/settings` 设置 `data-desktop-workspace="settings"`，隐藏产品主侧栏并让设置工作区占满顶部栏以下区域。Web 和移动端不使用这一壳层切换。
3. 设置侧栏使用声明式分类清单驱动标签、图标、搜索关键词和内容标题，避免导航与渲染条件分散。
4. 账户菜单采用锚定在头像上方的轻量弹出菜单，支持点击外部、Escape 和路由切换关闭；不使用全屏模态框。
5. 将设置、AI 路由和管理端从主侧栏工具区迁移到账户菜单；下载移动端仍保留为产品级常驻入口。

## Risks / Trade-offs

- [分类切换会卸载未提交的表单状态] → 现有设置大多即时保存；AI 配置的编辑状态仅在用户主动切换分类时丢弃，符合页面导航预期。
- [设置搜索只匹配分类与关键词，不搜索每个字段] → 明确显示“匹配的设置分类”，保持实现快速且结果可预测。
- [桌面隐藏产品侧栏后返回路径不明显] → 设置侧栏顶部固定提供“返回应用”。

## Migration Plan

先部署兼容的页面与账户菜单，再启用设置工作区运行时标记。无数据迁移；回滚前端文件即可恢复原布局。
