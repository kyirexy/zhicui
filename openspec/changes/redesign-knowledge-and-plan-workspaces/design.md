## Context

知识库目前以大尺寸视觉预览卡片为主，适合少量内容，但在视频同步规模达到 50～100 条后会降低扫描与检索效率；深绿色背景也和全站轻色外观不一致。计划首页已有概览、计划卡片、任务 CRUD、排期、优先级和完成动画，但“概览 + 筛选 + 卡片”的结构没有形成目标到执行再到复盘的心智模型。

本次变更同时影响知识库、计划列表、计划详情和移动端响应式样式。后端现有数据已经足以完成第一阶段 UI 闭环，因此优先做前端信息架构，不新增表结构或外部依赖。

## Goals / Non-Goals

**Goals:**

- 建立统一的中性、明亮、低装饰工作台视觉，去除大面积深绿色。
- 让知识库在大量内容下仍能快速搜索、筛选、扫描和打开。
- 让计划首页默认给出 1～3 个当前行动，并可在“今日 / 目标 / 复盘”间切换。
- 复用真实的计划、任务和 Agent 数据，桌面、移动网页和 Android 保持功能一致。
- 保留现有详情、任务编辑、删除确认、AI 调整和无服务器视频存储边界。

**Non-Goals:**

- 本轮不接入第三方日历、邮箱、精力模型或系统级冲突检测。
- 本轮不新增知识图谱数据库，也不把关系图作为知识库默认视图。
- 本轮不改变视频同步、文案提取、卡片生成或媒体存储策略。
- 本轮不声称 AI 已经根据长期行为学习用户习惯；复盘只显示当前可验证的数据。

## Decisions

### 1. 知识库采用“对象库 + 列表/卡片切换”，不采用纯文档树或默认知识图谱

视频文案、知识卡和来源元数据天然是一组可搜索对象。默认列表能够在同一屏展示更多标题、摘要、类型和更新时间；卡片视图保留视觉浏览偏好。纯文档树要求用户手工维护层级，默认图谱在条目多时也会增加认知负担，因此都不作为主入口。

### 2. 计划首页用一个一级分段控件承载“今日 / 目标 / 复盘”

三个视图对应产品闭环中的执行、方向和反馈。默认“今日”只呈现最多三个优先行动与简短状态，避免重复统计矩阵；“目标”承载全部计划；“复盘”基于完成/待办/逾期数据给出需要继续或调整的目标。

### 3. 第一阶段只展示真实可计算的信息

预计时长、优先级、排期和任务完成状态来自现有计划数据。不存在历史完成时间、日历冲突或精力记录时，不生成伪造趋势图和“AI 已学习”文案。需要调整时，入口连接现有计划详情和基于视频的计划 Agent。

### 4. 使用独立的工作台样式命名空间

新增 `knowledge-workspace-*` 与 `plan-workspace-*` 类名，并把最终覆盖规则放在 `globals.css` 尾部，避免历史 `.library-*`、Tailwind 工具类和桌面壳层多段覆盖互相干扰。颜色使用中性纸白、石灰边框和低饱和蓝紫强调色；品牌绿色只保留在全站品牌标识中。

### 5. 移动端不是缩小桌面，而是重新排序

移动端隐藏桌面侧栏式导航，将搜索、分段控件和筛选变为可横向滚动的顶部工具条；列表压缩为单列行，今日行动保留直接打卡。所有主操作至少 44px，并为 Android 安全区留出底部空间。

## Risks / Trade-offs

- [风险] 旧样式文件存在大量后置覆盖，可能造成局部样式回退 → 使用新命名空间并在文件尾部集中定义，构建后进行桌面与移动实机浏览验证。
- [风险] 当前分页只返回一页计划，跨页的“今日/复盘”统计可能不完整 → 今日优先使用后端 `/api/plans/overview`，目标列表明确沿用分页；不把当前页数据包装成全局统计。
- [风险] 列表视图降低知识卡主题预览的存在感 → 保留一键切换到卡片视图，并记住当前会话选择。
- [风险] 用户期待完整智能排程 → UI 明确展示当前已有排期与优先级，未接入能力不显示虚假状态，后续可在独立变更中接入日历与历史复盘模型。

## Migration Plan

1. 仅新增前端组件状态与样式，复用现有 API，无数据库迁移。
2. 先验证 `/notes`、`/plans` 及详情路由，再运行 TypeScript 与生产构建。
3. 验证 390px 移动视口与桌面视口，确认安全区、触控区和空状态。
4. 若上线后出现样式冲突，可回退相关页面组件与文件尾部新命名空间规则，不影响后端数据。
