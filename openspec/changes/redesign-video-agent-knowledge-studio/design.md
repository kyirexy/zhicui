## Context

视频 Agent 当前已经支持用户级线程、最多 100 条视频来源、标题/作者搜索、完整文稿检索、证据校验、跟进问题、回答形态以及定时摘要。桌面端主结构只有“来源 + 对话”两栏，回答形态隐藏在设置中，生成后的总结、对比或行动方案仍混在消息流里，因此用户很难快速找到最终成果。现有工作区还有并行未提交改动，本次必须以增量方式复用既有组件和 API，不重写 Agent 数据流。

## Goals / Non-Goals

**Goals:**

- 建立稳定的“视频—对话—成果”三栏信息架构。
- 让用户能在左栏搜索并手选自己的视频，也能继续使用全部、昨日新增和抖音分类范围。
- 保持所有回答的来源约束、引用、边界说明和用户隔离能力。
- 将不同回答形态显式呈现为成果，并允许从右栏快速发起新的成果生成。
- 在平板和手机上提供清晰的三面板切换，而不是横向压缩三栏。

**Non-Goals:**

- 不复制 NotebookLM 的音频概览、视频概览、幻灯片、测验或思维导图生成。
- 不新增 Agent 成果数据库表，也不改变已有线程/消息 schema。
- 不把文本形式的“行动方案”自动转换为现有 `plans` 表中的结构化计划；该能力可作为后续独立变更。
- 不改变现有 LLM 检索、配额、联网查证或定时摘要逻辑。

## Decisions

### 1. 成果从持久化消息派生

右栏把带有 `source_context.output_style` 的 assistant 消息视为成果；`summary`、`comparison`、`action_plan` 和 `custom` 显示为显式成果，普通 `answer` 可作为“回答摘录”查看但不抢占成果入口。成果 ID 使用消息 ID，正文、引用、时间和来源覆盖均来自已保存消息。

选择该方案是因为 Agent 消息已经用户隔离、持久化且能被线程接口完整恢复。替代方案是新增 `agent_artifacts` 表，但会引入迁移、同步和重复数据，在本次纯工作区改版中收益不足。

### 2. 三栏使用现有 CSS Grid、全宽桌面画布和渐进式降级

宽屏采用 `视频 / 对话 / 成果` 三列并占满桌面客户端内容区。左右面板获得足以阅读搜索结果和成果正文的均衡宽度，中间对话保持最大弹性；中等宽度只保留中间对话，视频与成果作为侧滑面板；移动端在顶部提供“视频 / 对话 / 成果”切换，并复用底部安全区。

不引入新的布局或动画库；沿用 Tailwind v4 项目中的 CSS custom properties、现有主题变量和 Phosphor 图标。

### 3. 右栏提供产出入口而不是静态装饰卡片

成果栏顶部提供“总结、对比、行动方案、自定义”四类操作。操作会设置已有 `output_style` 并使用明确的中文提示发起当前来源快照上的新消息；生成期间展示真实状态，完成后自动选中新增成果。没有线程或来源时禁用操作并解释原因。

### 4. 来源快照语义保持不变

已创建线程继续使用创建时的来源快照。用户在左栏调整范围时，如果当前线程已有消息，界面明确提示这是“下一个研究”的来源并通过现有 `startNewTask` 创建新线程，避免静默改变既有回答依据。

### 5. 命名统一为产品能力而非通用 AI 标签

导航和页面使用“知萃研伴”，对话消息作者仍显示“知萃”，减少品牌割裂。语义描述始终强调“基于你的视频”，不使用“万能 AI 助手”等宽泛承诺。

### 6. 来源面板采用“搜索优先、人工确认”的选择模型

“全部、昨日新增、收藏、喜欢、我的作品”仅作为搜索范围，收进一个紧凑筛选控件；“手选”不再作为第六种范围。用户通过显式搜索或浏览获得视频列表，再用原生复选框语义确认来源。跨搜索结果保留已选来源，并提供清空与数量反馈；已有线程的快照仍只读，新选择只用于下一项研究。

智能搜索使用独立的显式 POST 请求，避免在每次键入时调用模型。模型只负责把自然语言扩展成少量检索词，召回和排序则确定性检查当前用户视频的标题、作者、已保存 AI 摘要和完整文稿；界面只展示真实命中摘录，不生成匹配事实。模型不可用时退化为关键词检索并明确返回降级模式。

### 7. 忙碌线程使用 HTTP 冲突语义

同一线程仍在生成时的第二次消息请求返回 `409 Conflict` 和短暂重试提示；`422` 仅用于请求或业务校验，模型/提供商失败使用现有网关错误语义。错误诊断为 best-effort，任何配置读取失败都不能覆盖原始异常。

## Risks / Trade-offs

- [成果仍是 Markdown 文本，并非结构化计划] → 在成果标签和操作文案中称为“行动方案”；不伪装成已进入今日执行系统的计划。
- [三栏在 1280px 左右可能压缩对话] → 使用均衡的 `minmax` 列和客户端全宽画布，并在中等断点切换为抽屉而不是继续压缩。
- [AI 搜索增加延迟和模型成本] → 仅在点击或回车时调用，限制扫描量和返回数量，模型失败时继续使用确定性关键词召回。
- [跨搜索选择可能丢失不可见来源] → 前端按 note ID 保存已选来源元数据，提交前仍由后端重新校验用户归属、文稿状态与 100 条上限。
- [旧消息可能缺少 `output_style`] → 归类为普通回答，仍可查看，不影响线程恢复。
- [从成果栏一键生成会消耗一次 Agent 配额] → 使用按钮文案和处理中状态明确这是一次新生成，并复用现有频率限制错误反馈。
- [工作区有并行未提交改动] → 仅修改 Agent 工作区、导航文案和本 change artifacts；不格式化或重写无关文件。

## Migration Plan

1. 前端发布后直接读取现有线程和消息，无需数据库迁移。
2. 先上线三栏和派生成果；旧消息按兼容规则显示。
3. 若出现布局回归，可回滚前端组件/CSS，后端数据不受影响。
