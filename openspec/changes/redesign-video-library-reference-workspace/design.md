## Context

视频资料页目前由一个大型客户端页面承载抖音登录、来源切换、同步任务、搜索排序、批量处理与隐藏管理；`PlatformLibraryPanel` 独立承载 B站/小红书账号 bridge、链接导入和跨平台资料列表。现有功能完整，但页面使用多个纵向大区块和卡片网格，不利于桌面端高频扫描和处理。

参考界面的有效设计语言是平面生产力工作台：窄来源栏、单列高密度视频行、选中资料预览、贴近选择状态的批量操作。项目已有 `DesktopAppFrame` 全局导航和移动端底栏，因此重构只发生在 `/library` 内容区，不复制应用导航，也不把业务状态耦合到全局框架。

## Goals / Non-Goals

**Goals:**

- 桌面内容区采用来源栏、视频列表、轻量预览的三栏关系，并在中等宽度自动收起预览。
- 统一抖音、B站和小红书的列表视觉、搜索与平台筛选，同时严格保留不同平台的能力差异。
- 将同步状态、真实处理状态、批量动作和详情入口放到用户当前工作上下文附近。
- 保持 Windows 桌面、普通网页和 Android 的既有登录、导入、详情及数据隔离行为。
- 在 1366×768 小笔记本、1080px 最小桌面内容宽度和 390px 移动端上保持可用。

**Non-Goals:**

- 不新增或修改后端 API、数据库表、同步数量上限和 Electron IPC。
- 不实现多账号、导入历史、分页、网格切换、站内收藏、回收站、本地文件总览、相关视频或标签编辑。
- 不为缺失字段伪造账号昵称、作者头像、视频时长、分辨率、文件大小、配额、总容量或平台计数。
- 不把抖音专属批量提取、移出和隐藏能力错误开放给 B站或小红书资料。

## Decisions

### 1. 保留全局桌面框架，在页面内容区建立响应式三栏

`DesktopAppFrame` 继续负责产品导航、账户菜单和窗口拖拽区。`/library` 使用 CSS Module 的容器查询建立 `188px / minmax(480px, 1fr) / 336px` 内容网格；内容宽度不足 1080px 时隐藏轻量预览并保留详情路由，767px 以下改为单列。

选择页面内三栏而不是重写全局侧栏，是为了避免复制导航和把平台登录状态提升到无关的应用框架。左右栏只做 sticky，不创建三套独立滚动区域。

### 2. 平台账号逻辑保持单实例，跨平台数据通过回调交给列表

`PlatformLibraryPanel` 继续唯一持有 B站/小红书 bridge 订阅、登录、同步、断开和链接导入状态。新增紧凑 controls 呈现模式，并在成功加载后通过只读回调把 `PlatformLibraryItem[]` 交给父工作台；页面不复制 bridge 监听或导入请求。

父页面使用现有 `platformFilter` 和 `search` 渲染统一视觉列表。抖音行保留复选与批量能力；B站/小红书行只提供其现有的详情、摘要和来源动作。

### 3. 选中预览只使用列表已有字段和现有详情路由

右侧预览从当前抖音选择或当前活动跨平台行派生，显示封面、标题、作者、日期、发布文案、标签、文案状态和 AI 状态。完整文案、AI 助手、摘要、行动计划及本地视频操作继续通过现有 `/library/detail` 工作区完成。

不直接把 `VideoKnowledgeWorkspace` 嵌入列表页，因为该组件包含播放器、多个任务和详情级请求，会造成重复请求与复杂的嵌套交互。中等桌面隐藏预览后，列表中的明确详情入口仍可访问全部能力。

### 4. 批量动作只由抖音复选状态驱动

底部批量条继续读取现有 `selected`、`pendingTranscriptSelected`、`pendingAiSelected` 和移出/隐藏对话框状态；仅在选中至少一条抖音资料时出现。没有选择时保留现有全库 AI 入口，但降低其视觉权重。

这避免为了视觉统一而扩张 B站/小红书 API，也避免让不可执行的复选框和按钮误导用户。

### 5. 视觉系统采用平面列表和单一绿色强调色

列表依靠 1px 分隔线、8–12px 圆角和轻量状态底色建立层级，避免卡片嵌套、渐变、大面积模糊和装饰性徽章。桌面主要交互至少 44px，移动端至少 48px；标题使用平衡换行，正文使用自然换行，数字使用 tabular figures。

不增加 JavaScript 动画；只保留项目现有加载指示和焦点反馈。破坏性操作继续使用现有 `dialog` alertdialog。

## Risks / Trade-offs

- [抖音与跨平台数据不是同一 API，全部筛选无法保证严格跨平台时间排序] → 统一视觉但保持各来源现有顺序，不声称全局时间排序。
- [大型 `page.tsx` 重排可能影响同步和对话框状态] → 不移动业务处理函数，仅重组返回结构并逐项验证登录、同步、批量与隐藏流程。
- [旧版全局 CSS 对 library 类存在多代覆盖] → 新网格、预览和平台行使用 CSS Module 本地类；只对必须复用的现有全局类做工作台作用域覆盖。
- [右侧预览可能被误认为完整详情] → 明确命名为“当前资料”，提供“打开完整资料”主操作，不伪造详情级字段。
- [移动端固定批量条与底部导航冲突] → 使用现有安全区变量，在底部导航之上定位，并验证 390px 视口无横向溢出。

## Migration Plan

1. 为 `PlatformLibraryPanel` 增加紧凑 controls 模式和只读 items 回调，保留默认完整模式以便回滚。
2. 新增跨平台行与轻量预览组件，再重排 `/library` 的工作台 DOM 和 CSS。
3. 将现有卡片改为横向资料行，保留整卡详情层、复选、播放与更多菜单的层级关系。
4. 验证桌面、网页和 Android；若需回滚，恢复原页面结构即可，后端和本地会话不需要迁移。
