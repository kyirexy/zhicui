## Why

本地开发仍依赖一枚写在前端源码中的固定 JWT，失效后会重新落到登录页，也把开发便利与生产认证耦合在一起。与此同时，卡片详情虽然信息完整，但工具栏、主题选择、卡片主体和问答区的表面层级过多、动效偏重，尚未形成连续、易读的内容工作台。

## What Changes

- 新增仅在后端开发开关启用时可用的开发会话端点，自动创建或复用本地管理员并签发正常 JWT。
- 前端开发模式自动申请开发会话，移除源码中的固定 Token，并让开发模式访问登录页时自动进入应用。
- 保持生产环境的注册、登录、JWT 校验和权限边界不变。
- 将卡片工具区与主题选择合并为更连续的控制表面，减少套娃边框和重复说明。
- 重构聚光卡片的信息层级、统计区、引文、章节、结论和可信度展示，统一使用单一内容类型强调色。
- 移除聚光卡片中耗时较长或修改布局属性的动画，保留不超过 200ms、尊重减少动态偏好的轻量交互反馈。
- 完善桌面双栏与移动端单栏中的卡片、问答区宽度、间距、焦点和无横向溢出表现。

## Capabilities

### New Capabilities

- `development-auto-session`: 仅开发环境可开启的免登录会话签发、前端自动恢复及生产隔离行为。
- `polished-card-workspace`: 连续的卡片阅读工作台、精简的聚光卡片视觉层级和响应式交互基线。

### Modified Capabilities

无。

## Impact

- 后端配置、认证服务与认证路由。
- 本地 `run.py` 启动行为；部署环境默认行为不变。
- 前端认证上下文、登录页、卡片渲染器、聚光卡片和全局样式。
- 不新增第三方依赖，不改变数据库表结构或现有生产 API 的认证要求。
