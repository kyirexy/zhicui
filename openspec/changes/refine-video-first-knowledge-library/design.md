## Context

混合知识接口已把视频笔记和用户自写内容合并分页，但列表只返回通用标题、摘要和字数。现有页面用大 Hero 和抽象图标承载内容，既浪费桌面空间，也弱化了产品最重要的视频来源。此次改动跨越后端序列化、前端类型和响应式工作区，但不改变数据库结构。

## Goals / Non-Goals

**Goals:**

- 首屏直接进入资料浏览任务，视频封面和状态可快速扫描。
- 用来源筛选代替已废弃的内容类型标签。
- 桌面端提供按需概览，移动端保持直接打开详情的单列行为。
- 复用现有封面容错组件、主题变量和知识 CRUD。

**Non-Goals:**

- 不恢复食谱、洞察、历史、产品、计划、通用标签。
- 不新增知识关系图、文件夹、批量编辑或新的数据库字段。
- 不重做视频知识详情工作区，也不改变 Agent 路由。

## Decisions

1. **接口直接返回展示元数据。** `knowledge_service._note_item` 从 `Note.to_dict()` 补充封面、作者、平台、章节数和文稿状态，避免列表页逐条请求详情。个人知识返回兼容的空值。
2. **来源筛选先在当前页即时执行。** 当前接口最多返回 20 条混合结果，前端的全部/视频/我的笔记筛选无需新增服务端查询契约；搜索和分页仍由服务端负责。若数据规模要求跨页精确筛选，可后续扩展 `kind` 查询参数。
3. **默认列表，缩略图模式是媒体浏览而非知识卡片。** 两种视图共享同一数据与操作，偏好保存在本地。缩略图模式突出 16:9 封面，不引入内容类型卡片样式。
4. **桌面概览由明确选择触发。** 每行/缩略图提供概览按钮，选择后右侧检查器出现；标题仍是直接打开详情的链接。窄屏不渲染检查器，以避免双层导航。
5. **视觉保持克制。** 使用现有前景、背景、边框和 emerald 强调色，圆角 8 到 12px，不使用渐变、大面积玻璃、宽色条或装饰动画。

## Risks / Trade-offs

- [封面 URL 失效导致空白] → 复用 `LibraryCoverImage` 的重试与回退，并使用稳定比例容器避免布局跳动。
- [来源筛选只作用于当前服务端页] → 文案不显示全库类型计数；未来需要跨页过滤时再扩展 API 参数。
- [桌面概览增加交互复杂度] → 只有用户主动点击概览时出现，并保留清晰关闭按钮与直接打开详情入口。
- [旧数据缺少作者或封面] → 所有新增字段均为可选，使用平台标签和文档预览回退。
