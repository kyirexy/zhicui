## Why

当前“我的知识”把所有视频 Note 与用户原创内容直接混合展示，导致它与“视频资料”重复，也把仅有文稿、尚未形成可复用结论的视频误称为知识。现在需要把产品边界收敛为“资料 → 研究 → 沉淀 → 行动”，让用户只在“我的知识”看到自己写下或明确保存的成果，同时保留现有视频摘要作为可整理草稿而不丢失历史数据。

## What Changes

- **BREAKING** 将 `/notes` 从视频优先的混合资料库重构为“我的知识”成果工作区；原始视频、同步、导入、平台筛选与文稿状态继续只由 `/library` 承担。
- 引入“知识页”和“待整理”两种明确状态：用户原创内容可直接形成知识页；已有且具备 AI 摘要的视频 Note 作为待整理候选；只有原始文稿、没有摘要成果的视频不再进入知识列表。
- 增加显式沉淀契约，支持知识页的摘要、正文、来源、状态和来源数量；后续 Agent 成果必须由用户保存后才能进入“我的知识”。
- 将来源筛选、搜索、计数与分页下沉到服务端，避免前端只过滤当前页造成错误空状态和分页总数。
- 桌面端改为稳定的成果列表与阅读画布；移动端使用单列列表与全屏详情。移除知识页的网格切换、导入视频主操作和不真实的“向全部知识提问”。
- 桌面工作区使用应用内容区的完整可用宽度，将视图切换与搜索收进左侧列表，把阅读内容从分栏边界直接起排；移除无信息量的零来源、重复状态和说明性元数据，降低首屏学习成本。
- 将桌面知识页进一步收敛为连续的全高工作台：移除悬浮大卡片外壳与独立说明区，使用紧凑工具栏、扁平列表控制和贯穿剩余高度的阅读舞台；短知识页让标题、正文和真实来源按自然文档流连续排列，把剩余空白统一留在内容之后。
- 统一视频摘要详情的阅读入口，保留历史 `/notes?id=...` 深链，但将来源视频交给共享视频详情工作区呈现。
- 保留现有 `notes` 与 `knowledge_entries` 数据和用户隔离，不引入向量数据库、知识图谱或新的前端框架。

## Capabilities

### New Capabilities

- `curated-knowledge-outcomes`: 定义用户知识页、待整理候选、显式保存、来源关联及兼容现有视频摘要的行为。

### Modified Capabilities

- `knowledge-library-workspace`: 将视频优先混合资料库改为以可复用成果为核心的搜索、筛选、阅读和编辑工作区，并更新桌面与移动端交互要求。

## Impact

- 后端：`KnowledgeEntry` 模型与启动迁移、知识服务、知识 API 查询参数和序列化契约。
- 前端：`/notes` 页面、知识工作区样式、知识 API 类型与兼容详情路由。
- Agent：本次不把原创知识接入 Agent 检索；相关入口改为“去知萃研伴”，避免承诺尚未存在的全知识检索。
- 数据：现有视频 Note 继续作为来源数据；非空 AI 摘要可投影为待整理候选，原始记录不迁移、不删除。
- 验证：知识所有权、服务端筛选/分页、候选可见性、桌面/移动布局、加载/空/错状态和历史深链。
