## Context

产品主导航由共享的 `PRODUCT_DESTINATIONS` 驱动，桌面侧栏、网页应用头部和移动底栏复用同一数据。当前 `today` 入口同时匹配 `/` 与 `/plans`，因此两个不同工作区共享选中状态；计划页自身又默认打开“今天”，形成重复层级。

## Goals / Non-Goals

**Goals:**

- 首页和计划中心拥有独立、稳定的导航身份。
- `/plans` 默认用于管理计划，今日执行仍可在计划中心内部访问。
- 所有客户端导航同步名称、图标、角标和路由选中状态。
- 计划页顶部更紧凑，更像计划管理工具而非首页欢迎区。

**Non-Goals:**

- 不移动根路由已有的视频同步与桌面工作台内容。
- 不新增日历拖拽、提醒、重复规则或新的后端字段。
- 不移除计划中心内的今日安排和复盘能力。

## Decisions

1. **扩展共享导航模型而非逐组件硬编码。** 新增 `plans` destination，`today` 只匹配根路由，避免桌面与移动端再次漂移。
2. **计划角标归计划入口。** 未完成任务数量属于计划中心状态，不再显示在首页入口上。
3. **计划中心默认 `plans` 视图。** 内部顺序为“全部计划 / 今日安排 / 本周复盘”，用户进入独立计划 Tab 后首先看到计划全貌；需要执行当天任务时再进入今日安排。
4. **导航允许五项移动 Tab。** 五个入口均使用短标签和等宽布局；计划与首页分离的清晰度优先于四项限制。
5. **保留现有数据请求。** 计划页仍并行加载列表与今日概览，切换内部视图无需额外等待。

## Risks / Trade-offs

- [移动端五项导航变拥挤] → 使用“首页 / 视频 / 研伴 / 知识 / 计划”短标签、20px 图标与等分宽度。
- [用户习惯从计划页先看今日] → 今日安排仍是第二个内部 Tab，首页继续呈现今日任务数量和计划入口。
- [角标请求增加无意义首页加载] → 维持现有条件请求逻辑，但把角标展示归属迁移到 `plans`。
