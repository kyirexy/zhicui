## Context

视频资料页目前把来源介绍、账号状态、来源切换、同步数量、平台连接、链接导入、平台筛选、搜索、排序、选择、AI、处理状态和预览操作同时展开。功能本身均有真实数据或处理函数，但多层说明和重复入口让用户的主要任务——同步并找到一条资料——被淹没。现有实现为 Next.js 客户端页面、CSS Modules 与少量原生 `details/dialog`，无需新增基础设施即可完成减法。

## Goals / Non-Goals

**Goals:**

- 让首屏只保留来源状态与同步、平台筛选与搜索、资料列表、当前资料和一个主要 AI 入口。
- 通过渐进式展开保留同步数量、账号管理、链接导入、隐藏管理及危险批量操作。
- 减少重复标题、介绍段落、技术说明和同义状态，同时保留错误、隐私和确认信息。
- 将桌面三栏收敛为列表与预览双栏，并保持移动单列的功能连续性和可访问性。

**Non-Goals:**

- 不删除同步、导入、转写、摘要、AI、移出、永久隐藏或恢复能力。
- 不改变 API、数据库、采集策略、认证、排序语义或平台支持范围。
- 不添加新的导航、分页、模型选择、统计面板或本地文件管理功能。
- 不重新设计视频详情页或 AI Agent 工作台。

## Decisions

### 1. 采用两级功能层级，而不是按平台堆叠完整说明

首级只展示高频且能立即完成任务的操作：账号状态、来源模式、同步、平台筛选、搜索、详情和快速提问。低频控制集中到命名明确的“同步设置”“账号管理”“导入链接”“更多操作”入口。相比直接删除控件，这能降低视觉密度且保留完整能力。

### 2. 常驻来源栏改为始终挂载的任务对话框

来源控件不再常驻占用首屏栏位，而是保持挂载在“添加 / 同步”对话框中，以继续请求跨平台列表和接收桌面 bridge 状态。抖音区域只保留账号、来源模式和同步按钮；同步数量显示为当前值并在设置中编辑。B站和小红书使用紧凑账号行，连接后再显示必要的同步来源；登录状态仅用一行反馈。平台隐私和 Beta 说明只在相应展开区显示一次。

### 3. 主列表只保留一个页面标题和一个 AI 主入口

删除“视频资料 / 我的视频资料 / 查看已同步……”的重复层级。标题与总数合并，快速问答作为唯一首屏 AI 动作；完整 Agent 通过该动作或资料预览中的链接继续可达。平台 Tab、搜索和排序保持原行为。

### 4. 预览以决策信息为主

预览默认展示封面、标题、作者、处理状态和主要动作。发布文案与标签只在有真实内容时紧凑显示，来源、摘要等次级动作收进统一操作区，避免与列表重复解释。

### 5. 危险操作继续显式确认

移出、永久隐藏、删除与退出账号可以进入次级入口，但触发后仍使用原确认对话框和原有说明。错误与处理中状态不折叠，避免简化导致不可诊断。

### 6. 移动端沿用同一优先级

窄屏继续使用来源折叠和单列列表。主要控件保持至少 48px 触控区域；次级入口在展开后按单列排列并避开底部导航。不会为移动端创建另一套功能模型。

## Risks / Trade-offs

- [低频能力更难被首次发现] → 使用具体入口名称和当前值摘要，例如“同步设置 · 50 条”“导入链接”，不使用含糊的“高级”。
- [原生 `details` 在复杂状态下可能保持展开] → 只用于非模态设置，登录、危险确认和 AI 对话继续使用现有受控交互。
- [删除说明后用户不理解平台限制] → 将限制放到发生位置附近，只保留一条直接、可操作的提示。
- [桌面减密后移动端出现隐藏内容过长] → 移动端展开区采用单列并保持安全区间距，验证 390px 无横向溢出。

## Migration Plan

1. 先重排来源栏与主标题，不改变处理函数和 API 调用。
2. 将同步数量、账号管理和链接导入迁移到现有或新的渐进式展开容器。
3. 合并 AI 与批量操作入口，保留原链接和确认流程。
4. 完成类型检查、生产构建和桌面/窄屏视觉验证。
5. 若需要回滚，可恢复 JSX 与 CSS 布局；数据和后端无需迁移。
