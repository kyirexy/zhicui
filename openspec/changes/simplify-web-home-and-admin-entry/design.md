## Context

Web 营销首页当前由 Hero、品牌陈述、四步流程、问答案例、下载中心和重复 CTA 组成，多个区块表达相同价值，导致页面过长。公开首页虽然无需登录，但顶部仍显示普通账号登录/登录状态；管理员入口与普通访客入口混在一起。

现有认证链路已经满足安全要求：`/admin` 非公开、AuthGuard 会把匿名用户送到 `/login?redirect=/admin`，登录页支持安全的站内 redirect，管理员页再次校验 `user.is_admin`。本次应复用这条链路，而不是放开后台权限。

## Goals / Non-Goals

**Goals:**

- 让访客在首屏和一次后续滚动内理解三个核心功能。
- 将营销页压缩为 Hero、核心功能和下载中心三个主要内容区。
- 保持首页免登录，不在顶部向普通访客展示账号状态或普通登录入口。
- 让管理员可以从低干扰入口进入已有安全登录链路。
- 保持上一变更完成的纯白中性视觉、双平台下载和设备推荐。

**Non-Goals:**

- 不允许匿名访问管理员后台。
- 不修改管理员权限模型、JWT、后端 API 或登录凭据。
- 不重构后台 UI、客户端下载中心或原生客户端导航。
- 不新增隐藏手势、秘密路由或安全性较差的快捷登录。

## Decisions

### 1. 页面采用三段式信息架构

保留现有 Hero 和产品预览，删除重复的品牌陈述、问答案例和尾部 CTA；将四步流程替换为三个简短核心功能项，随后直接进入双平台下载中心。这样保留真实产品感和下载转化，同时显著降低文字量。

备选方案是只缩短各段文案但保留全部区块；这仍需要长距离滚动，不能解决用户指出的学习成本问题。

### 2. 三个功能项只描述用户结果

功能项固定为“批量整理视频”“基于资料提问”“保存知识或计划”，每项使用一个 Phosphor 图标、一个标题和一句说明。删除编号、四步教学与重复的可信度说明，让访客通过结果而不是内部流程理解产品。

### 3. 公开顶部不承担普通账号入口

营销顶部保留品牌、核心功能锚点、管理员已登录时的“管理端”和“下载客户端”。匿名或普通登录用户不显示“管理登录”“账号已登录”等账号文案，避免让公开官网看起来必须登录。

### 4. 管理员入口放在页脚并直接访问 `/admin`

页脚始终显示“管理员入口”。匿名访问 `/admin` 时由 AuthGuard 转到带安全 redirect 的登录页；管理员登录后回到后台，非管理员会被管理员页送回首页。使用真实路由而非前端伪装或隐藏手势，便于收藏和运维人员发现。

### 5. 删除 JSX 同时清理局部 CSS

不只通过 `display:none` 隐藏长区块，而是删除对应 JSX、静态文案和不再引用的图标，再清理 CSS 选择器。这样减少客户端包体和维护成本，同时避免旧样式重新污染页面。

## Risks / Trade-offs

- [删除案例后产品可信度表达减少] → Hero 产品预览继续展示真实工作台，核心功能项使用具体结果文案。
- [管理员入口移到页脚后不够显眼] → 已登录管理员仍在顶部看到“管理端”，匿名管理员可在页脚找到固定入口并收藏 `/admin`。
- [普通登录用户无法从官网顶部进入账号] → 官网定位为公开下载页；客户端内保留完整账号与设置入口。
- [删减 CSS 误伤保留区块] → 只删除已确认无引用的局部类，并在桌面/手机视口运行浏览器回归。

## Migration Plan

1. 重构营销首页 DOM 和文案，保留下载中心数据逻辑。
2. 调整营销 Header/Footer 的账号与管理员入口。
3. 清理无引用样式和图标。
4. 验证匿名 `/`、匿名 `/admin`、管理员 `/admin` 与双平台下载入口。
