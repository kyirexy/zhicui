## Context

知萃 Harness 的回答已经使用 SSE，并且服务端也会消费模型供应商的原生流。然而当前链路在两个位置放大了等待和抖动：快速模式在真正的回答流之前总会执行一次非流式 LLM 检索规划；模型返回 JSON 后，`answer` 字段又被逐字符转成独立 SSE，浏览器随即对每个字符更新 React 状态并重新解析整段 Markdown。最近真实回答记录显示，本地扫描与排序通常只需几十毫秒，而快速模式的规划调用常额外占用数秒。

回答中的流式光标目前挂在 Markdown 根容器的伪元素上。根容器内部是块级段落或列表时，伪元素会落到下一行，表现成独立空白块和孤立蓝线。视频资料的两种隐藏动作已经具有完整的确认、用户隔离与非破坏性语义，但桌面选中工具栏把它们收进了更多菜单。

本次变更跨越后端 Agent 编排、SSE 事件粒度、前端流式状态提交与视频资料选中工具栏。现有工作区包含其他未提交改动，因此实现必须保持窄范围并复用现有 API、确认弹窗和消息数据结构。

## Goals / Non-Goals

**Goals:**

- 缩短普通快速问答从提交到首个可见回答的时间，同时保留深度研究和多轮指代消解能力。
- 把逐字符事件风暴恢复为供应商增量粒度，并让浏览器每个绘制帧至多提交一次后续文本更新。
- 保证完成、停止、错误和断流时不会遗失仍在缓冲区中的可见文本，也不会重复最终回答。
- 移除会生成独立空白块的流式光标，用已有作者状态表达“正在生成”。
- 在桌面选中工具栏直接展示“移出视频资料”和“永久隐藏”，继续复用既有确认与权限边界。

**Non-Goals:**

- 不合并“创建会话”和“发送回答”两个 HTTP 请求。
- 不改变模型供应商、计费、引用校验、联网研究、详细视频解析或消息持久化语义。
- 不为流式文本增加逐词淡入动画或新的 UI 依赖。
- 不改变临时移出、永久隐藏、删除文案与摘要之间的既有业务差异。

## Decisions

### 1. 普通快速问答使用确定性本地检索计划

快速模式、独立问题、默认回答形式且没有定制要求时，直接使用现有的本地 fallback 计划：原问题作为检索词，并由确定性关键词决定 focused/broad 覆盖。即使会话已有历史，只要当前问题没有“刚才、上述、继续展开、这个结论”等明确承接信号，也视为独立问题。深度模式、明确依赖上文的追问、非默认成果形式或定制要求继续使用 LLM 规划器。

这样可以在最常见路径中省去一次完整模型往返，同时不牺牲需要指代消解或复杂结构规划的路径。备选方案是让规划与扫描并行，但最终综合仍依赖规划结果，无法消除首字前等待；另一个方案是所有模式都跳过规划，会削弱深度研究和多轮问答质量。

### 2. 后端按供应商增量而非字符发送可见回答

JSON `answer` 提取器仍逐字符识别转义和结束引号，以维持结构安全；但它在每个供应商 delta 内聚合可见字符，仅在处理完该 delta 后调用一次 `answer_delta`。首个可见供应商 delta 立即进入 SSE 队列，流结束时显式冲刷未完成的转义字符。

这保留了供应商原生首字速度和现有最终 JSON 校验，又显著减少 JSON 编码、队列、网络事件和浏览器解析次数。备选方案是在后端按固定 20–30ms 计时器合并；它需要额外线程同步并会人为增加首字延迟，因此本次不采用。

### 3. 客户端使用 requestAnimationFrame 微批提交

第一个可见 delta 立即写入消息，提供明确首反馈；之后的 delta 先写入局部缓冲区，通过单个 `requestAnimationFrame` 在下一次绘制前合并提交。每次提交只更新目标临时消息，并同时调度已有的跟随滚动。请求结束、异常或取消清理时先同步冲刷缓冲区，再取消剩余帧回调。

相比固定 32ms `setTimeout`，绘制帧微批与浏览器刷新同步且不会形成明显阶梯；相比每个 delta 直接 `setMessages`，它避免对增长中的完整 Markdown 重复做无意义解析。

### 4. 流式状态不再使用 Markdown 根伪光标

删除 Markdown 根容器上的 `::after` 光标和对应动画。回答开始前继续展示已有阶段状态；回答开始后，作者行的“正在生成”是唯一持续状态。完成时切回静态消息语义。

把光标改挂最后一个 Markdown 子节点也能避免空行，但流式解析期间最后节点类型会不断变化，容易产生跳动且没有新增信息，因此不保留光标。

### 5. 桌面直显隐藏动作，窄屏保留紧凑收纳

桌面工具栏在“去提问”后直接渲染两枚带标签与当前抖音可操作数量的危险次级按钮，两者继续调用现有 `openRemovalDialog`。更多菜单保留详细解析、删除文案等低频动作。为避免移动端固定工具栏过高，`<= 767px` 时隐藏两枚桌面按钮，并在更多菜单中保留同语义副本。

混合平台选择时，按钮数量使用 `selectedItems.length` 而不是总选择数；没有可操作的抖音条目时维持禁用。这样不误导用户，也不扩大后端现有抖音隐藏接口的范围。

## Risks / Trade-offs

- **快速模式检索规划质量可能略降** → 仅跳过独立默认问答的规划；出现明确上文指代、定制输出或深度模式时仍使用模型规划器，并保留原 fallback 逻辑。综合提示词仍携带有界对话历史，因此启发式漏判不会丢失上文内容。
- **供应商可能一次返回很大的 delta** → 前端仍按绘制帧提交，最终 Markdown 渲染保持有界；服务端不再人为逐字符拆分。
- **完成事件可能与未绘制的帧竞争** → 在处理最终响应前同步冲刷局部 buffer，再用服务端规范消息替换临时消息。
- **桌面工具栏在中等宽度下可能换行** → 现有 `flex-wrap` 保持可用，危险按钮采用紧凑文字；移动断点继续使用更多菜单。
- **断流时部分文本与最终持久化内容可能不同** → 现有失败状态仍以可重试用户消息为准；缓冲冲刷只防止 UI 丢字，不把未校验的部分回答持久化。

## Migration Plan

无需数据库、接口版本或依赖迁移。按后端增量聚合、前端绘制帧微批、视觉指示器、工具栏入口的顺序部署；旧客户端仍能消费粒度更粗但结构不变的 `delta` SSE。

## Open Questions
