## Why

知萃 Harness 当前在等待首段回答时缺少及时反馈，细碎增量又会触发频繁的整段渲染，长回答容易出现停顿、跳动和异常空白光标块。与此同时，视频资料的“移出视频资料”和“永久隐藏”被收进更多菜单，用户完成选择后仍需额外寻找高频管理动作。

## What Changes

- 优化 Agent 流式链路，让服务端尽早发送可消费的生命周期事件和文本增量，并减少首段回答前可避免的串行等待。
- 在客户端按浏览器绘制节奏合并增量，避免每个微小 chunk 都重跑完整消息树与 Markdown 渲染，同时保证停止、错误、引用和完成态语义不变。
- 用克制的行内流式状态替代回答末尾异常的空白输入框/蓝色竖线，不再为等待光标占据独立大块空间。
- 在桌面端视频资料选中工具栏直接展示“移出视频资料”和“永久隐藏”，继续复用现有确认、用户隔离和非破坏性语义；窄屏仍允许合理收纳。
- 不引入新的模型供应商或第三方 UI 依赖，不改变已有知识、计划和隐藏记录的数据语义。

## Capabilities

### New Capabilities

- `responsive-agent-streaming`: 规定 Agent 回答的快速首反馈、连续文本增量、客户端平滑提交、可恢复错误态以及不干扰阅读的流式指示器。

### Modified Capabilities

- `douyin-library-sync-control`: 选中视频后的桌面批量工具栏直接提供临时移出与永久隐藏动作，同时保留确认和批量上限。

## Impact

- 后端：Agent 流式路由、模型事件归一化和可能的检索/上下文准备顺序。
- 前端：Agent 请求解析、消息状态提交、Markdown 渲染、流式状态样式，以及视频资料批量操作工具栏。
- API：沿用现有流式端点和认证方式；如补充生命周期事件，客户端需保持对既有事件的兼容解析。
- 依赖与数据：不新增依赖，不迁移数据库，不改变 Note、Agent 线程、临时移出或永久隐藏记录结构。
