## Context

线上服务和当前静态资源均可用，但历史访问日志证明旧 HTML/Service Worker 曾继续请求已删除的 Next.js chunk，从而产生白屏。当前内联恢复脚本只在资源报错后清理缓存，无法保证所有长期未刷新的客户端都能脱离旧 Service Worker。开发环境还允许认证请求无限等待，使 AuthGuard 长期只显示恢复状态。

视频 Agent 已采用对话优先布局和结构化后端回答，但前端仍存在乐观消息失败后不可恢复、旧 JSON 消息直出、资料范围重复、证据标签含义模糊以及移动触控区过小等问题。

## Goals / Non-Goals

**Goals:**

- 让 Web、桌面和 Android 客户端在缓存或认证异常时始终展示可恢复界面。
- 清除旧 Service Worker 的 HTML/chunk 缓存影响，同时保留安装清单与普通静态资源能力。
- 在不改变现有 Agent 数据模型的前提下改善失败恢复、结构化回答、资料上下文和证据表达。
- 统一 Agent 与新版知识库、计划工作台的暖中性视觉，并完善移动端触控和安全区。

**Non-Goals:**

- 本轮不引入新的 Agent 框架或重写后端检索链。
- 不伪造实时工具步骤；后端没有流式状态时只展示真实可确认的等待状态。
- 不实现日历自动排程或邮件供应商配置。

## Decisions

1. **Web Service Worker 进入清理模式。** `sw.js` 在 activate 阶段删除旧缓存并注销自身，不再缓存 HTML、`/_next/` 或 API。相比继续维护复杂缓存版本，这更适合频繁发布的 Next.js 应用，也避免 Android WebView 与浏览器持有不同页面壳。

2. **认证请求使用统一可取消超时。** `authRequest` 接受超时并通过 `AbortController` 结束挂起请求；恢复失败后必须结束 loading。开发模式可显示“重新连接开发会话”，生产模式进入登录页或展示明确错误。

3. **消息采用本地发送状态而不修改后端模型。** 前端为乐观消息维护 `sending/failed` 状态，失败时保留问题并提供重试；成功刷新真实线程后删除本地状态。这避免数据库迁移，也保证错误贴近消息。

4. **在渲染边界兼容旧结构化文本。** `AgentMessageView` 尝试解析 JSON envelope、围栏 JSON 和双重编码，只提取可验证的 answer/evidence/follow-up 字段；解析失败才按 Markdown 文本展示。

5. **资料范围只保留一个主入口。** 顶栏 context chip 表示当前会话已锁定资料；新任务欢迎态的资料抽屉编辑 draft scope。输入区不再重复范围说明，运行中允许用户继续编辑草稿但禁用发送。

6. **证据按来源类型分组。** 视频文案依据、知识卡理解和联网来源分别计数；只有存在视频/知识库证据时才使用“原文依据”，联网来源使用“外部查证”。

7. **样式追加单一最终覆盖层。** 暂不大规模删除历史 CSS，以独立 `video-agent-refined-*` 与末尾高特异性作用域收敛视觉和移动行为；完成回归后再单独清理旧样式，降低脏工作树中的冲突风险。

## Risks / Trade-offs

- [清理 Service Worker 会暂时失去离线壳] → 当前产品依赖在线 API，本轮优先保证版本一致与可恢复性。
- [前端消息状态刷新后丢失] → 失败问题恢复到输入框，真实成功消息仍由后端持久化。
- [旧 JSON 形态很多] → 解析器只接受白名单字段并保留纯文本兜底，禁止执行或信任任意结构。
- [历史 CSS 仍然重复] → 新样式集中在一个最终作用域并以浏览器回归验证，后续再做机械清理。

## Migration Plan

1. 发布清理版 `sw.js` 与停止注册逻辑。
2. 发布认证超时和 Agent 前端改动。
3. 部署时继续保留旧静态 chunk，观察一轮访问日志中的 404。
4. 确认旧 Service Worker 注册量下降后，再决定是否重新引入仅缓存图标的轻量策略。
5. 任一异常可回滚前端版本；清理版 Service Worker 注销后不会继续控制客户端。
