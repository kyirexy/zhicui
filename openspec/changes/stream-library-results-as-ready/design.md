## Context

资料库同步先取得抖音视频元数据，再通过一个并发批量任务执行云端 ASR。后端批量接口已经返回每条视频的 `queued`、`transcribing`、`done` 和 `error` 状态，并在 `done` 时携带 Note ID 与文案字数；当前前端每 1.2 秒轮询并更新底层卡片数据，但主要反馈仍是整批文本通知，完成结果不够醒目，用户容易认为必须等待全部 50/100 条。

## Goals / Non-Goals

**Goals:**

- 视频清单一经同步就先显示，ASR 在同一页面后台继续。
- 每次轮询发现一条完成结果时，立即更新该卡片和问答来源。
- 在视频网格上方提供紧凑、可扫描的批次摘要及最近完成结果。
- 让排队、处理中、已完成和失败状态在桌面端与移动端一致可读。

**Non-Goals:**

- 不改变 ASR 服务、并发上限或批量任务持久化模型。
- 不自动运行 DeepSeek 总结、知识卡或计划生成。
- 不保存视频文件，不增加新的媒体数据库字段。
- 不通过自动滚动或频繁重排卡片打断用户当前阅读位置。

## Decisions

1. **复用现有批量任务轮询，不引入 SSE。** 将轮询间隔缩短到约 800ms，并把最新任务快照保存在页面状态中。现有接口已经包含完整的逐项状态，增加另一套推送通道会扩大部署和断线重连复杂度，收益有限。

2. **用独立的实时摘要突出新增结果，不重排整个视频网格。** 摘要显示完成数、处理中、等待、失败、进度条，以及按 `updated_at` 排序的最近完成视频。这样第一条完成后立即出现，同时避免卡片不断换位。

3. **完成结果直接更新已有视频对象。** 继续使用 `aweme_id` 合并 `note_id`、`transcript_chars` 和 `ai_initialized`，因此问答来源的 `useMemo` 会在同一次渲染中自然加入该视频，无需额外刷新整页。

4. **使用静态状态色与短时合成层反馈。** 卡片通过边框、状态徽标和不超过 180ms 的 `opacity/transform` 反馈完成；`prefers-reduced-motion` 下取消动画。沿用现有绿色主强调色，不增加渐变或新的交互组件体系。

## Risks / Trade-offs

- [800ms 轮询增加少量状态请求] → 每次请求仅返回最多 100 条轻量状态，任务结束立即停止轮询。
- [后端进程重启会丢失内存任务] → 保留现有已持久化 Note 结果；页面重新加载仍可从资料库读取已完成文案。
- [大量同时完成导致最近结果快速变化] → 摘要只展示最近 4 条，完整结果始终保留在下方网格。
- [错误信息过长破坏卡片布局] → 卡片只显示单行安全错误并保留 `title` 查看全文。
