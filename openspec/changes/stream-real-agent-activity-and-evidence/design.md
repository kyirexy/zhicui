## Context

当前 durable Agent 已持久化生命周期事件与回答 delta，并由同一 SSE replay 端点恢复；但前端活动投影仍会把阶段映射成预设文案列表，用户看到的是“应该发生什么”而不是“刚刚发生了什么”。后端最终答案同时保留结构化 Claim/Evidence 数据和面向用户的 Markdown 正文，现有 delta 只覆盖前一部分叙述，完成事件到达后前端再用完整 canonical 内容替换消息，因此证据区域整块出现并触发长消息重新布局。

约束包括 React 19 DOM 所有权、既有线程和 SSE replay 兼容、取消与租约语义、只显示验证后证据，以及不能为了 UI 体验把未验证的模型草稿提前暴露给用户。

## Goals / Non-Goals

**Goals:**

- 活动时间线中的每一项都对应真实持久事件，不补齐固定步骤，也不重复同义阶段。
- 从第一段正文到最后一条验证原文与引用均通过同一 replay-safe delta 流渐进出现，结构化追问在正文完成后稳定挂载。
- initial send、断线恢复和页面刷新共用相同序号去重与文本泵，终态对账不造成内容回退或整块替换。
- 将高频网络 delta 与昂贵 Markdown/滚动更新解耦，使视觉节奏连续且滚动保持响应。

**Non-Goals:**

- 不显示隐藏思维链、模型内部推理或未脱敏工具参数。
- 不改变现有模型供应商、检索策略、证据验证门槛或计费规则。
- 不引入 Vercel AI SDK、WebSocket 或新的前端 Markdown 库。

## Decisions

1. **活动区使用事件白名单直接投影，而不是阶段编号模板。** 后端事件继续保留 `event_seq/type/message/metadata`，前端只对可公开事件做轻量标签归一化、相邻重复折叠和当前动作选择。阶段枚举只用于图标/色彩，不生成尚未收到的项目。替代方案是保留五步模板并动态高亮，但它仍然制造假动作，拒绝采用。

2. **验证完成后先生成唯一 canonical Markdown，再按有界块持久化全部 answer delta。** canonical Markdown 包含回答叙述、Claim 标题与说明、覆盖度、代表依据和验证原文。只有验证通过的结构进入该文稿；交互式追问继续作为结构化结果在正文结束后挂载。`done` 携带结构化结果和同一正文，用于状态对账；前端在文本泵排空前不覆盖 provisional 文本。替代方案是在浏览器按结构化 JSON 二次拼接证据正文，但这会重现整块跳变并让恢复路径不一致。

3. **服务器按语义安全边界切块，客户端按帧预算平滑消费。** 服务端块保持 UTF-8/Markdown 边界安全且足够小，事件序号用于恢复；客户端网络回调只入队，单个 `requestAnimationFrame` 泵根据队列积压自适应消费字符，在标点与换行处优先提交。这样不会为每个网络包触发 React/Markdown 重渲染。替代方案是固定逐字定时器，延迟高、后台标签页不稳定且长答案会积压。

4. **长消息将稳定区与活动尾部分离。** 已提交 Markdown 以较低频率更新，活动时间线和输入框不随每个字符重建；自动滚动仅在用户接近底部时按帧合并，用户上滑后暂停跟随。终态时一次完成最后 flush，再切换为 canonical 消息。

5. **兼容旧事件。** 缺少新内容哈希或完整 delta 的旧 Turn 仍可在 `done` 时显示 canonical 回答；新 Turn 不再依赖固定步骤。恢复时以最后确认的 `event_seq` 与 turn id 去重，忽略旧帧回调。

6. **瞬时动作折叠，不做假性错峰。** `turn.created`、`turn.started` 等生命周期旁白不进入可展开历史；已知同步完成的本地扫描/引用校验不作为独立步骤展示，其他工具若在 600ms 内完成且没有失败也从活动历史中移除。界面只保留当前真正耗时的动作，批次、失败和较长工具调用仍可追溯。替代方案是给快速事件增加逐条延迟动画，但它会制造并不存在的等待，拒绝采用。

7. **正文泵以“低延迟常态 + 有界快速追赶”取代固定慢速逐字。** 新 delta 在下一绘制帧即可提交；小队列使用较小字符组保持连续感，队列超过 96 字、等待超过 240ms 或进入终态 drain 时切换追赶档。追赶档仍保持每帧一次 React 提交，但按积压量动态提升到最多 192 个 Unicode 字符；终态 drain 默认最多等待 2.5 秒。服务端 durable follow 间隔缩短到 50ms，降低首个 delta 的额外等待。单视频与普通事实问题允许 JSON `answer` 叙述字段随模型流出，claims、逐字引用和证据区仍在校验后作为 canonical 后缀追加；需要证明跨视频“反复/共同/趋势”的 broad deep 问题继续等待独立来源校验，避免先显示后撤回。替代方案是继续固定 12 字/24ms 播放并把所有叙述扣到验证完成，这会让 5,000 字回答被人为拉长，且模型已开始回答时用户仍可能空等近一分钟，拒绝采用。

8. **快速单视频流式回答使用服务端检索依据，不生成隐藏 claims 尾部。** 模型只负责先写完整 `answer` 和简短追问，claims/evidence 返回空数组；服务端从进入合成上下文的精确文稿片段中按当前问题选择最多三条引用，并继续通过既有逐字匹配校验后附加到结构化结果。这样正文结束后不再为一份用户看不到的 claims JSON 静止等待，也不为凑齐 claims 阻塞式重写整篇正文。多视频、外部查证以及 broad deep 的跨来源共同观点问题仍使用模型 claims 和独立来源校验，不能以检索相关性替代共同性证明。

## Risks / Trade-offs

- [快速单视频回答的服务端依据只证明检索片段相关，不等于逐项覆盖正文] → UI 只把它标为本轮代表依据，不把 evidence 数量解释成所有结论的覆盖率；多视频 broad 结论仍须先完成独立来源校验。
- [完整证据 delta 增加事件行数] → 使用有界合并块和最大 payload，持久化前按 Markdown 安全边界批量切分。
- [Markdown 未闭合时短暂样式变化] → 切块优先完整段落/换行，前端对未完成尾部使用轻量纯文本或稳定解析策略。
- [旧 Turn 只有部分 delta] → `done` canonical 作为兼容兜底，仅在文本泵排空后且内容确有差异时对账。
- [Faster pump 造成主线程压力] → 设置每帧最大字符与最小提交间隔，长历史消息使用 memo/content-visibility，滚动监听使用被动事件。
- [追赶档字符组过大造成跳字] → 只在存在明确积压或终态收口时启用，保持单帧上限 192 字且每绘制帧最多提交一次。

## Migration Plan

1. 先扩展测试覆盖 canonical Markdown、delta 完整性、事件真实性和 replay。
2. 部署兼容旧消费者的后端事件，再部署前端投影与文本泵调整。
3. 通过功能开关和现有 durable Agent 灰度验证单视频、多视频、取消与刷新恢复。
4. 若发现异常，可回滚前端到 `done` canonical 显示；事件表和 API 不需要数据迁移。
