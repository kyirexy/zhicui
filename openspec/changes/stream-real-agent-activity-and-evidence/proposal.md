## Why

知萃 Harness 虽然已经能够恢复 Turn 并流式显示答案，但运行中仍展示一组预设的“研究步骤”，无法反映 Agent 实际执行了什么；最终证据与引用结构又只在完成事件到达后整块出现，造成明显的假进度感和二次跳变。用户需要接近 Codex / DeepSeek Harness 的连续反馈：只呈现真实发生的动作，并让完整回答从首字到证据尾部保持同一条平滑增量流。

## What Changes

- 移除前端按序补齐的固定研究步骤，活动区只投影后端实际持久化的生命周期、批次、工具和验证事件。
- 将最终结构化回答序列化为单一可增量传输的 Markdown 文稿，使标题、正文、逐条依据和原文引用都通过可恢复 delta 流展示；交互式追问在回答完成后由结构化结果挂载。
- 完成事件只负责权威状态与结构化元数据对账，不再用整块最终正文覆盖仍在播放的增量消息。
- 改进客户端流缓冲、Markdown 提交频率、自动滚动和长消息渲染边界，减少逐字跳动、布局重排和滚动卡顿。
- 提高已验证回答的可见吞吐：首批正文不被额外定时器拖延，积压正文在有限帧内追赶，终态不再等待最长十秒才完成对账。
- 快速单视频问答直接复用服务端已检索的原文片段作为依据，不再让模型在正文之后重复生成一份不可见的 claims JSON；跨视频深度研究继续执行严格的独立来源校验。
- 保留取消、断线重连、事件去重、来源验证和用户连续追问队列能力。

### Modified Capabilities

## Impact

- 后端：Agent 运行事件、最终回答 Markdown 投影、持久化 delta/SSE replay 与完成对账。
- 前端：`VideoAgentWorkspace`、活动时间线、消息投影、帧合并文本泵、Markdown 渲染和滚动行为。
- 测试：事件真实性、证据 delta、断线恢复、终态对账和流式节奏回归测试。
- 不引入 Vercel AI SDK 或新的模型供应商依赖，继续使用现有 FastAPI durable SSE 协议。
