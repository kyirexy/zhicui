## ADDED Requirements

### Requirement: 运行反馈只投影真实 Agent 动作
系统 SHALL 只根据当前 Turn 已持久化且允许公开的生命周期、批次、工具和验证事件展示运行活动，MUST NOT 按固定阶段模板补出尚未实际发生的步骤，也 MUST NOT 暴露隐藏思维链、完整工具参数或未脱敏模型输出。

#### Scenario: Fast Turn 跳过外部查证
- **WHEN** 单视频事实问题在本地文稿中已经获得足够证据且没有发生外部查证
- **THEN** 活动区只显示实际发生的检索、验证和组织回答动作
- **AND** 不显示“正在判断是否需要外部查证”或其他未收到对应事件的固定步骤

#### Scenario: 多批次研究正在执行
- **WHEN** deep Turn 实际完成若干 transcript map 批次并开始验证证据
- **THEN** UI 按事件顺序显示真实批次数量、覆盖进展与当前验证动作
- **AND** 相邻重复或同义事件被折叠而不会形成重复的五步清单

#### Scenario: 页面刷新恢复活动
- **WHEN** 用户在 Turn 运行中刷新并从已确认事件序号恢复
- **THEN** 活动区由 replay 事件重建为与服务端一致的真实动作摘要
- **AND** 不补齐客户端本地预设步骤

#### Scenario: 多个瞬时事件在一次轮询内完成
- **WHEN** 排队、启动和一个不足 600ms 的本地工具动作在同一批 replay 事件中到达
- **THEN** 活动区不把它们依次保留成一套完成步骤
- **AND** 只显示当前仍在执行的耗时动作，或具有批次、失败及可追溯结果的活动
- **AND** 系统不得为了营造进度而人为错峰或延迟这些事件

## MODIFIED Requirements

### Requirement: 最终回答只包含已验证观点与引用
系统 SHALL 先产生结构化 Claim/Evidence，再验证逐字引用并从验证结果渲染唯一 canonical Markdown；MUST NOT 让正文保留已拒绝或不存在的来源编号。该 canonical Markdown 的叙述、Claim、覆盖说明、代表依据、验证原文和引用 SHALL 通过有序、可恢复的 answer delta 连续传输，完成事件只 SHALL 对账权威状态与同一内容，不得导致仍在播放的回答被整块替换或回退。结构化追问 SHALL 在正文完成后稳定挂载。

#### Scenario: 模型生成四条引用但只有一条有效
- **WHEN** 服务端只能在冻结来源中验证一条候选 Evidence
- **THEN** 系统修复或删除其余相关 Claim
- **AND** 最终正文及证据列表只引用通过验证的来源

#### Scenario: 声称观点反复出现
- **WHEN** 回答把一个观点描述为共同、反复或主流主题
- **THEN** 该 Claim 至少包含两个独立视频支持
- **AND** 回答显示支持数与研究范围，例如 `11/37 个视频`

#### Scenario: 回答包含较长证据区
- **WHEN** 验证后的回答包含多个 Claim、代表来源和逐字原文
- **THEN** 用户从回答开头到最后一条证据都能看到连续的增量输出，并在完成后看到结构化追问
- **AND** 证据区不得等到 `done` 后一次性整块出现

#### Scenario: 增量流中断后恢复
- **WHEN** 客户端已显示部分回答后断线并从最后确认的事件序号恢复
- **THEN** 服务端只重放缺失 delta，客户端按序去重并继续同一条消息
- **AND** 最终 canonical 对账不会重复文字、截断证据或覆盖较新的内容

#### Scenario: 已验证长回答快速连续显示
- **WHEN** 客户端收到数千字的已验证回答 delta，或完成事件到达时仍有正文积压
- **THEN** 第一批非空正文应在下一绘制帧提交，网络层不得再增加固定逐字延迟
- **AND** 客户端应根据队列深度与等待时间进入有界追赶档，每绘制帧最多提交一次且单次不超过 192 个 Unicode 字符
- **AND** 6,000 字积压在 60Hz 可见页面中的模拟排空时间不应超过 1.5 秒
- **AND** 终态对账不得因固定慢速播放而等待超过 2.5 秒

#### Scenario: 普通问题正文先于证据校验开始流出
- **WHEN** 单视频或无需证明跨来源共同性的普通问题进入模型综合阶段
- **THEN** 系统应只把 JSON `answer` 叙述字段作为 provisional delta 实时传输
- **AND** 快速单视频回答的模型不得生成 claims/evidence 尾部，服务端应从已经进入合成上下文的原文片段中选择最多三条代表依据并执行逐字匹配校验
- **AND** 多视频或需要外部查证的 claims、逐字引用、来源编号和证据区必须在服务端校验后才作为 canonical 后缀传输
- **AND** canonical 必须保留已经流出的叙述前缀，不得在完成时整块改写正文
- **AND** 若首轮只有部分 claims 通过，系统不得为了凑足数量阻塞式重写整篇普通回答，而应追加已验证部分并明确依据边界

#### Scenario: 跨视频共同观点继续先校验
- **WHEN** broad deep 问题要求判断多个视频中反复、共同或趋势性观点
- **THEN** 系统必须等待独立来源数和逐字引用校验后再传输相关结论
- **AND** 不得为了首字速度提前显示无法证明的跨来源模型草稿
