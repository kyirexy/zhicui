## Context

前端目前同时维护官网、Web 应用、Electron 桌面端和 Capacitor 移动端。它们共享主题变量和业务路由，却分别实现了页面容器、导航、标题、按钮、状态和弹层；核心工作区也各自定义颜色、圆角、阴影与文案结构。历史全局样式多次覆盖同一选择器，使新的视觉调整容易继续叠加而不是收束。

本次改造必须在不改变业务流程、URL、数据契约、权限和 React DOM 所有权的前提下完成。资料库、研伴、知识与计划仍需要不同的信息布局；营销页和管理端也不能被强行压成完全相同的信息密度。

## Goals / Non-Goals

**Goals:**

- 让所有应用页面使用同一套画布、表面、文字、边框、强调色、间距、圆角、控件高度和动效令牌。
- 让页面名称、标题、主操作和状态反馈在不同端保持同一语义。
- 日常工作区正常态不展示教学段落；必要帮助在空状态、错误、风险决策或字段附近出现。
- 在不重写大型业务组件的情况下，先统一页面外壳、头部、工具栏、状态和文案，再逐步迁移内部区域。
- 保持键盘、触控、缩放、焦点和移动安全区可用。

**Non-Goals:**

- 不重新设计资料同步、Agent 对话、知识沉淀、计划执行或管理端的数据模型与业务流程。
- 不将营销页面的信息量压缩到应用工作区的水平，也不删除管理端做决策所需的价格、安全、审计和破坏性操作说明。
- 不引入新的组件框架、图标包、Portal 容器或全站动画系统。
- 不在首轮一次性重写超大型资料库和研伴组件的内部 DOM。

## Decisions

### 1. 以语义令牌为唯一视觉来源

在现有主题变量上增加并统一 `canvas`、`surface`、`surface-subtle`、`border`、`text`、`text-muted`、`accent`、`danger` 和 `warning` 等语义别名。页面专属 CSS 可以定义布局，但不得再硬编码新的近似品牌绿、独立画布色或任意圆角。圆角收束为 8/12/16px，交互高度收束为 36/40/44px，正常触控目标不小于 44px。

替代方案是一次性删除历史全局样式并重写所有页面。该方案在当前多端和脏工作区中回归面过大，因此采用“新共享层优先、旧选择器按迁移页面逐步退休”的方式。

### 2. 页面统一为“标题 + 内容 + 状态”，不统一领域布局

共享 `ProductPage`、`ProductPageHeader`、`ProductState` 和基础按钮/图标按钮样式，统一页面宽度、标题层级、操作槽、状态表达和移动端间距。资料库双栏、知识阅读器、研伴三栏和计划执行区继续保留自己的领域布局。

页面头默认只显示一个名词型标题；可选上下文只能是一行，并仅在标题无法说明当前任务时使用。右侧最多一个实心主操作，其余操作使用次级按钮或“更多”菜单。

### 3. 使用单一产品词典

导航定义成为前台产品名称的来源，统一使用“首页 / 视频资料 / 视频研伴 / 我的知识 / 行动计划”。同一对象的按钮采用“动词 + 对象”，例如“添加视频”“解析链接”“新建知识”“创建计划”。内部术语如“完整 Agent”“AI 资料”“工作台”不出现在普通用户界面。

### 4. 文案采用渐进披露

正常态只保留标题、必要标签和动作。首次空状态允许一句用途提示与一个主操作；搜索无结果只说明结果并提供清空；错误只给出短原因与重试。价格、安全、隐私、计费、破坏性后果和管理员诊断信息属于决策信息，不按“少文字”规则删除，而是放在相关控件附近或可展开区域。

### 5. 多端共用语义，布局随端变化

顶部导航、桌面侧栏和移动底栏继续使用不同容器，但从同一导航定义和图标映射读取名称、链接、选中状态与徽标。桌面应用使用确定的动态视口高度链；移动端使用文档流、安全区和至少 44px 的操作目标。功能性页面使用实色表面，减少玻璃、光晕和装饰渐变；官网可保留克制的品牌表达。

### 6. 弹层统一到稳定挂载的原生对话框

新增或迁移的确认、模态、抽屉和移动 sheet 优先基于稳定挂载的原生 `<dialog>`，统一 Esc、背板、初始焦点、焦点恢复和处理中不可关闭行为。现有安全的原生 dialog 保留；不使用临时 body Portal，不手工移动或删除 React 拥有的 DOM。

## Risks / Trade-offs

- [全局样式历史覆盖导致局部回退] → 共享组件使用窄作用域类名，迁移时删除同一路由的冲突规则，并在 Web、Electron 和移动断点分别验证。
- [大页面一次改动过多] → 资料库、研伴和管理端按“名称与头部 → 状态与操作 → 内部区域”分批迁移，首轮不重写业务状态管理。
- [减少说明导致关键信息丢失] → 明确保留价格、隐私、安全、计费、权限、错误诊断和破坏性操作后果；仅删除重复与教学式说明。
- [统一高度破坏独立滚动] → `ProductPage` 提供自然流和全高工作区两种显式模式，双栏/三栏工作区继续由内部滚动容器承担滚动。
- [两个图标库短期共存] → 新共享导航与公共控件使用同一套现有图标库；旧领域组件随迁移逐步替换，不做高风险机械全量替换。

## Migration Plan

1. 建立语义令牌、共享页面头和状态组件，并修复产品名称与明显错误深链。
2. 迁移首页、样式、模型选择、设置和解析结果等独立页面，删除重复说明和装饰性层级。
3. 只修改资料库、研伴、知识与计划的头部、工具栏、空/错/加载状态和产品文案；保留领域布局与请求逻辑。
4. 分批迁移管理端标题、工具栏、表单、按钮和弹层，保留高密度诊断信息。
5. 压缩官网重复叙事，但保留产品价值、平台与隐私所需信息。
6. 对关键路由执行类型检查、生产构建、键盘/触控与多端视觉回归。每批变更均可通过恢复对应共享组件调用与模块样式独立回滚。

## Open Questions

无。首轮采用现有暖白/深色主题与绿色单强调色，不新增品牌方向。
