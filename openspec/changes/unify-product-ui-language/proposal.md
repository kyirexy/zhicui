## Why

当前产品各页面分别演进，页面标题、操作层级、控件尺寸、空状态和说明文案缺少统一规则，导致同一产品在不同功能间呈现出不同的使用方式。需要建立一套面向全站的界面语言，让用户进入任何页面都能快速看懂“这里是什么、主要能做什么、下一步点哪里”，同时减少重复和教学式文字。

## What Changes

- 建立适用于桌面 Web、桌面应用和移动端的统一页面骨架、视觉令牌与响应式规则。
- 统一页面标题、主次操作、标签页、搜索筛选、表单、状态反馈和危险操作的层级与外观。
- 将日常工作区中的长段说明压缩为必要的一行上下文；把帮助放到发生问题或需要决策的位置。
- 为加载、空数据、无结果、错误和不可用状态建立一致的动作优先模式，每个状态只突出一个下一步。
- 迁移入口、核心工作区、设置和管理端；营销页面与高密度管理页面保留各自必要的信息量，但共享品牌、控件和可访问性基线。
- 保留现有业务流程、URL、数据契约、权限边界和原生对话框行为，不引入新的 UI 框架。

## Capabilities

### New Capabilities

- `product-ui-language`: 定义全站页面层级、视觉令牌、文案密度、操作优先级、状态反馈、响应式和可访问性的一致契约。

### Modified Capabilities

无。

## Impact

- 主要影响 `frontend/src/app` 下的共享样式与各路由页面，以及 `frontend/src/components` 中的导航、页面标题、状态和操作控件。
- 不改变后端 API、数据库、认证、知识/资料/研伴/计划的数据与交互契约。
- 现有正在演进的资料库、研伴和知识工作区继续保留其专用布局，本变更仅统一共享语言和表层交互，不覆盖其领域行为。
