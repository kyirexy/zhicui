## Context

知萃当前已经具备一条完整业务链路：抖音资料同步、云端 ASR 文稿、单/多视频问答、联网补充、知识卡、行动计划和定时摘要。问题主要出在呈现层：

- Web 顶栏、Windows 左栏和移动底栏使用三套不同的导航名称与数量。
- `/agent` 默认常驻的是任务历史，真正决定回答内容的资料范围被放进抽屉；回答的依据、限制和处理阶段又连续堆在消息下方。
- `/library/detail`、`/notes?id=` 和卡片渲染器形成了多套单内容详情。
- `/notes` 更像另一套视频列表，而不是用户主动保存和持续维护的知识成果。
- `/plans` 已有“今日 / 目标 / 进度回顾”，但逾期任务仍以堆叠为主，AI 创建与调整能力没有贯穿计划工作台。
- `globals.css` 已累积大量 Agent 和桌面覆盖规则，继续追加样式会增加空白页、级联漂移和移动端回归风险。

目标体验采用以下组合，但不复制任何单一产品：

- NotebookLM：资料范围始终可见、回答基于用户选择的资料快照。
- Perplexity：先给直接答案，再表达引用、来源和限制。
- ChatGPT Canvas：知识卡与计划脱离聊天流，成为可编辑成果。
- Manus：只在长任务中展示真实执行阶段，不展示模型思维链。

系统继续运行在 Next.js 16 客户端应用、Electron Windows 壳和 Capacitor Android 中。所有端共享业务组件。服务器和数据库不保存视频文件。

## Goals / Non-Goals

**Goals:**

- 让用户进入任一页面后都能理解自己位于“资料 → 理解 → 成果 → 行动”的哪一步。
- 将一级导航收敛为“今日行动、视频资料、AI 助手、我的知识”，并让所有端使用同一份导航配置。
- 让 Agent 第一眼回答三个问题：正在参考什么、得出了什么、可以形成什么。
- 统一单视频详情、知识卡详情和计划成果的浏览与编辑方式。
- 将计划从任务集合升级为目标澄清、今日执行、动态调整和复盘闭环。
- 默认维持白色、暖中性和少量薄荷绿，保证 390px 移动端、键盘、安全区和 44px 触控目标。
- 逐步拆分超大组件和全局样式，避免一次重写现有能力。

**Non-Goals:**

- 不迁移 Next.js、React、图标系统或 Agent 框架。
- 不实现 Codex 式主题市场、任意配色编辑器或复杂模型参数面板。
- 不声称已经接入日历、精力估算、准确收藏时间或尚不存在的行为学习。
- 不在 UI 中展示 chain-of-thought、原始模型 JSON、伪造进度或技术日志。
- 不改变视频不落库、不在服务器持久保存视频文件的边界。
- 本提案不直接部署生产，也不在规划阶段重建 APK。

## Decisions

### 1. 统一为四个用户目的地，首页成为“今日工作台”

全端共用一份导航配置：

1. `今日行动`：登录后的默认工作台，包含今天最重要的任务、继续中的 AI 助手任务、最近同步和一个快速提问入口。
2. `视频资料`：同步、查找和选择 AI 可阅读的视频。
3. `AI 助手`：基于一条或多条视频解决问题；单视频问答与多视频分析共享同一任务、证据和回答结构。
4. `我的知识`：主动保存下来的摘要笔记、专题、回答和已转化行动。

设置、反馈、应用更新、账号、抖音绑定和管理端进入头像菜单。计划的“目标 / 今日 / 复盘”仍沿用 `/plans`，但导航名称面向用户表达为“今日行动”；旧 URL 保留。

移动端底栏只显示这四项。登录后的 `/` 渲染今日工作台并高亮“今日行动”；未登录 `/` 继续展示产品介绍。

备选方案：继续保留“首页、视频库、Agent、知识库、计划、设置”六个入口。拒绝原因是它按数据库对象而不是用户目标组织产品，移动端也无法提供足够的触控与阅读空间。

### 2. Agent 使用资料、对话、成果三层结构

桌面 Agent：

```text
┌──────────────┬──────────────────────────────┬──────────────────────┐
│ 视频资料     │ 当前对话                     │ 当前成果             │
│ 250–280px   │ minmax(560px, 1fr)           │ 330–380px            │
│              │                              │                      │
│ 来源与范围   │ 直接结论                     │ 依据 / 知识卡 / 计划 │
│ 搜索         │ 来自视频                     │ 原文片段与时间点     │
│ 视频列表     │ AI 综合                      │ 可编辑成果           │
│              │ 外部补充与限制               │                      │
│ 最近任务入口 │ 最相关的下一步               │                      │
├──────────────┴──────────────────────────────┴──────────────────────┤
│ 依据：收藏 36 条 · 资料优先   问这些视频，或把结论变成计划…  发送 │
└────────────────────────────────────────────────────────────────────┘
```

- 左栏默认展示资料，不展示历史任务。
- 历史任务进入顶部任务切换器或抽屉。
- 自动化和邮箱摘要进入独立侧面板，不常驻在对话左栏。
- 屏幕小于约 1180px 时，成果栏改为右侧抽屉；小于约 960px 时，资料栏也改为面板。
- 新任务创建时冻结资料快照，后续追问继续使用同一快照；界面始终区分“当前对话资料”和“下一个任务的资料草稿”。

移动 Agent 不压缩三栏，使用单栏对话：

```text
任务                  资料 12
──────────────────────────
对话和答案

已核对 4 条依据
──────────────────────────
12 条视频 · 资料优先
基于这些视频提问…       ↑
──────────────────────────
今日     资料     问 AI     知识
```

资料选择使用接近全高的 Bottom Sheet；依据和成果使用全屏子页面或底部面板。键盘弹起时隐藏底栏，输入区贴合可视键盘。

### 3. 资料范围拆成“来源”和“范围”两个维度

现有“全部、昨日新增、收藏、喜欢、我的作品、手选”混合了来源类型和时间/选择方式。目标模型拆成：

- 来源：收藏、喜欢、我的作品、全部来源。
- 范围：全部可用、昨日新增、手动选择。

这样能够表达“昨日新增的收藏”或“手选的个人作品”。迁移第一阶段继续兼容现有 `source_scope`；第二阶段扩展线程快照契约为 `source_mode + range_mode + source_ids`，旧线程按原 scope 只读展示。

默认不要求用户逐条勾选，范围模式可直接检索完整文稿；只有选择“手选”时才进入视频勾选。

### 4. 回答采用证据型文档，不以聊天气泡堆叠组件

用户消息保持紧凑气泡，助手回答作为无气泡文档。标准顺序：

1. 直接结论。
2. 来自你的视频：可被原文直接支持的判断。
3. AI 综合分析：跨视频归纳或按用户要求补充的建议。
4. 外部资料补充：仅在联网实际成功并引用来源时出现。
5. 分歧与限制：只有存在冲突、覆盖不足或资料缺失时出现。
6. 下一步：最多两个主要动作和一个更多菜单。

回答底部把多个状态标签压缩成一行，例如：

> 已读 36 个视频 · 6/6 条引用已核对 · 资料优先

点击引用状态将成果栏切到“依据”。复制、反馈和重试进入更多菜单。桌面端不再在正文下方连续展开“依据、处理过程、限制”等多个大折叠卡。

正文必须在视觉和语义上区分三种来源，不允许将联网补充伪装成视频原文：

- `来自你的视频`
- `AI 综合分析`
- `外部资料补充`

### 5. 成果画布承载依据、知识卡和行动计划

右侧成果栏有三个 Tab：

- `依据`：当前回答实际使用的视频、作者、原文片段、文稿位置、时间点和外部来源。
- `摘要笔记`：从当前回答生成或打开的可编辑摘要草稿，不作为提问或创建计划的前置条件。
- `行动计划`：目标、里程碑、今天任务和完成标准组成的可编辑计划草稿。

第一阶段将现有 evidence、trace、limitations 迁移到依据画布，复用已有知识卡和计划创建 API。第二阶段增加统一的知识成果记录，使用户可以保存多视频专题或某次 Agent 结论。

知识卡或计划生成后，不在聊天中输出几十行 Markdown；对话只说明已经形成成果，并把焦点移到右侧画布。移动端打开全屏成果页，顶部保留“返回对话”。

### 6. 单视频和知识成果共用一个 AI 助手详情工作区

`/library/detail?id=<noteId>` 成为单视频的标准工作区；`/notes?id=<noteId>` 保留兼容，但内部复用同一个组件并打开相应 Tab。

桌面使用约 42% / 58% 两栏：

```text
┌──────────────────────┬────────────────────────────────────┐
│ 视频、标题、作者     │ AI助手 | 完整文稿 | 摘要笔记 | 计划 │
│ 播放器与查看原视频   │ 当前 Tab 内容                      │
└──────────────────────┴────────────────────────────────────┘
```

- 默认打开 AI 助手；当前视频自动成为该任务唯一资料来源。
- 摘要笔记只在用户需要保存或快速回顾时生成，不占据详情首屏。
- 文稿一旦就绪即可提问，不要求先生成摘要、AI 总结或知识卡。
- 从视频库进入当前视频、从独立 AI 助手手选当前视频，均复用同一问答组件和证据展示。
- 引用点击后切到完整文稿、定位原文，并在可用时跳到视频时间点。
- 计划 Tab 直接编辑关联计划，不以聊天消息展示任务清单。

移动端播放器可以折叠；Tab 固定在播放器下方，内容单列滚动。

### 7. “我的知识”只管理可复用成果

知识列表不再复制视频资料库。它包含：

- 单视频摘要笔记。
- 多视频专题总结。
- 用户保存的 Agent 回答。
- 已转化为行动的方案。

主要筛选为“最近整理、主题集合、已转为行动、全部成果”。菜谱、历史、产品等 AI 分类降为标签，不作为最重要的导航。

打开单视频摘要时进入统一详情的摘要笔记 Tab；打开多视频专题时进入对应 AI 助手任务和成果画布。

### 8. 计划以“今日 / 目标 / 复盘”形成执行闭环

#### 今日

- 默认只展示最重要的 1～3 项。
- 每项展示预计时间、所属目标和一个大完成控件。
- 逾期任务不直接全部堆入今天，提供“今天完成、重新安排、跳过本次”。
- 唯一明显的 AI 操作为“AI 调整今天”。

#### 目标

- 每张目标只显示目标结果、截止时间、当前阶段、进度、下一步和来源视频数量。
- 顶部使用一句自然语言输入：“告诉知萃你想实现什么……”
- AI 每次只追问一个最关键问题，覆盖结果、截止时间、当前基础、可投入时间和限制，确认后才生成计划。

#### 复盘

- 使用真实的完成、逾期和改期数据说明本周发生了什么。
- 展示受影响的里程碑和 AI 调整建议。
- 用户必须主动接受调整或自己修改。
- 没有真实耗时和日历数据时，不推断拖延习惯、精力曲线或日程冲突。

计划详情优先展示当前阶段、今日任务和下一里程碑。动态字段默认只显示最重要的 3～5 项，其余进入“计划依据与设置”。AI 调整始终保留已完成内容，并说明改变了什么、为什么改变。

### 9. 视觉系统使用中性色结构，薄荷绿只表达方向和确认

默认视觉：

- 页面背景：暖白或轻灰绿。
- 主表面：白色。
- 分隔线：中性浅灰绿。
- 主要文字：近黑绿。
- 薄荷绿：当前选择、主要提交、已连接、已核对。
- 红色仅用于错误、逾期和危险操作；不作为第二套品牌色。

计划与知识页现有紫色主按钮和紫色面板全部迁移到统一 token。大面积玻璃、模糊、渐变和阴影不进入工作台主区。

圆角分级：页面容器 20px、面板 14–16px、输入与小控件 10–12px。交互反馈 140–180ms，只使用 transform 和 opacity，并尊重 `prefers-reduced-motion`。

触控目标至少 44px，主发送按钮 48px。移动正文不低于 14px、辅助文字不低于 12px。固定元素同时适配 `safe-area-inset-bottom/left/right`。

### 10. 拆分 Agent 组件和样式，不再追加全局修正层

`VideoAgentWorkspace.tsx` 仅保留任务协调，逐步拆分为：

```text
components/agent/
  AgentWorkspace.tsx
  AgentWorkspace.module.css
  sources/
  threads/
  conversation/
  artifacts/
  automation/
  hooks/
```

Agent、计划和知识工作区的新样式进入 CSS Modules；`globals.css` 只保留主题 token、排版基础和跨页面壳层规则。复用现有 BottomSheet、确认对话框、AgentMark、Markdown 渲染器、API 客户端和公开类型。

备选方案：继续在 `globals.css` 末尾添加“最终覆盖”。拒绝原因是当前同类选择器已经多次重复，无法可靠验证级联来源。

## Risks / Trade-offs

- [导航变化会让老用户短暂迷路] → 保留旧 URL，使用一致图标和一次性轻提示，先改名称与位置再移除旧入口。
- [三栏在普通笔记本屏幕过窄] → 设置 1180px 与 960px 两级折叠，不强行压缩正文。
- [成果画布需要新的持久化对象] → 第一阶段只呈现已有依据、卡片和计划；第二阶段再增加多视频成果记录。
- [资料来源与范围拆维度会改变线程契约] → 新字段保持可选，旧 `source_scope` 继续读取，创建新任务时逐步写入新快照格式。
- [AI 澄清会增加创建计划步骤] → 简单目标允许用户直接确认默认值，复杂目标才逐题澄清。
- [登录首页与未登录首页分叉可能重现壳层空白] → 继续使用现有认证恢复兜底；加载期间渲染结构化骨架，不返回空节点。
- [一次迁移所有页面风险过高] → 按壳层、Agent、详情/知识、计划、跨端五轮落地，每轮独立构建和浏览器验证。
- [全局 CSS 拆分可能改变历史页面] → 新模块先覆盖新工作区，确认无依赖后再删除旧选择器，不做一次性大删。

## Migration Plan

1. 建立统一导航配置，收敛 Web、Windows 和移动端入口；保留全部旧路由。
2. 将登录首页替换为今日工作台，复用现有最近视频、计划概览和 Agent 任务接口。
3. 拆分 Agent 壳：资料栏常驻、历史任务进入抽屉、现有依据进入右侧画布；此阶段不改后端协议。
4. 简化回答和输入框，将高级回答方式、自动化与邮箱移入次级面板。
5. 统一 `/library/detail` 与 `/notes?id=` 的详情组件，并将知识库改成成果集合。
6. 接入知识卡和行动计划成果画布；需要时增加保存 Agent 成果的后端契约。
7. 扩展计划澄清、逾期决策、调整原因和复盘界面。
8. 完成 390×844、768×1024、1280×800、1440×900 验证，执行 Next 正式构建、后端测试、Electron 类型检查和 Capacitor 同步。
9. 逐批删除不再被引用的旧 Agent/计划/知识全局 CSS。每一步都可以通过回退组件入口恢复旧界面，不需要数据库降级。

## Open Questions

- 多视频专题与保存的 Agent 回答是否共用一个 `knowledge_artifacts` 表，还是先复用 Note 的 JSON 字段。
- 计划 AI 调整是否在第一版保存完整调整历史，还是只保存最近一次原因与变更摘要。
- “资料优先”在资料不足时是否自动联网，还是每次先请求用户确认；当前建议维持按需联网并清楚标注。
- 桌面端成果栏默认宽度最终取 340px 还是 380px，应在 1280px 和 1440px 实际数据下确定。
