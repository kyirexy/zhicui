## Why

知萃已经具备视频同步、完整文稿、资料问答、知识卡、计划和自动摘要，但这些能力分别长在视频库、Agent、知识库和计划页中，页面之间像四套独立产品。用户需要一个围绕“资料 → 理解 → 成果 → 行动”的统一工作台，并且必须始终看清 AI 正在参考哪些视频、结论依据在哪里、下一步能形成什么成果。

## What Changes

- 将登录后的一级导航收敛为“视频资料、AI 助手、今日行动、我的知识”，账号、设置、反馈和自动化进入次级入口；移动端不再同时显示六个底部标签。
- 将多视频 Agent 重构为“资料范围 / 对话 / 成果画布”三层工作区：资料范围优先于历史任务，回答优先展示结论和依据，知识卡与行动计划从聊天流中抽离为可维护成果。
- 统一单视频详情和知识卡详情，使用“知识卡 / 完整文稿 / AI 问答 / 行动计划”四个 Tab；知识库不再维护另一套重复详情。
- 将知识库重新定位为“我的知识”，管理单视频知识卡、多视频专题、保存的 Agent 结论和已转化行动的成果。
- 将计划闭环强化为“今日 / 目标 / 复盘”：AI 先澄清目标，再生成可执行步骤；当逾期、时间不足或目标变化时，提供有原因的重新排程。
- 登录后的首页改为轻量工作台，优先显示最近同步、一个资料提问入口、今天最重要的 1～3 项和最近成果；未登录首页继续承担产品说明与登录引导。
- 桌面端使用可折叠的资料栏和成果栏；移动端使用单栏主流程，并通过底部面板或全屏页承载资料选择和成果编辑。
- 全部页面统一为白色与暖中性色背景，只用少量薄荷绿表达当前选择、已连接和已核对状态；移除计划和知识页残留的紫色主强调。

## Capabilities

### New Capabilities

- `unified-product-workspace-navigation`: 定义登录后的四个一级目的地、工作台首页、桌面壳和移动端导航收敛方式。
- `source-grounded-agent-canvas`: 定义视频资料范围、证据式对话、任务状态和知识卡/行动计划成果画布在桌面与移动端的交互关系。
- `knowledge-artifact-workspace`: 定义统一单视频详情、知识成果集合、成果类型和从依据到卡片或计划的连续浏览路径。

### Modified Capabilities

- `douyin-library-homepage`: 将已登录用户首页从产品介绍优先调整为最近资料、提问、今日行动和最近成果组成的工作台，同时保留未登录营销入口。
- `clear-action-plan-workspace`: 在现有今日/目标/复盘结构上增加 AI 目标澄清、逾期决策、可解释重新排程和贯穿计划详情的 AI 执行助手。

## Impact

- 前端应用壳与导航：`frontend/src/app/layout.tsx`、`frontend/src/components/AppHeader.tsx`、`DesktopAppFrame.tsx`、`BottomTabBar.tsx` 和首页。
- 核心页面：`/library`、`/library/detail`、`/agent`、`/notes`、`/plans` 及其组件和全局样式。
- 后端/API：第一阶段复用现有资料、Agent、知识卡和计划 API；第二阶段需要保存 Agent 成果、计划澄清/调整记录和复盘建议的轻量契约。
- 数据与隐私：不改变用户隔离，不将视频文件写入数据库或服务器持久存储，不暴露模型隐藏思考过程。
- 跨端：同一响应式实现覆盖 Web、Electron 桌面端和 Capacitor Android；不引入新的 UI 框架或 Agent 编排框架。
