## ADDED Requirements

### Requirement: Agent 首先呈现资料、回答与成果关系
桌面 Agent 工作区 SHALL 将视频资料范围、当前对话和当前成果作为三个明确区域，并 SHALL 将资料范围置于历史任务之前。

#### Scenario: 用户在宽屏打开 Agent
- **WHEN** 可用视口宽度足以容纳三个区域
- **THEN** 左侧显示当前资料范围和视频列表
- **AND** 中间显示对话
- **AND** 右侧显示依据、知识卡和行动计划成果 Tab

#### Scenario: 桌面空间不足
- **WHEN** 视口不足以保持可读的三栏宽度
- **THEN** 系统先将成果区改为可打开的抽屉
- **AND** 不将对话正文压缩到不可读宽度

### Requirement: 当前对话资料与新任务草稿相互独立
系统 SHALL 为每个 Agent 任务保存创建时的资料快照，并 SHALL 在界面中清楚区分当前对话资料和下一个任务的资料选择。

#### Scenario: 用户继续已有对话
- **WHEN** 用户打开一个已有 Agent 任务并继续追问
- **THEN** 系统继续使用该任务创建时的资料快照
- **AND** 后续修改新任务资料不会静默改变当前对话

#### Scenario: 用户准备新任务
- **WHEN** 用户调整来源、范围或手选视频
- **THEN** 调整只作用于新任务草稿
- **AND** 提交前界面显示最终资料数量

### Requirement: 资料来源与范围可组合表达
系统 SHALL 分别表达视频来源和范围，其中来源至少包括收藏、喜欢、我的作品和全部来源，范围至少包括全部可用、昨日新增和手动选择。

#### Scenario: 用户选择昨日新增收藏
- **WHEN** 用户将来源设为收藏并将范围设为昨日新增
- **THEN** 新任务只冻结符合两个条件且文稿可用的视频

#### Scenario: 用户选择手动范围
- **WHEN** 用户选择手动范围
- **THEN** 系统显示可搜索的视频选择界面
- **AND** 未选择任何视频时不允许创建任务

### Requirement: 回答明确区分不同信息性质
Agent 回答 SHALL 先给出直接结论，并 SHALL 在内容和语义上区分“来自你的视频”“AI 综合分析”“外部资料补充”和“分歧与限制”。

#### Scenario: 回答同时使用视频和联网资料
- **WHEN** Agent 使用了已核验的视频引用和外部来源
- **THEN** 视频支持的结论与外部补充分区显示
- **AND** 外部内容不会被描述为视频原文

#### Scenario: 用户要求资料中不存在的示例
- **WHEN** 视频没有提供具体示例但用户明确要求 Agent 补充
- **THEN** Agent 可以生成实用示例
- **AND** 该示例被标记为 AI 补充而不是视频原文

### Requirement: 引用和处理元数据进入依据画布
桌面端 SHALL 在依据画布中展示实际使用的视频、原文片段、文稿位置、可用时间点、联网来源、限制和真实处理阶段，并 SHALL 在回答正文中只保留紧凑状态摘要。

#### Scenario: 用户查看已完成回答
- **WHEN** 回答包含已核验引用
- **THEN** 正文底部显示已读视频数和引用核验数量
- **AND** 用户可以打开依据画布查看完整证据

#### Scenario: 引用无法通过核验
- **WHEN** 模型返回的引用不在候选证据中
- **THEN** 系统不将该引用标记为已核对
- **AND** 依据画布显示覆盖不足的限制说明

### Requirement: 知识卡和计划作为独立成果
Agent SHALL 将知识卡和行动计划呈现为成果画布中的可编辑对象，而不是仅在聊天消息中输出长 Markdown。

#### Scenario: 用户将回答保存为知识卡
- **WHEN** 用户选择“保存为知识卡”
- **THEN** 成果画布打开知识卡草稿
- **AND** 用户可以确认或修改后保存

#### Scenario: 用户将回答转成计划
- **WHEN** 用户选择“转成行动计划”
- **THEN** 成果画布打开包含目标、里程碑、今日任务和完成标准的计划草稿
- **AND** 保存后计划出现在计划工作台

### Requirement: 执行状态按任务复杂度渐进展示
系统 SHALL 对简单问答只显示一行真实状态，并 SHALL 仅在批量分析、专题总结或计划生成等长任务中展示可展开的真实阶段。

#### Scenario: 用户询问单个视频
- **WHEN** Agent 正在处理简单单视频问题
- **THEN** 页面显示简短的处理中状态
- **AND** 不模拟复杂阶段或虚构百分比

#### Scenario: 用户要求比较大量视频
- **WHEN** Agent 正在扫描多条完整文稿
- **THEN** 页面可以展示规划、扫描、筛选、联网、综合和引用核验阶段
- **AND** 每个阶段只显示实际可获得的数量、状态和结果摘要

### Requirement: 输入区默认保持轻量
Agent 输入区 SHALL 常驻显示当前资料范围、回答边界、输入框和发送按钮，并 SHALL 将快速/深度、输出格式和自定义要求收进回答设置。

#### Scenario: 用户首次开始提问
- **WHEN** 用户打开空白 Agent 任务
- **THEN** 输入区显示当前资料数量和默认“资料优先”边界
- **AND** 页面提供总结、对比和变成计划三个简短意图入口

### Requirement: 移动端保持完整 Agent 能力
移动端 SHALL 以单栏对话为主，通过底部面板或全屏子页面承载资料、依据、历史和成果，并 SHALL 保持输入区不被底部导航或安全区遮挡。

#### Scenario: 390px 视口提问
- **WHEN** 用户在 390px 宽度打开 Agent
- **THEN** 对话正文占据可用宽度且没有横向溢出
- **AND** 资料入口、发送按钮和成果入口具有至少 44px 的触控区域
